Wedge signature: `response_captured` cycle keeps `replaying captured CRDT patchback` on every preflight; socket IPC receipt-timeout (6000ms) → file-IPC → `no_ack recovery=retry_without_disk_write`. `admin inspect` shows `freshness=controller:fresh,supervisor:fresh` (so NOT a stale-binary supervisor), and the `plugin-owner/<dochash>.json` heartbeat is fresh (JB IDE alive, pid running). The JB plugin's **heartbeat thread is alive but its IPC patch-handler thread is hung** — it silently never acks (old `.nack` files are days-stale, not fresh rejections).

**Why:** `agent-doc admin reload-lib` (the `#cdylib-reload-broadcast` API path) announces a cdylib reload, but a reload cannot un-hang a thread that is already stuck mid-handler. It only helps a *stale-mtime* cdylib that hasn't reloaded yet. So reload-lib is the wrong tool for an already-wedged handler.

**How to apply:**
1. Confirm live processes with `ps -eo pid,etime,cmd | grep -E 'agent-doc|idea'` (a plain `ps aux | grep` missed them once — use `-eo`). Check `plugin-owner/<dochash>.json` heartbeat vs `date +%s`: fresh heartbeat + hung acks = wedged handler, not dead editor.
2. The fix is **operator reopens the doc tab in IntelliJ** (close+reopen or File→Reload from Disk) — that drops the wedged handler and re-establishes a fresh IPC listener. reload-lib and `admin recycle` (fresh supervisor) do NOT fix it. Confirms [[feedback_jb_restart_reopen_dont_fix_stale_cdylib_corruption]]'s inverse: reopen DOES fix a *wedged-handler* (vs. does NOT fix *stale-cdylib*).
3. After reopen, preflight's repair `retired superseded Captured-only orphan` (the stale captured response whose heading was already answered) and reached the clean `snapshot differs from HEAD without an open cycle` state → compose response, deliver via `agent-doc write --commit`.
4. **write --commit hang:** the `--stream` write delivered the response to disk AND the editor buffer (IPC applied), then hung >2min before the git commit (crdt sidecar `.yrs.lock` contention with the live supervisor). Killed process left a **stale 0-byte `.yrs.lock`**. Recovery: `rm` the stale lock, verify the append is clean + un-duplicated (`grep -c` each new heading == 1, operator prompt still present), then `agent-doc commit <FILE>` — it absorbs the on-disk pending write and commits (fast, ~2s). Extends [[feedback_hung_pending_add_recover_via_agent_doc_commit]].
5. `agent-doc commit` prints `postcommit_worktree_check match=false ... realtime replica owns reconciliation, no revert (#realtimecutover)` — that is EXPECTED (boundary-reposition diff), not a failure. session-check then reports the cycle `abandoned` (`reason=manual_reset_from_current_retired_stale_already_visible_response`) = clean.

Do the whole recovery scoped to the session doc only; ignore session-check `partial staging closeout` warns for unrelated submodules (equityfundingsource-dev, patchboard, skill-harness) per [[feedback_session_document_scope_discipline]]. Pairs with [[feedback_stuck_response_captured_cycle_mv_state_cycles_json]] and [[feedback_send_failed_no_ide_running_forcedisk_not_restart]] (opposite branch: there NO ide = force-disk; here ide ALIVE+wedged = reopen tab, never force-disk against a live buffer).
