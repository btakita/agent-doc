**Design (DONE, source of truth = lazily-spec `cell-model.md` § Keyed cell collections + § Materialization, committed 8e5d53b):**
Unify keyed collections on ONE generic primitive `ReactiveMap<K,V,H>` (mutable reactive keyed dict: reactive membership/order, `get_or_insert_with`, `remove`, `move`), with two specializations:
- `CellMap<K,V> = ReactiveMap<K,V,CellHandle>` — input cells; adds **cell-only** `set(k,v)`.
- `SlotMap<K,V> = ReactiveMap<K,V,SlotHandle>` — derived slots; `get_or_insert_with` mints a slot on first access = **lazy materialization**; NO `set` (derived); NO eager/lazy mode flag (eager = pre-mint loop).

**REMOVE** family types entirely: `ReactiveFamily`, `CellFamily`, `MaterializedFamily`, the eager/lazy `MaterializationMode` flag, and the handle-generic `FamilyHandle` (rename → a ReactiveMap handle trait). Materialization becomes SlotMap *behavior* (transparency + deferral), pinned by `conformance/materialization/*.json` fixtures + `lazily-formal/Materialization.lean` theorems (theorems are ABSTRACT — `materialize_present_monotone` is read-scoped, so it survives `remove`; unchanged). Thread-safe/async keyed collections move to the ReactiveMap line (`ThreadSafeSlotMap`/`AsyncSlotMap`). Why: family type diverged (lazily-zig spreadsheet benchmark); pinning *behavior* not a type prevents re-divergence. The real `atomFamily` analog is `CellMap` + `get_or_insert_with`, not the family.
