**First-class ThreadSafeContext + generic AsyncContext(V) — v0.15.0 (2026-07-11).** Prior v1.4.0 families used a value-cache/own-mutex shortcut and there were no distinct TS/Async *context* types. v0.15.0 makes them genuine (operator-chosen "distinct types + families ride on them", NOT a full engine mirror):
- `thread_safe_context.zig` `ThreadSafeContext`: a lock-backed Send-shareable reactive context DISTINCT from the `build_options.thread_safe` mutex flag on `Context` (so both can coexist). Standalone **id-keyed** registry (the fn-pointer-keyed `Context` can't mint per-*runtime*-key nodes) with type-erased box storage + monomorphic-per-`T` recompute/free thunks; one `ParkingMutex` serializes every op; reads returned **by copy**. Lazy recompute, PartialEq (`std.meta.eql`) writes, `computedClosure` (userdata) computes. `TsHandle(T)` phantom-typed handles.
- `async_context.zig` generalized `AsyncContext` struct → `AsyncContext(comptime V)` type constructor (nested `ComputeContext`/`SlotNode`; `std.meta.eql` guards). Added `computedAsyncClosure(ptr, fn)` — the `*anyopaque` userdata that lets a per-key async slot resolve a key-dependent value on a no-closure engine. Back-compat: old `AsyncComputeContext` top-level export dropped (now `AsyncContext(V).ComputeContext`); `AsyncContext(u32)` is the historical instantiation.
- Families rebuilt: `ThreadSafeReactiveFamily` rides `*ThreadSafeContext` (each entry a real cell; present-set behind family `ParkingMutex`); `AsyncReactiveFamily` rides `*AsyncContext(V)` (cell entries = async cells, slot entries = genuine async slots pending-until-`drive`/`settle`). **GOTCHA:** the async slot closure must capture a **heap-allocated** `slot_id→value` map, NOT `&self` — the family is returned by value from `eager`/`lazy`, so `&self` dangles after the move.
Zig gotcha: an unused `comptime T` param still errors ("unused function parameter") — discard with `_ = T;`.

lazily-zig (`src/lazily-zig`), Zig `0.17.0-dev.892` / mise `zig=master`. Released **v1.1.0** (2026-07-10, tag + GitHub release; superproject gitlink bumped). Two things fixed this session:

**1. ParkingMutex lost-wakeup DEADLOCK (was: full `zig build test` / `make check` hung).** The 3-state futex mutex (`parking_mutex.zig` `lockSlow`) acquired the lock as `LOCKED` when a woken waiter observed `UNLOCKED` from the wait path — dropping the `CONTESTED` flag. With ≥2 waiters parked, waking one (which re-acquired as LOCKED) meant its `unlock` saw LOCKED and skipped `wakeOne`, stranding the co-parked waiter → hang in `futex_wait` at 0% CPU under N-thread contention (slot/cell thread-safe soaks). **Fix:** slow-path acquires by `swap(CONTESTED)`, never LOCKED (Drepper "Futexes Are Tricky" §2 / glibc lowlevellock). Full suite now runs green (139 pass/1 skip main module + all others).

**2. cold_full_recalc allocation bottleneck (profiled, `perf` ReleaseFast).** ~38% of wall-clock was `ArenaAllocator.alloc`, ~21–25% of it *growing the two per-node `AutoHashMap` edge sets* (`change_subscribers`+`parents`). Fixed with `SlotEdgeSet` (`#lzedgeinline`, inline 4 edges/direction, spill to map for high fan-out) → alloc self-time 38%→17%, edge-map `getOrPut→grow` 25%→3%. Plus `#lzinline` (inline small `.indirect` values in the slot vs heap box) and `#lzcachegop` (initKeyed dedup+publish = one `getOrPut`). ~8–12% cold gain (pinned core; wall-clock VERY noisy — use `taskset -c N` + min-of-8, not single runs). Residual gap vs cpp/rs is definitional (zig materializes formula nodes lazily *inside* cold_full_recalc) + global 2N-entry keyed-cache hash-probing.

Also fixed: `cellFn` test now asserts dependents are **stale-in-cache** after a cell `set` (invalidate-in-place `#lzinplace`, v1.0.0), not removed.
