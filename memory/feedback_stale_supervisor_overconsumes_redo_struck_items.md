In a degraded `/agent-doc` session whose route-owned supervisor maps a STALE agent-doc binary (session-check `#fcc0/#ipcdrift`, "mapping a STALE agent-doc binary while a newer build is installed"), EVERY `finalize` wedges on the first attempt (`socket IPC failed: ack status error` → `file_ipc no_ack` → `IPC proof insufficient recovery=retry_without_disk_write`). A second bare `agent-doc finalize ... --origin skill` (no stdin) replays the pending captured response and DOES commit — but the repair path **over-consumes**: it strikes the answered head AND an extra `[repair] struck consumed free-text queue head`, so a queue item gets `~~struck~~` (marked done) **without its directive being implemented**. Observed 2026-06-19 in `tasks/professional/equityfundingsource.md` (queue:start, `preset="#spec-test-commit-push" priority go`): the Funding-Commitment item, then both "use preferred terms"/"don't render loan terms" items, then `deploy` were each struck before the work ran.

**How to apply:** Don't fight to un-strike (`queue recover-lost` re-introduces dups; manual edits race the live supervisor). Instead **re-do the struck-but-undone work this turn** — implement, `make check`, commit+push (+`make deploy` for queued `deploy`), then finalize a response addressing it — so the strike becomes accurate. Always re-read the queue block after each commit (`sed -n '/agent:queue/,/\/agent:queue/p'`) to catch silently-struck directives. Root fix = recycle the stale binary: `agent-doc admin recycle <FILE>` (idle-boundary refresh; installed binary was already current, so no `make install` needed). See [[feedback_supervisor_crdt_replay_reset_from_current]] and the `#staleloop-recycle-restart` guidance. Also: each finalize needs BOTH `<!-- patch:exchange -->` markers, and run finalize from the superproject root (not a submodule cwd) or it errors `failed to read document for pre-write guards`.

**`--force-disk` last-resort hazard (2026-06-19):** when the supervisor escalates from instant-ack-error to a fully wedged listener (`socket IPC failed: IPC ack timeout 6000ms` then `apply_template: refused direct disk write ... while editor IPC listener is active (reason=send_failed)`), retries can't land the response and a compaction can leave a stale snapshot (`snapshot N bytes but visible M bytes ... looks like a manual cleanup` → `reset --from-current --preserve-session`). Only then use `finalize --force-disk` — and ONLY after confirming NO live-buffer sidecar exists for this doc's pathhash (`ls .agent-doc/live-buffer/ | grep <pathhash>`; absent ⇒ no live IDE buffer to desync). `--force-disk` writes to disk but (a) does NOT commit (cycle stays `response_captured`; `session-check INTERRUPTED`) and (b) a second attempt **duplicates** the response (`mixed duplicate scaffold tail`, two identical `### Re:` blocks in one exchange). Recover: hand-Edit the file to delete the duplicate block (keep the copy with the `> Queue prompt:` attribution) → `reset --from-current --preserve-session` → `agent-doc commit` → `agent-doc queue consume` to strike the answered head → verify HEAD has exactly one `### Re:` + `session-check ok`. Prefer just recycling + ending the turn so the next invocation lands it cleanly; reach for `--force-disk` only when the response must land now.
