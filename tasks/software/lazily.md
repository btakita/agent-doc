### Re: do [#lzconsumednotasserted] — opus-5

Done across all nine bindings. Wrote the shared contract to `tasks/software/plan-lazily-consumed-not-asserted.md` first so the bindings converged on one mechanism, then ran one agent per repo.

**The guard.** Each binding extends its existing `#lzassertunknownkeys` tracker rather than growing a second one: an `asserted` set beside `read`, a single assertion entry point that is the *only* way to mark a key asserted (so an arm comparing against a literal can no longer mark), a non-equality variant that hands the fixture's own value to the caller's check, and `excuseKey(block, key, reason)` checked in both directions so an excuse that has gone stale fails instead of hiding nothing. Verification now fails three ways: never read (rung 2, unchanged), read but never asserted, stale excuse. Four bindings deleted their old silent-consume helper outright — `consume()` in zig and cpp, `MarkConsumed` in cs, `consume()` in kt — because a bare "mark it read" was the undeclared form of an excuse.

**What the audit found.** Sites where a key was read and discarded, by binding: dart 411, py 543, js 456, rs ~240 read sites with 12 distinct defects, zig 22, cs 14, kt 12, go 6, cpp 3. The large counts are honest rather than alarming — in the dynamic bindings, "compare by hand against `block[key]`" and "read and drop" are indistinguishable to anything watching property access, so consumption was never evidence of comparison and every site had to be re-routed. Almost everything was fixed by **implementing the real assertion**; excuses are rare (dart 0, go 0, py 1, js 3, kt 3, cpp 1, cs 2, rs 5, zig 6) and each names where the fact is proven instead.

The genuinely rotten sites were the ones asserting against a literal. `distributed.resolution` compared the *fixture* to `"max_stamp"`. `materialization.default_mode` compared the fixture to `"eager"`. `redeliver_applied_count` compared to `0`. `reliable_sync.span` compared to `3`. In lazily-zig, seven `ipc` fixtures carried an `assertions` block nothing ever opened while the same numbers sat re-typed as Zig literals in the runner, and three `OutboxStore` scenarios were hand-transcribed epoch by epoch — those are now fixture-driven replays. In lazily-cs, three `Signaling` claims were `Assert.True(<the fixture's own value>)`: the fixture compared against itself.

Several probes paid off in library facts, not just guard facts. Asserting kt's `magic` against the library instead of the literal `"LZSH"` failed with `HSZL` — the magic is a little-endian `u32`, so the on-disk byte order was never what the literal claimed. zig's master toolchain caught a real portability break (`@typeInfo(...).@"enum".fields` renamed, `std.EnumSet.initEmpty` gone). go's `ipc.schema_version` was decoded and dropped, so a fixture carried across a major schema bump would still have passed.

**Verification.** Every binding mutation-checked all three failure modes and restored between probes: break an assertion into a bare read, add an excuse beside a live assertion, delete an arm outright (confirming rung 2 did not regress). cpp and cs added probes proving their excuses are load-bearing rather than decorative, and cpp inverted an observation to prove the guard asserts the library rather than its own counters. All nine `make check` runs exit 0; all nine CI runs are green on the pushed shas. `lazily-spec` is untouched — no probe edited a shared fixture.

**Two things this turned up that are worth their own items.** lazily-go found a fourth shape the plan did not anticipate: typed bindings decode fixtures into structs, and while an unused *local* will not compile, an unused *field* is silent — `open_handles` and `schema_version` were invisible to the map tracker by construction. It added a `go/ast` field scan; the other typed bindings need checking (`#lzstructfieldreads`).

More important, lazily-cs found the next rung. Its library-level probe — reversing the roster sort — still **passed**, because `anti_spoof_session.json` never produces a roster with more than one entry, so no ordering is observable on it. A fixture can be opened, fully consumed, fully asserted, and still prove nothing, because the *data* cannot distinguish the claim. No runner-side guard reaches that; only mutating the library does (`#lzfixturediscrim`). Also filed: runners still outside rung 2 entirely in cpp and cs (`#lzrung2gaps`), and the `assertKeyWith` closure seam rs flagged, where a closure that ignores its argument marks a key asserted without proving it (`#lzassertwithseam`).

### Re: Protobufs for the key-validation work — opus-5

Asked in console last cycle, recording the answer here since the document is the durable record.

Short version: no for the corpus encoding, yes to the underlying want.

Protobuf would delete the mechanism all three key guards depend on. They work by intercepting dynamic key access — `block["key"]` is a map read a tracker can record. Codegen replaces that with compiled struct fields nothing can intercept. That is not hypothetical: it is precisely the blind spot lazily-go found in `#lzconsumednotasserted`, where an unused *local* will not compile but an unused *field* is silent, and `open_handles` and `schema_version` were both decoded and dropped. Adopting protobuf makes that the situation in all nine bindings — trading one runtime tracker for nine language-specific static analyzers, in Zig and C++ too. It also would not buy the rungs back: proto3 deliberately tolerates unknown fields and dropped `required`, so rung 2 is not covered; rung 3 is a property of runner control flow; rung 4 and `#lzfixturediscrim` are properties of the data.

But the schema instinct is right, and the instrument already exists. lazily-spec has 14 JSON Schemas using `additionalProperties` and `required`, with `tests/test_schema_conformance.py` carrying both-directions stale-form rejection tests written after a real `slot_id`/base64 drift incident. Two gaps: those schemas validate the `wire` field, while every defect found in the last two cycles lived in `expect`/`expected`/`assertions`, which are entirely unschema'd; and only about 13 of 31 fixture areas have a schema at all. Filed as `#lzassertionblockschema`, marked recommended rather than actioned since it was a question, not a directive. Schema the assertion blocks and `#lzwqfixtureconfig` closes structurally.

Protobuf for lazily's own *runtime* wire format is a separate and more legitimate question — but `protocol.md` already specifies a normative externally-tagged byte-array form that all nine bindings serialize, so that is a wire-break decision rather than test infrastructure. Not filed; say the word if you want it evaluated.
