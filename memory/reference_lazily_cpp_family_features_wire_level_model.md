lazily-cpp **v0.9.0** completed the C++ feature-table gap: `ThreadSafeReactiveFamily`, `AsyncReactiveFamily`, and reactive family sync (`#lzfamilysync`). Header-only; publish = git tag `v0.9.0` + `gh release` (no package registry). CI (`ci.yml`, g++/clang++ matrix) green.

Key design fact (non-obvious): the C++ `CrdtPlaneRuntime` (in `include/lazily/command.hpp`, NOT `crdt.hpp`) is a **wire-level convergence tracker** (op-log + `winning_` map by NodeId), like `lazily-js` — NOT the reactive-graph-integrated runtime that lazily-rs/lazily-kt bind into a `Context`. So family-sync followed the **JS model**: `membership_epoch()` is a plain `uint64_t` counter (not a reactive cell), bool family values encode as a single byte `IpcValueInline{{value?1:0}}`, and `family_keys()` returns full `namespace/suffix` paths (test strips suffix). Family entries mint private NodeIds from `kFamilyNodeBase = 1<<48`. Added `Hlc hlc_` member for local stamping (`family_set_lww`). The two family headers port lazily-rs 1:1 (traits over CellHandle/SlotHandle; ThreadSafeContext/AsyncContext reuse the same handle types).

Conformance: `conformance/materialization/*` replayed through BOTH new families (hand-transcribed, no JSON loader — the repo's established pattern); `conformance/familysync/materialize_on_ingest.json` (3 scenarios) for family-sync. lazily-formal proofs (`Materialization`/`AsyncMaterialization`/`FamilySync.lean`) already existed — C++ conforms, no Lean changes.

**v0.10.0 (2026-07-12) — reliable sync (`#lzsync` + `#sync-driver`) = FULL feature-table parity** (last two C++ rows flipped ✅). New header `include/lazily/reliable_sync.hpp`, ported 1:1 from lazily-kt `ReliableSync.kt`: `ResyncCoordinator` (gap→RequestSnapshot, multi-epoch-span deltas, idempotent Ignore), `DurableOutbox`/`InMemoryOutbox` (append-before-send, replay-from-cursor), `OrSet`/`WireLwwRegister` liveness cells, and full-duplex `SyncDriver` over `std::function` seams (`IpcSink`/`IpcSource`/`Clock`/`SnapshotProvider`). Wire: `ResyncRequest`/`OutboxAck` are two new `IpcMessage` variants — added to `ipc.hpp` (variant + `ipc_resync_request`/`ipc_outbox_ack` ctors), `codec.hpp` (msgpack type discriminators **3/4**), and `ffi.hpp` `LazilyFfiMessageKind` (**4/5**, matches spec schema); the pre-existing `pack_ipc_message` `else` assumed CrdtSync — MUST convert to explicit `else if` chain when adding variants. All 5 `conformance/reliable-sync/*.json` fixtures hand-transcribed into `tests/test_reliable_sync.cpp` (+ codec round-trip + SyncDriver integration). `lazily-formal ReliableSync.lean` already existed and is imported — cpp `test_formal` gates on `lake build`, no Lean changes. `make check` 16/16; release CI green; published tag `v0.10.0` + `gh release`.
