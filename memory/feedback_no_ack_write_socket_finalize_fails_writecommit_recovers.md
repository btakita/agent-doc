When `finalize` fails every cycle with `socket IPC ... ack status error` → file-IPC `IPC timeout (2s)` → `IPC proof insufficient ... invariant=no_ack recovery=retry_without_disk_write` AND `admin inspect` shows `controller:fresh,supervisor:fresh`, the JB editor plugin's **write socket** is dead (NOT a stale binary, NOT a stale supervisor). The queue-convergence/read path still acks OK during preflight — only the finalize write path is broken.

**Recovery that works:** `agent-doc write --commit <FILE>` reliably absorbs the orphaned response out-of-band and commits it (the preflight repair path does the same on the next cycle). Use it every cycle the broken socket persists. Do **NOT** retry `finalize` (degraded-IPC retries queue duplicate patches → N duplicate `### Re:` blocks per [[feedback_degraded_ipc_write_retry_duplicates_response]]). Do **NOT** `agent-doc commit` (it refused here: "captured response body is not present in the staged snapshot ... refusing already-committed closeout. Replay with `write --commit`"). For a `do #id` head, pass `--done <id>` to the `write --commit` (the finalize pending-done guard requires it).

**Why:** This is the `no_ack` variant. Distinct from [[feedback_dead_jb_listener_send_failed_blocks_finalize]] where reason=`send_failed` and `write --commit` ALSO fails (→ STOP, operator restarts IDE). Here write --commit succeeds, so DON'T stop the work — recover and continue. The real fix is an operator IDE/agent-doc session restart to restore the write socket; until then write --commit is the per-cycle recovery and work still lands in HEAD.

**How to apply:** finalize no_ack + supervisor fresh ⇒ `write --commit` (+`--done` for `do #id` heads) once, verify `git show HEAD:FILE` has the response + working tree clean, continue. Recovery side effect: the recovery often consumes/strikes the current free-text/`do #id` queue head as "answered" — honest only when the work is actually done, so finish the work before recovering. Drained the whole EFS contextual-lender-chat feature (#lender-ctx-chat + #lenderdealattach) this way 2026-06-26 across a session with a persistently dead write socket.

**Queue left un-reconciled after a degraded-path commit (2026-07-01, reitrades go-queue):** When the response commits via the degraded path (`write --commit` reported `already_applied` → response landed in HEAD) but the JB write socket then wedges harder (`ack_mismatch`, `editor_endpoint=live`), the **queue drain can be left un-reconciled** — the answered free-text heads + a `go` marker stay in the committed doc and will churn (re-answer) on the next healthy preflight. The proper tool is `agent-doc queue consume <FILE>` (strikes leading answered heads). BUT once the editor buffer diverges, preflight AND the binary paths fail-closed on `visible editor buffer differs from expected disk state` (even `finalize --force-disk` runs a pre-write gate that refused with `latest cycle already committed`), so `queue consume` may also be blocked. With explicit operator force-disk authorization and the response already safely in HEAD, the reconciliation is: clear the `<!-- agent:queue go -->` block to an empty `<!-- agent:queue -->`/`<!-- /agent:queue -->`, set frontmatter `queue: stop` (remove `go` AND stop per [[feedback_go_marker_churn]]), and `git commit` directly with an `agent-doc(<doc>): ...` message — agent-doc owns the boundary marker (already correctly placed on disk), so a hand git commit of the drained queue is safe when IPC is dead. Note: `finalize`/`write --commit` "latest cycle already `committed`; refusing explicit-baseline response" is a FALSE post-success error — check `git log`/`git show HEAD` first (the commit already landed) before any retry. This session also needed the mv-cycle-aside dance twice ([[feedback_stuck_response_captured_cycle_mv_state_cycles_json]]) because the degraded socket kept re-poisoning `response_captured`.

**Escalation when write --commit ALSO no_ack's (2026-06-26 #msg-dialog-focus):** sometimes BOTH `finalize` and `write --commit` fail the same `ack status error`→`no_ack` (supervisor still fresh) — this looks like the [[feedback_dead_jb_listener_send_failed_blocks_finalize]] STOP case but the reason is `no_ack`/`ack status error`, NOT `send_failed`. Here `finalize --force-disk` DID recover: it cleans the stale IPC patch, force-writes to disk, CRDT-merges the concurrent live-buffer edit (`cell_merge conflict ... policy_chose_ours=true`), commits, and consumes the answered head. It may then `session-check INTERRUPTED` on a SECOND answered free-text head ("deploy") still active — clear it with `agent-doc queue consume <FILE>` (strikes the leading answered free-text head; drains queue_active), then re-run `session-check` → ok. So the ladder is: finalize → write --commit → **finalize --force-disk** (+ `queue consume` for straggler heads). Only treat it as a hard STOP when reason is genuinely `send_failed`.
