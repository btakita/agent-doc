# Queue Markers

Every row in an `agent:run` (or `agent:loop`, or legacy `agent:queue`)
component can carry a leading marker such as `🚧` or `☑️`. agent-doc writes
these markers. They show the row's durable lifecycle state, which agent-doc
derives from its claim ledger, report receipts, and completion cells. They are
never part of the row's work text: every parser strips them before it matches,
claims, or strikes a row, so a marker change never retargets work. Editing a
marker by hand does not change the state; the next projection repaints it.

Stable link for other pages: `docs/guide/queue-markers.md#queue-markers`.

## Legend

Lifecycle markers are mutually exclusive: an executable head shows exactly
one. `🙋` combines with a lifecycle marker (`🙋🚧`). The two pins set
priority, not lifecycle.

A nesting group label — a row whose only job is to name the heads indented
under it — is not a head and is not ready to run. It carries no `📥`. The
next projection removes a pending marker from a group label. A claim, report,
or completion on that same row still projects. A sub-prompt child is part of
its parent head, so it carries no lifecycle marker of its own either; a bare
`📥` on a child is removed on the next projection. An operator pin on a child
stays.

## Where the legend appears

The legend has one definition in the code (`agent-doc-queue-icons`), and three
surfaces render it:

- **Help.** `agent-doc queue --help`, plus the long help of `queue claim`,
  `start`, `report-complete`, `release`, `claims`, `brief`,
  `repair-projection`, and `recover-lost`. `agent-doc queue legend` prints it
  with your configured palette; `--line` prints the document line, and
  `--markdown` prints the table above.
- **Each document.** When a document has a runnable-work component, agent-doc
  keeps one compact legend line as the last paragraph of `agent:status`:

  ```text
  Queue markers: 📥 pending · ⛔ blocked · 🟡 claimed · 🚧 running · ☑️ keep: worker done · ⚠️ lost · 🔄 needs reconcile · ❔ unknown · ⏭️ skipped · ⏳ awaiting operator · 🙋 operator action · 📌 pinned · 📍 agent pin · ~~done~~ safe to delete ([legend](…/queue-markers.md#queue-markers))
  ```

  New documents from the Claim for Tmux Pane template start with it. An
  existing document gets it on its next status write. Every status write
  replaces the line rather than adding another, so a document has at most one,
  and it follows your palette. To hide it, set `queue-legend=off` on the status
  marker: `<!-- agent:status patch=replace queue-legend=off -->`.
- **This page.**

## What `⛔` means

`⛔` (blocked) means the row's tracked item cannot start yet, because other
work it waits on is still open. agent-doc paints it with the open blocker ids,
for example:

```text
- ⛔ ⟦blocked by bossroom-sbx-provision⟧ do [#bossroom-stg-provision]
```

agent-doc derives the state from the tracked item the row names (`do [#id]`)
in `agent:backlog`, `agent:todo`, or `agent:review`:

- **A stays-open blocker clause.** The item text carries
  `(stays open: blocked behind #a, #b)`. Every `#id` inside the clause is a
  candidate blocker. The clause must say it blocks (`blocked`, `blocker`), so
  a `(stays open: ...)` note about something else is not read as one.
- **An `after=#id` edge**, or a nested ordered-list predecessor in the queue.

A candidate blocks only while it names an item that is still open in this
document's backlog, todo, or review. An id that is done, archived, or not an
item here does not block: a PR number such as `#749`, or an id that moved to
another document. So the row returns to `📥` on the first projection after its
last open blocker closes. A clause whose ids are all closed or absent leaves
the row runnable, because agent-doc only derives blocked state from ids it can
watch close.

A blocked row is held out of the queue:

- A row blocked by a stays-open clause is deferred: no drain selects it,
  inline or supervisor, it is not counted as drainable, and session-check
  counts it with the deferred heads. A row blocked only by an `after=` edge
  keeps the dependency gate it already had: it is not counted as drainable
  while the prerequisite is open in the backlog, the queue orders the
  prerequisite first, and a head whose turn is already running is not
  preempted when a dependency is added.
- `queue_subagent_dispatch`, session-check's "queue awaits subagent dispatch",
  and the `subagents=N` planner never offer it, so it does not take a slot
  from runnable work.
- A row blocked by a stays-open clause is never marked `⏭️`. It was never
  dispatched, so it cannot have come back unconsumed.

A live attempt still outranks it: a claimed, running, reported, lost, or
reconciling row keeps that marker. `⛔` outranks `⏳`, `⏭️`, and `📥`.
agent-doc never edits the row's text or the tracked item: only the marker and
annotation change. To unblock a row by hand, close the blocker or edit the
clause in the tracked item. The exact rule is in
`specs/07-orchestration-commands.md` (`#queueblocked`).

## When a `☑️` row closes

`☑️` (reported) means **keep this row**: a worker finished and reported back, but nobody has
integrated its result yet. The state comes from one of two records: a
`Reported` claim attempt (`queue report-complete`), or a release receipt
(`queue release` without `--requeue`). For an executable leaf, agent-doc never
strikes a `☑️` row by itself, never downgrades or reopens it from later runtime
evidence, and time never clears it. Only the operator can reopen that leaf by
removing the `☑️` marker in the document. A structural parent is different: it
owns no worker lifecycle, so agent-doc removes a stale parent marker and lazily
derives its strike from the leaves (struck only while every leaf is struck).
The coordinator closes a reported leaf in a closeout, and
which close works depends on the row's shape:

Closure is not tied to the end of a harness turn. As soon as the coordinator
has integrated and verified the delivery boundary authorized by the queue item
(for example, a PR exists when PR delivery is the requested outcome, or the
change is in the target branch when branch delivery is required), it should
close the row immediately. For an id-backed row whose tracked item must remain
open, `queue consume --ack-id` makes that strike visible mid-turn. A worker
merely reporting or publishing a branch does not prove a stronger delivery
boundary than the queue item authorized, so `report-complete` never auto-strikes.

Do not delete a live `☑️` row: it is the coordinator's integration/writeback
debt. A struck row (`~~row~~`) is integrated terminal history and may be
deleted. Automatic lifecycle projection never removes its strike, even if a
claim remains or a descendant is live; only the operator can reopen it by
removing the strike. For a nested prompt tree, wait until every parent and leaf
is struck; if even one row remains live, the tree must remain in `agent:run`.

| Row | What strikes it |
| --- | --- |
| Free text (`Setup … channel.`) | The coordinator's response quotes the row exactly as `> **Queue prompt:** <row>`, with no `**Deferred:**` line beside the quote. The row must also be in the turn's baseline, or be backed by its claim or release receipt. In a multi-item closeout, a quoted `> **Queue response:** …` immediately after the prompt makes that pair individually answer-bearing even when another prompt echo follows. |
| Id-backed, and the work is done (`do [#id]`, `[#id]`, `#review [#id]`) | `--done <id>` in the closeout (it resolves the backlog item or Todo and strikes the row). If the id no longer names an open backlog item, use `agent-doc queue consume <FILE> --id <id>`. |
| Id-backed, and the item must stay open | `agent-doc queue consume <FILE> --ack-id <id>`. The backlog item or Todo stays open. For a backlog item, the id is also recorded as kept open, so session-check does not requeue the row. |

A quote never closes an id-backed row; it needs one of the id commands. A
leading tag such as `#review` is not the row's id: `#review [#adr0043-publish]`
closes as `adr0043-publish`, the same id its claim uses.

There is no age-based expiry for `☑️`: it remains until one of these explicit
closeout paths succeeds. This keeps an unintegrated worker result from being
silently discarded, but a successfully integrated row should be closed in the
same coordinator cycle rather than left for a later timeout.

A valid `☑️` does not later become `⚠️` because its claim aged or its worker
exited. If you see that transition, either `queue release --requeue` explicitly
abandoned the reported attempt, or durable state needs reconciliation. Do not
strike the row merely because it is lost: recover the worker result when it
exists, otherwise requeue the unfinished work. A completion cell without a
governing attempt projects as `🔄`, not as proof that integration happened.
The current coordinator-admission path selects valid reported rows even when no
fresh worker row is drainable, but older orphaned state may still need
`agent-doc queue repair-managed-state <FILE>` (dry-run first, then `--apply`).

These keep a `☑️` row open on purpose:

- **`🙋☑️`**: a blocking operator request is still open. The `🙋` stays until
  that request's Todo is checked off. You can answer on the row itself:
  append `: <answer>` after the `[#subagent-operator-request-…]` id, and the
  next closeout checks the Todo off. After that, the row closes the usual way.
  An answered request whose Todo is closed does not hold the row.
- **A `**Deferred:**` line** next to the quote: the response says the work is
  still outstanding, so the row stays. A deferral counts only when the
  response states it: a phrase inside backticks or a code block is a quotation,
  and a phrase like "waiting on" counts only in the first bullet (or the first
  paragraph) after the quote, not in a later bullet about other work.
- **`🟡` / `🚧` on the same work**: `--id` and `--ack-id` refuse a row whose
  worker is still running. Report or release that attempt first.
- **The worker reported that the work is blocked**: do not close it with
  `--done`. Acknowledge the report with `--ack-id <id>`, which keeps the
  backlog item open. Name an open blocker in the item, as in
  `(stays open: blocked behind #blocker)`. A clause that only names closed
  items blocks nothing, so a row queued again would be dispatched again. When
  the blocker closes, queue the item again with
  `agent-doc backlog <FILE> requeue <id>`.

The exact rules are in `specs/07-orchestration-commands.md`
(`#reportedrelease`, `#claimstrike`, `#taggedidhead`, `#ackkeepsopen`) and
`specs/07-closeout-commands.md` (`#operatoractionstrike`,
`#answeredrequeststrike`).

## What `🔄` means

`🔄` (needs reconcile) means agent-doc found finished-work evidence for a row
but cannot tie that evidence to a current attempt. The evidence is a
binary-attested completion cell (the `agent-doc-subagent-completion` block that
`queue report-complete` writes into `agent:exchange`). Nothing governs that
cell: the row has no current claim and no report receipt. agent-doc does not
offer the row as fresh work, because a worker may already have done it, and
it does not mark it `☑️`, because no exact attempt proves the report belongs to
this row.

There are two usual causes:

- A worker reported, its claim was released or pruned, and the row was never
  struck. Integrate the result and strike the row. Every strike path retires
  the row's completion cell and receipt, so the row closes cleanly.
- A completion cell from an earlier row with the same text outlived that row,
  and a new row with that text now shows it. Under the strike-retirement rule
  (`#strikeretires`), every binary strike retires the cell. An operator's hand
  strike, or a strike made by a release before that rule, can still leave a
  cell that paints `🔄` on a later row with the same text. No command retires
  such a cell without also closing the new row, so ask the coordinator to
  reconcile it.

The exact rule is in `specs/07-orchestration-commands.md` (`#queueworkevidence`).

## Custom palettes

Each prefix can be overridden in `[queue_icons]` in
`~/.config/agent-doc/config.toml` (see [Configuration](../getting-started/configuration.md)).
Built-in spellings stay readable, so changing a prefix never strands an
existing document. The help output always shows the defaults; `queue legend`
and the document line show the configured palette.
