# Plan: regular ontology audit (`existence audit`)

Session: `tasks/software/existence-lang.md`. Repos:
`src/existence-lang/existence` (CLI), `src/existence-lang/ontology` (nodes).
Backlog ids for the phases live in the session document, one per phase,
each pointing at this file.

## Question answered first: track sources per item?

Yes, but do not add a second registry to hand-maintain. The nodes already
record their sources in a machine-readable shape that SPEC rules 7 and 8
mandate: an `<a href="…" target="_blank">` anchor followed by `>` blockquotes
of the passage that was relied on. Today that is 313 anchors across all 117
nodes (119 Wiktionary, 144 Wikipedia, a handful of etymonline / YouTube /
other) and 989 quoted lines. The tool should **derive** the source record from
that markdown and persist only what the markdown cannot carry: when a source
was last fetched, what its page looked like then, and whether the quoted
passage was still present. That lives in a generated lockfile the audit
updates, not in the nodes.

```
audit/sources.lock.json           # generated, committed by the audit PR
{ "https://en.wikipedia.org/wiki/Entity": {
    "cited_by": ["entity", "being"],
    "fetched_at": "2026-09-11T00:00:00Z",
    "status": 200,
    "content_sha256": "…",           # normalized page text
    "quotes": { "entity": "present" | "moved" | "missing" },
    "archive": "https://web.archive.org/web/20260911…/…"   # pinned snapshot
} }
```

Recheck during the audit = re-fetch each URL and compare against the lock:
reachability, quote presence (normalized whitespace, fuzzy ≥0.9 on the
quoted sentence), and page hash change. A dead link or a vanished quote is
**source drift**; a changed page with the quote still present is noise and
is only recorded.

## What the audit checks

Three classes, each with what can be resolved safely (mechanically, no
judgment) versus what must be reported for a human.

### 1. Structure and manifest (already partly built)

- `existence lint` (title, required sections, broken links, typed-link
  vocabulary and broader+narrower conflicts).
- `existence toc --check` (lay definition opens with a plain sentence, ring
  terms without files, files in no ring). Today it finds 6 real drifts.
- New: links that miss the `.md` suffix (`[environment](./environment)` in
  `evolution.md`) — neither lint nor the rebaser sees them. Safe fix: append
  `.md` when `src/<term>.md` exists.
- New: near-duplicate slugs (`signal`/`signals`, `human`/`humans`,
  `agree`/`agreement`, `redefine`/`redefinition`) — report only, with a
  definition-similarity score so the pair reads as merge/keep.

Safe resolve: `.md` suffix, and nothing else. Manifest membership is a
decision.

### 2. Contradictions (internal to the ontology)

- **Typed-link cycles**: `A broader B` and `B broader A`, or any cycle in
  the broader graph after inverses (`export` already computes both
  directions). Report; a cycle is a content decision.
- **Mutual lay definitions**: A's lay definition links B and B's links A
  (the `entity`/`information`, `abstraction`/`concept` pairs that the
  canonical-chain work had to resolve by hand). Detect as 2-cycles (and
  short cycles) in the graph of links that appear in lay definitions only.
  Report with both sentences side by side.
- **Unlinked mentions**: a known term used in a lay definition without a
  link (`Entity` in prose with no `[Entity](./entity.md)`). Report; auto-
  linking changes meaning when the word is used in its ordinary sense.
- **Semantic contradiction** (last phase): for each node, hand an LLM the
  lay definition plus the lay definitions of every node it links, ask for
  a contradiction verdict with the two conflicting sentences quoted. Report
  only, behind a provider flag (`--semantic --provider anthropic|openai`),
  never on the PR path. Verdicts are cached by content hash so a weekly run
  only re-judges nodes whose neighborhood changed.

### 3. Drift

- **Source drift** (section above): dead link, quote missing/moved, page
  hash changed. Safe resolve: replace a dead link with the pinned
  `web.archive.org` snapshot recorded in the lock (or fetch one now via the
  Wayback availability API); everything else is reported.
- **Mirror drift**: surfaces that copy definitions out of `ontology/src`
  and then rot — the `<!-- philosophy:start -->` table in
  `~/.claude/CLAUDE.md`, the sibling `philosophy/` repo (the pending genus
  port is exactly this drift), a published `terms.md`. Declare them in
  `existence.toml`:

  ```toml
  [[mirrors]]
  path = "../philosophy/src"          # node-per-file mirror; compare lay definitions
  kind = "nodes"
  [[mirrors]]
  path = "terms.md"                   # generated by `existence toc`; regenerate
  kind = "toc"
  ```

  Safe resolve: regenerate `kind = "toc"` mirrors. `kind = "nodes"` mirrors
  are reported as a per-term diff of lay definitions; the fix is a decision
  (or a decision to make the mirror a submodule/symlink so it stops being a
  copy).

## Cadence and reporting

- **Every PR / push** in the ontology repo: the fast structural subset
  (`lint`, `toc --check`, `audit --structure`). Fails the check.
- **Weekly** (`schedule: cron "0 6 * * 1"`): `existence audit --all
  --format json > audit/report.json`, then:
  - upsert one GitHub issue titled `Ontology audit` (find by title, edit
    body; do not open a new issue per run) with the report grouped by class
    and the diff from last week's report;
  - open or update one PR `audit: safe fixes` containing only safe
    resolutions plus the refreshed `audit/sources.lock.json` and
    regenerated toc mirrors. Idempotent: reuse the branch.
- The report JSON is the interface; markdown rendering is a view of it.
  Exit code: 0 clean, 1 findings, 2 audit could not run (network).
- Network fetches are rate-limited (1 req/s, `User-Agent` set) and the
  source pass is skipped, not failed, when a host is unreachable.
