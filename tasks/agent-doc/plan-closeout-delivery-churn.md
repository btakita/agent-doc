# Closeout and editor-delivery churn contract

## Architecture contract

- **Invariant:** A remote delivery identity may be decoded into a local replica at most once while its visible editor projection or ACK is outstanding. Exact visible editor content is sufficient ACK proof even when disk persistence is deliberately deferred; disk-save status cannot gate the ACK. Repeated pulls of that identity coalesce into the retained projection/ACK state; they do not mutate the replica again, enqueue another EDT apply, or count as forward progress.
- **Invariant:** A remote canonical rejected by the template-structure guard is never left as the attached native replica frontier. When the unchanged live editor baseline is itself structurally exact, each editor replica manager performs one fenced text-adopt and atomic re-registration; otherwise it fails closed with bounded retry and never overwrites the editor.
- **Invariant:** An admitted operator edit is never projected away because disk is older or a native replica frontier is stale. If the native frontier does not equal the edit's shadow baseline, the plugin adopts the exact structurally-valid visible editor text once and atomically re-registers before accepting another delta.
- **Invariant:** Save is a durability acknowledgement, not a second logical mutation. Unsaved and saved forms of one queue edit share one semantic identity and produce exactly one canonical queue item.
- **Invariant:** Any disk change while an editor is open is an independent pending candidate, never CRDT authority and never the pending-response slot. Accept propagates the exact visible editor cut before clearing; a newer editor edit or exact save-flush clears the candidate; final editor close clears it and falls back to disk. Authority order is editor/CRDT, disk, then Git recovery evidence.
- **Invariant:** Closeout reports `committed` only when the authoritative response projection is durable and the session document at `HEAD` equals the proven closeout snapshot. A binary-owned compacted projection may cross the historical-response guard only with durable compaction evidence; arbitrary response-bearing drift remains fail-closed.
- **Invariant:** Commit-seam free-text cleanup is a bounded disk transaction. It performs no controller lookup while holding the document lock; ordinary editor-authoritative cleanup finishes its controller read before lock acquisition.
- **Invariant:** A baseline overlay is a cache paired with a named explicit markdown baseline, never implicit merge authority. With no baseline path, a stale `.overlay.yrs` sidecar cannot resurrect a consumed queue head.
- **Invariant:** Controller recycle invalidates a JetBrains replica registration and starts bounded re-registration. A disconnected relay cannot remain permanently idle while its document is still open.
- **Invariant:** Force-disk authorization is revalidated at the mutation boundary. If an editor relay registers or editor authority otherwise changes after authorization, the force-disk transaction aborts before projection/commit; it cannot race the relay, duplicate a response, or advance the boundary from stale content.
- **Invariant:** A timed-out preflight cannot retain document/controller work after its owner exits. Cleanup may signal another process only with same-document, command-shape, age, and orphan/owner-death proof; wrapper exit 144 after an intentional kill is cancellation evidence, not a new product failure.
- **Invariant:** Controller backpressure is a shared-capacity signal, not a retry prompt. Idle watchers use one controller-wide bounded backoff/coalescing gate, and a live-editor response already materialized by semantic response identity is retired instead of resubmitted to the merge/write path.
- **Invariant:** A foreground editor-ACK deadline is not response-write failure when canonical CRDT authority and the applied receipt still prove the exact complete target and asynchronous recovery has been successfully signaled. That state returns retained success and continues one binary-owned retry; it never instructs the agent or operator to retry finalize, force disk, or recycle the controller.
- **Invariant:** A retained document write owns its exact capture until settlement. Concurrent repair cannot retire that capture from a reused heading or temporarily missing body; a historical false retirement may reactivate only the identical capture ID, cycle ID, and response hash after the full response body is proven in converged editor, canonical, and disk authority.
- **Invariant:** ACK retry backoff is an admission gate, not only a timer. External CRDT events may mark pending work while backoff is active, but cannot start another drain or decode the retained delivery until the gate expires.
- **Invariant:** A controller commit request is sent on the same acquired stream that established controller liveness. A recycle after acquisition is a transport failure, not permission to reconnect ambiguously or fall back to a local commit.
- **Invariant:** Response recovery is cell-idempotent. A complete retry atomically supersedes stale uncommitted response tails, preserves intervening operator prompts, and an exact subsequent replay performs no mutation, leaving one final response and one boundary.
- **Invariant:** Release and local-install automation must produce an artifact accepted by its destination and must select a JetBrains target from explicit or runtime-proven evidence. Ambiguous targets fail with an actionable selector instead of consuming stdin implicitly.
- **Invariant:** A supervisor hot-reexec that preserves a live harness child preserves its successful capability proof instead of launching a competing proof child. Reuse requires the same surviving child plus an exact launch/capability fingerprint; any missing, changed, pending, or failed evidence re-proves.
- **Invariant:** A network probe proves the effective sandbox boundary, not the existence of a second model turn. `danger-full-access` Codex has no child sandbox, so the exact DNS/HTTPS command runs directly with the resolved child environment; sandboxed Codex/OpenCode still prove through their harness child.
- **Policy owners:** the JetBrains and VS Code `CrdtReplicaManager` adapters implement the same typed in-flight delivery, template-projection, fenced live-editor recovery, ACK-retention, and recycle re-registration policy; `agent-doc-workflow::capture::decide_stale_capture_retirement` owns whether a capture may retire; capture/cycle IO apply the exact-identity reactivation effect; `agent-doc-closeout-runtime-io` and `agent-doc-document-realtime-io` own the converged full-body settlement proof; `agent-doc-queue-io` owns strike read/lock ordering and commit-seam disk authority; `agent-doc-write-runtime-io` owns explicit baseline selection; `agent-doc-document-realtime-io` owns the force-disk authorization scope and mutation fence while write/compact entrypoints hold that scope across response generation; `agent-doc-turn-executor::capability_proof` owns exact proof-contract fingerprinting and the reuse/re-prove decision while `agent-doc-start-runtime-io` owns the same-child reexec handoff effect; `agent-doc-agent-io` owns timeout process-group cleanup/classification; `agent-doc-commit-io` plus the preflight/session-check closeout projection owns durable HEAD proof and compaction authorization; the executable model owns cross-layer trace semantics; the `Makefile` owns PyPI wheel compatibility; `src/plugin.rs` owns editor target discovery and selection.
- **Evidence inputs:** remote `patch_id` and `generation`, update bytes/content hash, current forwarder identity, controller instance/transport failure, pending EDT projection and retained ACK map, retained document-write presence, capture/cycle IDs and response hash, full-body materialization in converged editor/canonical/disk text, remote/editor template-normalization states, exact live editor text, unchanged shadow-baseline proof, recovery-in-flight state, strike mode and disk/controller source, document-lock boundary, explicit baseline path and paired markdown/model content, force-disk authority epoch and relay count immediately before mutation, process command line/document/parent/start age, surviving reexec child PID/master FD and proof-contract fingerprint, editor/disk/shadow hashes, cycle phase and response marker, snapshot/file/HEAD hashes, authoritative-compaction scope and archived exchange evidence, host wheel compatibility, explicit plugin directory and active IDE `idea.plugins.path` evidence.
- **Allowed edit surfaces:** JetBrains and VS Code replica-manager policy/recovery boundaries and focused parity tests/spec; an agent-doc-owned executable model and trace fixtures; queue consume read/lock policy and focused tests; write-runtime baseline and force-disk scope entrypoints; document-realtime force-disk authority/focused tests; agent backend child-process lifecycle and focused tests; compact force-disk scope port; closeout commit, preflight/session-check proof code only if evidence requires it; plugin installer CLI/discovery/tests; Makefile release target and release documentation; generated skill/version surfaces required by a patch release.
- **Verification:** reproduce duplicate pull behavior in deterministic replica-delivery tests for both editors; prove one decode/apply and retained ACK retry; prove every template-projection decision row, including fenced valid-editor adoption and invalid/stale-editor fail-closed behavior; prove controller loss triggers bounded replica re-registration; run generated fault traces through the reference model and assert safety invariants; compare legacy and Lazily-backed adapter observations or emit typed `CapabilityMissing` gaps; prove commit-seam strike performs no controller lookup and ordinary strike reads before lock; prove absent explicit baseline ignores stale overlay; prove a relay appearing after force-disk authorization aborts without write/commit while an already-live authorization retains its explicit semantics; prove a timed-out backend process group reaps a real background descendant and records cancellation; unit-test explicit/proven/ambiguous editor selection; build a `manylinux_2_17` wheel; run `make check`, editor suites, installation, and release validation.
- **Out of scope:** redesigning the controller CRDT or observable-set history, broad queue cleanup, automatic GUI restart, adopting arbitrary unsaved editor text without exact structure and unchanged-baseline proof, and unrelated working-tree changes.

## Executable model and Lazily migration contract

The reference model is agent-doc domain policy, not a second production runtime. Its state includes canonical/editor/disk/HEAD text, an independent pending external-disk candidate, semantic queue-item identities, delivery and ACK frontiers, controller/replica epochs, IPC queues, semantic response identities, and cycle phase. Its actions include local edit, queue-item admission, external disk change, accept pending disk, remote delivery, projection, ACK, capture, finalize, commit, save-as-durability-only, disconnect/reconnect, controller recycle, interruption, timeout, drop, duplicate, delay, and reorder.

Every reachable trace must preserve: editor text is never replaced without an exact authority proof; an accepted operator queue item is not lost and has multiplicity at most one on every plane; Save does not mutate canonical semantic identity; one semantic response identity produces at most one live response cell; ACK never advances beyond an exact visible projection; `committed` implies file, snapshot, and HEAD equality; a retained delivery is not decoded twice; timed-out work cannot outlive its proven owner; and, once injected faults stop, a live editor/controller pair can converge without force-disk or busy-looping.

Generated traces run against a pure reference reducer, the current implementation adapter, and a Lazily-backed adapter. Adapters expose only observable state and either match the reference or return a typed `CapabilityMissing` value. Capability gaps are classified separately from implementation mismatches and are promoted into Lazily only when the missing primitive is domain-neutral (for example retained cells, keyed single-flight, epoch/CAS fences, virtual-time backoff, cancellation propagation, durable-effect barriers, or an independent pending external-value decision).

Lean should encode the stable pure transition kernel and safety invariants once. Short-trace state-space exploration/property tests own concurrency and shrinking; liveness under fairness can be checked in TLA+ or an equivalent model checker. JetBrains, VS Code, legacy binary, and Lazily paths are adapters to the shared model, not separate formal specifications.

## Binary-owned finalize and evidence rules

After the first durable response capture, finalize is a keyed operation identified
by cycle id, capture id, and response hash. The CLI, Codex Stop hook, and
route-owned supervisor all resume that same operation through the strict
repair/write/commit seam. Only one supervisor worker runs per key; retryable
editor convergence, CAS races, controller backpressure, and ACK delays use bounded
backoff. The capture remains durable across process exit and supervisor recycle.
No automatic recovery uses force-disk or kills the controller.

Ambiguity rules are evidence-based: dedupe one semantic operation; choose a
causally newer authority over its stale projection; merge compatible complete
CRDT histories. If causal lineage is missing or two concurrent edits express
incompatible semantic replacement intent, retain both candidates and return
`needs_operator` without mutation. The executable model and Lean kernel enforce
this causal-versus-semantic boundary. The Lazily adapter reports
`EvidenceBasedAmbiguityResolution` as a typed capability gap until the core can
express the rule result and retained-candidate barrier directly.
