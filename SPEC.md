# agent-doc Functional Specification

- Removing a claimed `agent:run` row is authoritative cancellation
  (`#queue-removal-cancels`), not a best-effort request. Steering identifies the
  exact owner, bound harness worker, and claim generation. The binary first
  tombstones that exact identity+generation and retires any pending completion
  delivery so replay cannot resurrect or integrate it; a same-text re-add uses a
  fresh generation. The harness interrupts the old attempt only if still alive,
  at the nearest safe consistency boundary, preserves recoverable
  branch/worktree/commit artifacts, stops further implementation, tests,
  integration, publication, release, and external issue closure, then
  generation-fenced releases the claim. Best judgment controls only shutdown
  mechanics, never whether sunk-cost work continues. Irreversible effects already
  crossed are reported rather than undone. The binary emits this binary-to-harness
  contract without pretending it can kill a harness worker directly. When a
  live editor owns the document, cancellation additionally requires captured
  operator-operation lineage that removes the same claim identity; absence from
  a whole-buffer projection alone is not deletion evidence. Missing, unreadable,
  mismatched, unrelated, or duplicate lineage fails closed without cancelling a
  worker or invalidating a reported completion receipt. Detached disk edits keep
  the direct deletion path. Deleting a
  durably terminal struck row is presentation-only cleanup; a strikethrough that
  conflicts with claim or receipt evidence emits a degraded mismatch, once per
  owning attempt, and preserves/fences the work instead of cancelling or
  integrating it. A completion cell whose claim closed and whose receipt ended
  is stale residue, never ownership (`#deletedstruckmismatch`).

- Newly scaffolded and auto-created todo components use `<!-- agent:todo priority -->`; existing todo markers remain operator-owned and unchanged.

- systemd-backed `tmux-spawn-*.scope` units are stewarded without assuming
  ownership (`#tmuxscopesteward`): Rust-test targets prevent new scope creation,
  scheduled and on-demand sweeps reset failed units, and a running orphan is
  stopped only with empty-cgroup or executable-plus-temp-fixture ownership proof.
  All ambiguous processes are reported and left running. See
  [Session And Tmux Commands](specs/07-session-tmux-commands.md#tmux-spawn-scope-stewardship).

- An exhausted replica-rebuild budget (`state=editor_holds_unmerged_visible_text`)
  is resolved in place, not by a controller recycle (`#jetbrainsreplicaloops`):
  the controller sends a hash-fenced `editor_visible_roll_forward` event, the
  JetBrains editor publishes its complete visible buffer onto that exact
  canonical as one bounded splice, and the retained transition re-applies the
  pending write on top of the operator's text once. The remedy no longer forbids
  `admin recycle`; it is the fallback after the request. See
  [Real-Time Workflow Authority](specs/14-realtime-workflow.md).

- A retained captured write rolls FORWARD onto operator-authored editor text
  and never replaces it (`#retainedprojectionclobber`). Its rebase over the
  editor cut merges the frontmatter field-wise and both-diverged interstitials
  3-way; a rebase that would still drop an operator-added line is refused and
  reported (`retained_transition_refused_operator_text_loss`), never applied. A
  live editor whose updates are quarantined is never part of a converged
  delivery cut, is never dropped as a refusing replica, and an unreachable
  in-place roll-forward is terminal after a bound instead of a silent retry.
  See [Real-Time Workflow Authority](specs/14-realtime-workflow.md#retained-writes-never-replace-operator-text).
  Follow-ups (`#clobberfollowups`): a retained target waits while the editor
  has attested typing over the visible cut that the relay has not ingested; no
  commit seals a cut while a live replica is quarantined or the editor holds
  unmerged visible text; `realtime_doc_resolve` derives `diverged` from the
  quarantined live replicas; and `session-check` reports the operator-text
  refusal and the terminal roll-forward refusal with their remedies.
  `#inflighttypinghold`: the direct CLI CP-write path holds for attested
  in-flight typing too, both holds cover a mid-epoch burst (any prefix state
  of the epoch), and a commit refused over a quarantined replica names the
  quarantine (the barrier verdict crosses the controller RPC, `bool`-compatible).

- An agent component patch (`patch:status`, a todo or backlog patch) survives
  the response-only rebase onto a newer editor cut (`#statuspatchdrop`): it
  rolls forward where the operator left the component untouched, a component
  both sides changed goes through the per-cell authorship policy, and any agent
  component op a rebase still leaves at the editor's body is reported on stderr
  as `agent_component_patch_dropped`. Status-sync checkpoints quote the current
  `status:sync` payload and hash so they are answered against the document, not
  memory. See [Real-Time Workflow Authority](specs/14-realtime-workflow.md#retained-writes-never-replace-operator-text)
  and [Document Format](specs/02-document-format.md).

- A sync-managed `status:sync` payload is derived state owned by the `sync`
  instruction (`#statussyncrevert`): every status writer records the payload
  it landed, and preflight plus the mid-turn and final checkpoints demand a
  re-sync (`status set`, even with an unchanged answer) when the document's
  payload no longer matches it, as when an IDE undo walked back past the
  operator's own typo into the agent's status edit (2026-10-28 12:27Z). Undo
  stays available; operator text outside the block is untouched. See
  [Document Format](specs/02-document-format.md).

- `agent-doc serve`'s `POST /save` is a whole-document write with no base
  (`#servesavebypass`). It is refused with `409 Conflict` while an editor
  replica holds the document, and writes nothing and commits nothing then;
  otherwise it writes through `atomic_write_through_authority`, never a bare
  `std::fs::write`. See [Core Commands: serve](specs/07-core-commands.md#serve).

- Grok Build uses a native final-JSON backend and the existing managed
  supervisor lifecycle, with exact document-bound resume IDs and structural
  composer readiness. Passive hooks are not admission/continuation authority;
  the shared Grok skill uses connected admit/finalize. See
  [the backend contract](specs/05-agent-backend.md#grok-build-adapter).

- Cross-version supervisor recycle requests use a retained recycle-epoch high
  water mark, independent of compacted event counts. Settlement names the exact
  observed request epoch; a late settlement cannot consume a newer request.
  A fresh replacement acknowledges an uncleared legacy request only after
  successfully adopting its surviving child.

- Supervisor freshness display is a process-scoped effect of binary freshness.
  Its pane-local marker is display output, never recycle authority; adoption
  refreshes the warning without clearing the surviving child's turn title.
- Automatic layout ownership is a retained receipt/actor Computed separate from
  structural reuse: tab switches and geometry drift cannot erase outgoing
  ownership, while actor rebinding invalidates obsolete pane proof.
- A same-session document rename preserves its pane through the path-transition
  projection. Legacy sync may recover a missed editor transition only from one
  unambiguous registry row whose old path is absent and whose pane proves that
  old-path ownership; conflicting or still-live paths fail closed.
- Editor-route readiness is semantic across pane-layout generations. A newer
  generation that still contains the routed document remains awaitable and may
  satisfy dispatch when it converges. Absence, operator ownership, or a newer
  layout that removes the routed document remains a refusal; RPC must not
  republish competing layout generations.

- Retained-projection replica registration must preserve two independent facts:
  the bootstrap shape and causal frontier coverage. A durable canonical receipt
  may force a full bootstrap, but the controller must still compare the editor's
  supplied retained state vector and return `canonical_covers_retained_frontier`
  as true, false, or unknown. The editor may replace a live buffer that still
  equals its settled projection only when coverage is explicitly true. False or
  unknown coverage remains an ambiguity hold, and retained editor state is never
  union-merged into a forced canonical bootstrap.
- `#resumefrontierlostonfailedattach`: the editor releases a retained native
  resume state (the frontier a native-library reload captured) only when the
  registration that consumed it commits: its endpoint owns the document's
  forwarder slot and its projection finalized. A registration that held, raced
  the operator at the swap, or failed promotion keeps it, so the next
  registration still supplies the state vector and the controller can answer
  coverage as true. Releasing it earlier left every later registration with
  unknown coverage, and a buffer equal to its settled shadow held forever.
- `#lagcanonicalrollforward`: when every rebase planner refuses a registration's
  clean merge (or a captured-splice rebase), the live buffer is still the
  answer if it carries every change canonical made since the settled shadow:
  compared as whole changed lines over operator text (binary-owned boundary and
  `(HEAD)` markers and a queue row's attempt projection, such as a claim marker,
  removed), each canonical change lies inside one buffer change over the same
  base range, and canonical's inserted text reappears there in order with at most
  one run of later typing and nothing removed. A whitespace-only canonical
  insertion never counts. This covers a canonical that lagged the buffer only
  because live updates were refused (a structure-quarantined relay whose durable
  ops still landed), and a claim projection written onto the row the operator was
  editing. The editor text is the base; binary-owned projection the controller
  dropped this way is re-projected from its own state. A canonical change the
  buffer lacks still holds. The hold remedy says that no direction was proven
  lossless, never that the buffer diverged.
- `#lagcanonicalrowmerge`: when canonical both lags the buffer and carries a
  real controller change the buffer lacks (for example a claim marker on the
  queue row the operator is typing on, a prefix of that typing, and a response
  appended to the exchange), the rebase merges row-aware instead of holding.
  Canonical's whole-line changes since the settled shadow are split by whether
  they overlap an operator change. An overlapping change whose leading or
  trailing whole lines are controller rows beside the operator's row is split
  so those rows become insertions at that change's own boundary. Every
  remaining overlapping change must pass the `#lagcanonicalrollforward` dual
  proof, so the buffer is the answer on those rows. The independent changes
  then roll forward onto the buffer through the line merge, under the same
  lost-receipt guard and whole-line anchoring as any merge. Last, a queue row's
  attempt projection that canonical changed is moved onto the buffer's row
  with the same explicit work id, when that id names exactly one row in each
  text, the row is not struck, and the operator left the row's projection as
  it was. Every operator byte of the buffer is kept. A canonical change to a
  row's work text that the buffer does not carry (a rewrite, a strike, a close
  marker), or a controller insertion at the same boundary as an operator
  insertion, is a true conflict and still holds.
- A selected-document focus that resolves a proven live-owner pane outside the
  active `agent-doc` window must surface that pane before selection. Promotion
  and selection share the editor focus-generation fence, and the controller
  re-observes pane/window co-visibility after promotion. A stale desktop focus,
  failed promotion, or pane that remains stashed must not select in place or
  report success.
- Route startup must transport its resolved concrete harness through both
  provisional and child `start_session` publications. A missing or blank
  document `agent:` consults active actor authority for every admission mode,
  including a new route-created session; the literal `default` registry
  sentinel is absence, never a launchable harness identity. This prevents a
  Codex route from being overwritten and launched as Claude while editor
  metadata is temporarily unavailable.
- Effective queue pause authority fences the dead-supervisor watchdog as well as
  normal dispatch. Killing a quarantined supervisor must leave it stopped until
  the operator resumes the queue; a live pane and stale non-closed actor are not
  sufficient authority to relaunch its prior harness generation.
- The dead-supervisor watchdog restarts only a supervisor whose recorded pane is
  alive AND positively observed outside a `stash` window (`#watchdogbindinglive`,
  GH #133). A route-owned supervisor runs inside a shell pane, so a deliberate
  kill leaves the pane alive; a stashed pane holds no visible column and route
  re-provisions it on demand, so resurrecting it only undoes the kill. An
  unresolvable window fails closed. The skip is logged once per document and
  dead pid as `controller_supervisor_watchdog_skip reason=binding_not_live`.
- A dead-supervisor cold start has no live process that can accept replacement
  work. Its controller receipt therefore remains pending until the
  editor-authoritative document validates and the successor start command is
  submitted. A malformed live document or other cold-start failure returns a
  synchronous failed replacement receipt; it must never appear first as an
  accepted restart followed only by `background_failed`.
- A stale supervisor must validate the editor-authoritative frontmatter before
  replacing itself with a same-child `execve`. Transiently malformed document
  text defers the hot reload while the current supervisor continues serving the
  live harness; bounded retries may reload after the document becomes valid. It
  must not strand the preserved child at a bare shell by failing during reentry
  or poll editor authority on every idle-watch tick while the text stays invalid.
- Ordinary startup may repair an unterminated leading frontmatter block only
  when its would-be closing fence has exactly one stray ASCII alphanumeric
  prefix, the preceding YAML already forms a valid typed frontmatter mapping,
  and removing that prefix makes the entire document parse. Longer or ambiguous
  prefixes remain fail-closed. The repair is persisted through document
  authority before route-owned resume admission continues, using the same live
  current text startup will parse rather than a stale disk projection.
- A deliberately terminated supervisor is not a crash (`#gh133sigterm`, GH #133
  follow-up). The supervisor's `SIGTERM` handler (and a requested self-kill)
  records a durable `supervisor_intentional_exit` marker in `state.db` naming its
  exact pid and generation, then exits exactly as before (status 143). The
  watchdog never respawns that pid, even in a visible column, and logs
  `controller_supervisor_watchdog_skip reason=intentional_exit`. The marker is
  pid-scoped, so a later generation's crash still restarts; the controller
  replacement path clears the marker its own kill produced before cold-starting
  the successor, and a newly registered supervisor clears any earlier one.
- A controller replacement records its continue intent (a time-bounded
  `controller_replacement_cold_start` marker) before it requests the kill, and a
  supervisor's own exit record never downgrades a fresh replacement marker for
  its pid and generation (`#replacementintent`). A replacement whose controller
  died before the cold start is therefore recovered by the watchdog once the
  grace ends, instead of being read as an operator stop. A promoted
  predecessor's drain waits for in-flight replacement workers
  (`#replacementdrain`), and the dead-pane actor GC leaves alone a binding that
  the crash watchdog would recover (`#gcdefercrash`). A stale-binary `continue`
  replacement withdraws its pending kill once the supervisor has re-exec'd onto
  the installed binary in place (`#replacementwithdraw`). See
  `specs/supervisor.md`.
- With `agent_doc_per_component_convergence` explicitly enabled, the commit
  candidate uses the same exact retained expected→target ownership set as the
  terminal convergence gate. Every owned component must already equal current
  Lazily/editor authority; the candidate is then rebased onto that current cut
  so all unowned operator bytes survive. An owned mismatch blocks commit, and a
  live editor never grants authority to merge an independent disk candidate.
  An empty/no-op ownership journal or drift in an unowned exchange falls back
  to the snapshot-selective commit guard. An already committed response cannot
  authorize absorbing a new unanswered prompt. Failed-launch recovery leaves
  that prompt uncommitted and actionable on repeated preflight attempts.
  Post-commit cleanup cannot use response-heading similarity as answer proof.
  Queue-echo repair requires an exact prompt from a missing committed queue
  proof; a prompt appended while that proof remains visible is preserved.
- A capacity-paused or otherwise detached closeout must reconcile exact pending
  editor operations before treating an on-disk document equal to the cycle base
  as evidence that no concurrent edit occurred. The on-disk bytes remain the
  compare-and-swap expectation, while the replayed operator cut is the semantic
  current document used for response merge, snapshots, and queue reconciliation.
  Replayed operations are cleared only after the reconciled document is written
  successfully (`#pauseddeletetombstone`).
- Compact Exchange derives its semantic input from the same exact base-keyed
  durable editor-op cut before parsing the exchange. It retains the originally
  observed authority bytes as its compare-and-swap base, atomically lands operator
  deletes with the compact rewrite, and consumes the op epoch only after the
  authoritative write and snapshot succeed (`#compactcachedeletetombstone`). A
  transient delivery ACK between operator bursts is not a stable cut: compaction
  waits outside the controller until the newest captured operator op has remained
  unchanged for the complete compact quiescence window, and every newer op resets
  that window.
- Normal preflight publishes typed document observations to one
controller-owned per-document `Computed`; short-lived preflight CLI processes
consume that projection instead of independently rebuilding output state. It
must establish the project-controller actor before its first authoritative
current-document read, so a controller recycle cannot leave a live editor
registration querying a removed socket before startup/model reconciliation can
run. Probe mode remains actorless and side-effect free. Effects advance only
through `repair -> prior-cycle commit -> derived reads -> baseline checkpoint
-> cycle-open`; exhaustive effect identities and the terminal gate make
skipped or newly inserted steps fail closed. Cycle-open remains a durable,
exactly-once identity rather than computed state (`#preflightreactive`).
- Hot-path authority is singular and named consistently across the binary and editor plugins: Lazily current owns the live document, and `state.db` owns intent/lifecycle coordination. Normal execution must not read, write, import, scan, or replay filesystem live-buffer, patch-inbox, queue-journal, queue-delete, continuation, capture, cycle, turn-scope, editor-op, transport-health, hook-session, or cooldown state. Snapshot/CRDT files are permitted only as cold recovery projections after the authority is unavailable; they never vote in a live merge. There is no compatibility fallback to retired sidecars.
- The Zed integration is a supplemental language server for Zed's existing
  `Markdown` language, not a second language that claims `.md`. It activates
  realtime replica behavior only while the live buffer has parseable
  frontmatter with a non-empty `agent_doc_session`; every other Markdown buffer
  is a strict no-op. Controller-to-Zed edits use `workspace/applyEdit`, and a
  delivery is acknowledged only after the matching visible-buffer hash returns
  through `didChange`. The LSP PID is registered with the controller's
  process-exit watcher so a crash cannot strand editor authority.
- The document write state machine is `IntentCaptured -> CanonicalApplied -> ReplicaAccepted -> ReplicaVisible -> DiskProjected -> Committed`. A transition may advance only one edge after its matching proof, duplicate/reordered events are idempotent, endpoint churn is a self-loop, and no recovery command may skip an edge or reconstruct intent from a projection. Queue deletion uses the same rule: the exact Lazily authority shape is the compare-and-swap base, so a missing historical queue item is deletion—not an input to union/replay.
- A stale editor-delivery worker blocks new canonical mutations but not an
  already-satisfied projection (`#staledeliverydurablenoop`). When canonical
  authority already equals the target, delivery is converged, and disk exactly
  equals that same target, closeout accepts a no-write projected receipt and
  continues toward commit. Any missing or differing proof retains the target
  and fails closed without writing disk.
- When a retained operation observes live editor authority that differs from
disk, its recovery owner must request the editor's typed `save_document`
transition and prove that exact authority revision on disk before settlement or
semantic replay continues. A changed revision retries from the new authority;
an unavailable, rejected, or timed-out save remains retained. Recovery never
projects those bytes directly to disk, and operator `session-check` remains a
read-only observer rather than the save-effect owner.
- A controller-derived retained-write settlement is a reactive effect receipt,
not an imperative acknowledgment request. A short-lived observer may join a
`Satisfied` receipt that differs from its turn-local semantic reconstruction
only when the receipt names the same retained intent and its settled hash equals
both the observer's live editor authority and disk observations. A different
intent, missing plane, or mismatched hash must not clear or unblock the local
retained state.
- A controller recycle invalidates relay membership even when an editor still holds a cached client. Forced editor refresh must retire that client and issue a fresh registration. When the replacement controller has neither a live hub nor a retained canonical projection and that registration carries a native-reload frontier, it must bootstrap from an empty canonical frontier and let the retained replica publish its missing CRDT operations; seeding from disk and forcing a full bootstrap would discard the only live copy and wedge the editor behind an ambiguous-generation hold. Existing controller state still wins, and an IDE restart without retained native state still uses the normal canonical bootstrap. Every deferred document write, including an explicitly authorized `--force-disk` projection, retains its full base and target in Lazily state so reconnect restores or component-merges the editor buffer without consulting Git HEAD. Compact Exchange must compose active captured/deferred response lineage before archiving.

- Captured-response recovery must persist both the response and its complete editor-visible baseline in Lazily `ResponseCaptured` state; hashes alone are not replay authority. A partially materialized response may be reconciled only from added nonblank lines whose multiplicities are proven by the captured baseline and response, with at least two matching lines. The reconciled target must pass through document/editor authority, retain any unrelated operator text, and then replay and commit the complete response once. A legacy hash-only capture may consult a byte-hash-matching Git `HEAD` only as a historical baseline anchor and must fortify Lazily state with the recovered content; it must never restore the working tree to `HEAD`. Template-mode raw captures must become explicit exchange patches before strict replay. An open captured cycle may cross a recovered commit boundary only when the captured response is materially present in `HEAD`.
- A recovery-capable operator session-check that applies a proven replay canonicalization must also close its exact binary-owned commit boundary before reporting `OK`. It may commit only the session document through a private index after proving `normalize(HEAD) == authority == disk`, must checkpoint and re-prove the committed bytes, and must recover that settlement across a process restart without consuming unrelated staged or working-tree content.
- A canonical CRDT whose encoded state exceeds both a 1 MiB floor and the visible UTF-8 text by more than eight times plus 64 KiB must retain an automatic fresh-lineage request until every live editor has visibly projected the current delivery. Automatic history compaction never crosses an unacknowledged live-editor delivery, does not require a later editor update once that delivery settles, and records the unsatisfied gate when deferred. The compact frontier is projected back to each live editor so its persisted resume state, subsequent full bootstraps, and later controller-recycle suffixes remain bounded instead of retaining all prior insert/delete history.

> Language-independent specification for the agent-doc interactive document session tool.
> This document captures the exact behavior a port must reproduce.

Individual specs are in `specs/`. This file is the index.

Notable invariants:
- Terminal presentation and tmux session ownership are separate. The binary
  purely resolves document/project/global host policy against typed environment
  observations, and editor plugins consume its receipt. An attached client wins;
  `auto` prefers an available IDE over an external terminal; explicit unavailable
  hosts fail closed. Project `tmux_session` remains the only session-name setting;
  the optional `tmux_sessions` list (GH #17) is an allow-list for multi-session
  projects, not a second name. Every resolved target must be a member, and an
  empty list keeps the single-session behavior.
- Prompt provenance normalization preserves Markdown quote structure: it never
rewrites `> ...` as `❯ > ...`. Marker-only projection envelopes and restored
quoted prompts already adjacent to their response are semantic diagnostics, not
new operator intent; an unanswered quoted tail remains actionable.
- Real-time document authority is operator-first. The editor-visible document
  state owns every operator-authored change, including ordinary non-prompt text,
  queue/backlog edits, frontmatter, comments, whitespace, and partial words.
  `content_ours`, snapshots, and legacy editor-content receipts are merge candidates only; they
  must never authorize a recovery, IPC patch, harness hook, or disk write that
  drops operator-visible text. Snapshots are durable backup/audit state, not
  hot-path authority; legacy snapshot-derived candidates must be narrowed and
  merged into the latest source-of-truth document. The document realtime state
  machine, source-authority projection, editor/disk epochs, owner leases, and
  in-flight apply facts belong to `agent-doc-document-realtime` and are
  lazily-rs-backed state, not turn-local sidecars. The realtime parse state
  projection is also lazily-backed: parse issues surface as realtime editor
  diagnostics and preflight repair is a crash/retry backstop, not the hot-path
  way to make live documents parse. `agent-doc-document` remains the pure
  document model/projection crate. CRDT merge and document realtime
  apply/verify do not commit; the document turn lifecycle owns commit decisions.
  An attached-document write waits for typing quiescence, rebases the agent target
  over the latest canonical CRDT cut, and applies backpressure while any prior
  delivery frontier lacks visible-replica acknowledgement. Repeated intent is
  coalesced to the latest target; an accepted CRDT replacement is never replayed
  through legacy editor IPC, and disk is only a post-acknowledgement projection
  of exact canonical text. Bounded convergence failure retains the change and
  fails closed instead of issuing a competing disk write. An editor-visible
  write acknowledgement is durable authority only when its Lazily event carries
  the full acknowledged content; hashes validate and index that content but
  cannot reconstruct it. A legacy hash-only `already_applied` receipt gets one
  bounded live-buffer publication attempt that upgrades the same patch fact. If
  no editor replica can publish, the full target is retained as a Lazily
  deferred-write intent and the cycle fails promptly without file IPC or a disk
  projection. An empty delivery target set is never convergence for an
  editor-owned write.
  Editor-selected tmux focus is likewise latest-wins per project. A stale or
  pruned actor projection cannot hide a still-running document owner when the
  latest open session log, live pane, and exact process-tree document binding
  all agree; incomplete or cross-document evidence fails closed without
  repairing the document or ownership projections.
  The normal preflight boundary also recognizes the narrowly provable legacy
  corruption shape where a structurally complete session document is repeated
  byte-for-byte two (or a power-of-two number of) times. It automatically
  coalesces that replay to one projection through the same CRDT/ACK path before
  parsing, diffing, or dispatch; the agent must never run a document-repair
  workflow for this transport artifact. Non-identical content is never eligible.
  Editor delivery must target the `editor_id` from the newest live reliable-sync
  registration when an owner lease exists; untargeted file-IPC fallback is not
  delivery proof for an editor-owned document.
  See
  [Real-Time Workflow Authority](specs/14-realtime-workflow.md)
  and [Turn Lifecycle Authority](specs/15-turn-lifecycle.md).
  Invariant: parse state projection drives editor diagnostics; preflight repair
  is not the live parse hot path.
- Admission compares the recorded merge baseline, the registered live editor authority, and the durable disk file in the **durable** domain: transient agent-doc markers (`<!-- agent:boundary:… -->`, the ` (HEAD)` heading suffix, `❯ 🚧`, per-cycle guard comments, managed pipeline frontmatter) are normalized away before the planes are compared, so agent-doc's own transport state can never manufacture a third revision and refuse admission permanently. Three durably distinct revisions are still resolvable when the live buffer preserves every durable disk line in order — the blocked-commit shape (`NativeSaveRequired` with `disk_projection_ready=false`, disk keeping the older commit, operator still typing) proceeds on the authority and adopts nothing. Before a genuine split merge, an exact-base captured editor-op epoch is replayed to the initial authority cut. A disk-only queue row that appears in an intermediate replay revision and disappears from that final operator cut is a superseded save of the same row, not an independent addition; admission removes only the lineage-proven excess occurrence from the disk branch while preserving every disk row without that proof. The initial operator cut and durable op epoch remain the proof across the bounded compare-and-swap retry even after the first projection advances authority. The merge baseline is content-addressed, so a commit that never landed leaves it at the last durably-projected revision: `checkpoint_document_baseline` compares the new content hash against the projected baseline and, when they match, logs `document_baseline_checkpoint_unchanged` instead of appending a fact or emitting a filesystem content copy. Re-asserting the same baseline is not a new revision, so a blocked commit and its retries cannot walk the generation forward and make the ledger read as though the baseline had advanced past the commit. Only an unchanged durable authority branch authorizes fast-forwarding a proven newer durable save. `agent_doc_document::admission_divergence` owns the classification for both preflight and `session-check`; every non-trivial observation logs `admission_divergence … reason=<token> action=<token>`, and refusals print both the raw and durable hashes. See [Real-Time Workflow Authority](specs/14-realtime-workflow.md).
- `agent-doc commit` remains snapshot-selective. It may repair narrowly-classified missed agent-owned drift before staging, but it must not absorb free-form user prompts from the working tree. Already-committed historical response drift may repair the snapshot only when the working tree matches `HEAD` modulo transient boundary / `(HEAD)` markers. On an already-current no-op closeout, a stale agent-owned exchange collapse (committed `### Re:` heading missing from the working exchange, with only committed exchange lines remaining and a duplicated queue-prompt blockquote proving the missing response id) is restored from `HEAD`; independent local queue/backlog/prompt drift outside `agent:exchange` remains visible and uncommitted.
- When the snapshot already matches `HEAD`, post-commit local drift classification must reuse the canonical prompt-bearing diff classifier. Queue/backlog directive edits that preflight would surface as prompt targets are `user_follow_up` drift, not anomalous `working_tree_edits`; inline content corrections remain working-tree edits.
- A same-marker, same-attribute nonempty-to-empty transition of an `agent:done archive="..."` body is a binary-owned staging projection only when the exact removed bytes are proven as the complete append to the configured archive target. That proven publication is not prompt-bearing drift and must not start a new response cycle. - An operator re-arm beats snapshot-struck dominance (`#unstrikelost`). A head the operator typed again as a fresh line is a re-arm too (`#retypestruck`). The text the active epoch's operator ops inserted is base-independent evidence: it needs no replay base, so it holds when the epoch was captured against a text other than the committed snapshot (an earlier operator edit or an agent projection advanced the base), which is exactly when the exact-base replay above has nothing to offer. A whole typed line whose queue identity the snapshot holds struck stays live, whether the operator deleted the old struck row first or appended the new line below it, because a stale editor flush is never recorded as operator keystrokes. Only the active epoch counts: it opens after the last non-operator projection, so its keystrokes postdate every strike the agent projected, while a retained checkpoint may hold the keystrokes that typed a head the agent has since answered. Typed strikethrough and partial lines are not evidence. - The same operator re-arm evidence governs the per-item queue lifecycle merge (`#unstrikelost`). When a closeout write (a response-writing cycle's tracked-work/queue mutation, a deferred-write composition, a retained controller delivery, or a queue-maintenance rebase) is merged over the operator's editor cut, the `Live < Struck` join normally lets the struck side win so a stale buffer cannot resurrect a retired head. That join yields to the live side only when (a) the merge base holds the item struck, (b) the struck side still carries that same instruction (it did not re-answer a revised head), and (c) the operator's own captured editor ops, replayed from that merge base, leave the item live. - Unreadable re-arm evidence is not absent evidence (`#unstrikelost`, unreadable evidence). Reading the operator's editor-op epoch can fail: the controller this preflight launched died before the read (its socket file remains and refuses connections), it is wedged past the read deadline, or `state.db` cannot be read. Queue maintenance must not map that failure to "no evidence", because no evidence re-strikes every contested head. A contested head is a live queue head whose identity the committed snapshot holds struck; only those heads' outcome depends on the evidence. When there are none, maintenance does not read the evidence at all. When there are some, it retries the read a bounded number of times (`AGENT_DOC_QUEUE_AUTHORITY_ATTEMPTS`, default 3, re-ensuring the controller between attempts). If every attempt fails, it logs `queue_rearm_evidence_unavailable … admission=refused` and refuses with `QueueAuthorityUnavailable`. Preflight then refuses admission and persists nothing, so the contested head is neither re-struck nor resurrected. The queue-maintenance CAS rebase follows the same rule: when its merge base holds a struck queue item, unreadable evidence aborts the rebase instead of applying the `Live < Struck` join. The document write path follows the same rule at both of its re-arm evidence reads: rebasing an agent candidate over the live editor cut, and composing a new deferred write target over a retained one. When the merge base holds a struck queue item, the evidence is read up to 3 times (`OPERATOR_REARM_EVIDENCE_ATTEMPTS`, each read reconnecting to or relaunching the controller). If every read fails, the write path logs `<source>_rearm_evidence_unavailable … outcome=refused` and returns an error before it projects anything, and a refused composition leaves the prior retained intent unchanged. A base with no struck queue item cannot be re-armed, so its evidence is not read. Evidence left behind by strikes made before that rule, or by hand, is retired by the one-time, dry-run-first `agent-doc queue repair-stale-completion` (`#stalecompletionrepair`): a cell or receipt whose work has no live row in any queue and no active attempt, plus a live-row cell no attempt or receipt tracks only when named by `--key`. Fenced component markers are content for every marker line scanner (`#fencedmarkerscan`, one shared `overlay::ComponentMarkerScan`). A queue row's overlay node id is its work identity, never the attempt projection's owner tag (`#queuerowworkidentity`): a claimed row, its lifecycle re-projections, and its struck copy are one node. A marker-only editor difference is not an operator edit, and a stale projection-carrying editor copy never resurrects a struck row. Deletion of live work is authoritative cancellation, while deletion of a durably terminal struck row is presentation-only cleanup. A canonical local operator answer (`[#subagent-operator-request-<id>]: <answer>`) keys by its reserved request id and receives the same lifecycle projection; an identical shape quoted inside balanced inline code is evidence only and cannot retarget, truncate, or rename the surrounding queue prompt.

After the write, repair must prove both the realtime authority and the disk projection are byte-identical to the intended repaired image before it may save a snapshot, commit, or report success. A concurrent/stale projection mismatch fails closed and must never be merged back as operator content, because doing so can resurrect fragmented response bodies and duplicate boundaries. If the CAS target was durably retained but the editor owner has zero registered replicas, explicit repair may use the audited force-disk authority to project only that exact retained target; ordinary writes remain deferred, and repair must preserve force-disk reconnect lineage after exact disk proof so a stale editor buffer cannot overwrite the repair when it returns.
- If a repair crosses a detached write boundary and an editor registers with the exact pre-repair authority after the repaired bytes reach disk, settlement must wait a bounded interval for that editor to acknowledge the target. If the interval expires, the original expected-to-target compare-and-swap lineage must remain durably resumable; the already-applied repair must not be reported as an unretained terminal failure. Any different/newer editor cut remains a concurrent-authority mismatch and fails closed.
- Multi-stage repair must settle every superseded deferred target after exact authority/disk proof and retain at most the newest reconnect target, using the original editor cut as its content-bearing merge base. Settling the newest delivery must not reveal an older intermediate marker, boundary, or fragmented response image.
- When a newer response target already equals live CP authority, it supersedes any older deferred response target instead of merging that stale assistant tail back into the document. Reconnect lineage rebases on the exact superseded target: an unchanged failed-ACK editor cut receives the newer target directly, while later operator prompt nodes are preserved through semantic response-tail reconciliation with one terminal boundary.
- When recovery resumes a newer durable capture while the deferred journal still points at a prior-cycle reconnect target, that stale target must not block or overwrite the newer capture. If rebasing the retained target over exact current authority cannot materialize the newer captured response, recovery skips that stale rebase and CAS-replays only the newer response cell over the same authority cut; it clears the deferred lineage only after editor/canonical/disk convergence proves the resulting bytes.
- Every deferred-write composition and settled-operator rebase must canonicalize boundary control state from the newest target branch: outside fenced examples the result retains exactly that branch's singleton `agent:boundary` marker at exchange end. A forced editor refresh is not a reconnect merge or delivery operation: it captures the exact visible editor bytes, validates them, and register/swaps the replacement replica from that same baseline under a generation fence. It never preinstalls or saves a deferred target. Retained mutations replay afterward through the ordered document-cell/CRDT path, so a refresh cannot overwrite a prompt or resurrect deleted queue state.
- Before the generic integrity gate, recovery may collapse a replica-refresh suffix only when the retained prefix is already structurally sound, the appended bytes are an exact suffix of that prefix beginning at any UTF-8 character boundary (including a mid-line or mid-token cut), and the suffix contains agent-doc component scaffolding. This repair removes one duplicated partial component tail without interpreting repeated operator prose as binary-owned state; non-exact or prose-only tails fail closed.
- Session-check publishes that proof-bearing replica-refresh repair through an exact-current authority compare-and-swap. It must not route the repaired projection through the ordinary semantic component merge against the structurally invalid editor generation, because that merge can recreate the duplicate tail it is repairing.
- Terminal `session-check` success additionally requires byte-for-byte equality between current canonical document authority and disk, except for an operator-edit lead (`#operatorleadpendingsave`): with no open cycle, retained capture, retained document write, or unlanded tracked-work mutation, an authority that holds uncommitted content while disk equals a committed plane (baseline or `HEAD`) or is preserved line-for-line by the authority is reported as `pending-save` (plus verbatim pending steering), never INTERRUPTED. A disk ahead of or conflicting with the authority, an authority equal to a committed plane, or no committed plane at all stays fail-closed. The operator-facing command is status-only: a mismatch fails closed and records both hashes without requesting recovery, replaying a capture, settling a retained write, or mutating document content. Finalize/write/preflight and the supervisor own those transitions. Its sole self-heal is metadata-only repair of an already-committed historical snapshot whose exact `HEAD` content is proven; substantive post-commit operator edits are never eligible.
- An open `preflight_started` cycle whose exact registered owner pane has a fresh turn-active lease is reported as `[session-check] IN PROGRESS`, not as abandoned-closeout evidence (`#sessioncheckliveturn`). The command remains nonzero/fail-closed until a terminal boundary exists, but its guidance forbids concurrent recovery or owner restart and it does not raise the dogfood actionable-defect prompt. Liveness must correlate the document registry owner with that pane's lease; a sibling document's project-wide marker, expired lease, or unreadable ownership state is not proof.
- Operator steering found after a `committed` cycle is a typed `steering pending` outcome, not an interruption (`#steerinterruptexit`): `session-check` prints `[session-check] steering pending: …` with every settled item verbatim and its `dispatch`, exits `0` (`2` under `--codex-final-gate`), and the embedded `respond` / `finalize` / `write --commit` closeout succeeds. Genuine integrity failures and blocking retained writes still report `INTERRUPTED`. In a Codex session the active-harness-session drift guard reports the same outcome only for editor-op-proven operator steering (`#codexsteerinterrupt`); unproven drift, including console output replayed into the document, stays `INTERRUPTED`. A typed `UnansweredEditPending` refusal reached after Stop has committed the response ends the hook successfully (`#stopnextedit`): the newer typed-component edit remains live and uncommitted for the next cycle instead of being mislabeled as an unfinished closeout. See `specs/07-closeout-commands.md`.
- Mid-turn steering observes the same authoritative document as turn admission (`#steering-live-authority`, GH #173). With a live editor, every PostToolUse observation compares the watermark against the controller-owned CRDT text; disk bytes, disk mtime, and a later native save may not synthesize a removal/re-addition pair. Because the relay currently exposes content identity but not editor edit time, live edits settle by per-item stability rather than stale disk mtime. An explicit-send receipt identifies the authoritative content hash it sent, so it cannot flush a later unsaved edit; detached documents may retain the file-stat fast path and legacy timestamp coverage.
- When `session-check` collides with a foreground closeout owner for the same durable capture, it must subscribe to that exact cycle's controller projection and continue as soon as the cycle becomes terminal or the request-scoped owner guard releases. A long-lived supervisor PID is not proof that an individual closeout request is still active. Recovery retries once after owner release, controller reconnect, or a bounded 30-second crashed-owner fallback; the foreground lease is a safety stopgap, never the normal wait mechanism. A timer may schedule a wake at the lease boundary, but it may only observe the resulting clock edge into controller-owned Lazily state; the shared Computed closeout gate, derived from cycle, owner, and observed-clock sources, owns the blocking/released decision.
- Connected and managed clients must not run a second agent-invoked session check after strict finalize succeeds (`#sessioncheckturnreactive`). `agent_doc_finalize` returns the terminal binary-owned closeout report plus queue-continuation fields; managed orchestration consumes the same strict finalize boundary directly. The next turn's admit/preflight resolves the current document and evaluates the open-cycle, prompt-only-tail, and bypassed-response guards before opening new work. A `PreflightStarted` fact for cycle N+1 clears cycle N's closeout owner in the live projection immediately, so a superseded diagnostic cannot retain a lease. The explicit `session-check` command remains available for direct-exec harness distrust checks and debugging.
- Response placement, answered queue-head removal, backlog/review/done mutations, snapshot publication, and commit form one final-response transaction. A validation or convergence failure leaves none of those effects authoritative. `AlreadyApplied` can advance that transaction only when the visible document contains the exact complete final payload expected by the same transaction; a response prefix, partial checkpoint, prior-cycle body, or heading-only match is insufficient.
- Every appended response must cross a commit boundary in the document turn lifecycle unless the user explicitly asks to leave it uncommitted. The normal happy path is `agent-doc finalize <file>`; the documented repair path for an already-present prompt is `agent-doc write --commit <file>`. CRDT merge/realtime convergence may provide the verified document state for closeout, but it must not run the commit as a side effect.
- Strict `write --commit` with empty stdin may only commit when it first recovers an agent-doc-owned visible response or applies explicit backlog/review/icebox mutations. A live editor/CRDT projection is harness-neutral authority for this recovery: even when cycle state is already `Committed` and the snapshot/`HEAD` image is compacted or stale, a response delta proven in the editor buffer must be adopted into the snapshot and carried through the normal commit/session-check boundary exactly once. The binary must never recommend restoring the editor buffer to `HEAD` for that state. Empty stdin with no recoverable response and no tracked-work mutation must fail before commit so live prompt drift remains unresolved for the next cycle.
- Once a closeout cycle reaches `Committed`, a delayed editor intent for that cycle is rejected by its state-ledger phase and generation fence. No alternate delivery transport exists. Active delivery timeout retains the same intent in `state.db`, performs no direct write for an attached document, and resumes from the recorded phase. Terminal lifecycle updates are idempotent.
- Explicit `--force-disk` closeout is the operator-controlled direct-write escape hatch for stale/wedged editor listeners. When used with strict `write --commit` / `finalize`, the force flag must apply to the whole binary-owned closeout path: response placement, pending-maintenance reap, queue consumption, done-id marking, and free-text queue strike. Ordinary preflight/route maintenance still fails closed under active listeners unless the caller explicitly selected this force-disk recovery path, and force-disk maintenance writes must remain attributable in `ops.log`. A live editor buffer that diverges from disk because the operator has unsaved edits is a **valid state, not a wedge** (`#unsaved-buffer-divergence-valid`): the `retry after typing stops` / `visible_write_deferred_live_buffer_changed` / `live_prompt_drift` deferral is the guard working as designed. Harnesses must not chain `make install` + `agent-doc admin recycle` + `--force-disk` to force a closeout through it, and must escalate to the stale-binary recycle path only when the drift is actually traced to a `stale_install` / recycle-yield projection; once the response already reached `committed` in `HEAD` with `session-check` OK, state-only leftovers left in the working tree reconcile on save and must not be force-disked. See [runbooks/commit.md](runbooks/commit.md) `#unsaved-buffer-divergence-valid`.
- Every `agent:exchange` write emits `exchange_write_diagnostic` with the transaction id, writer identity, named intent, expected/current Lazily generations, affected semantic nodes, before/after canonical hashes, rebase/conflict result, and receipt phases. All template, queue, compact, normalization, and repair mutations use node/component-scoped socket intents; `fullContent`, file IPC, degraded attached-editor disk fallback, and compatibility payloads do not exist. The plugin validates target-node preconditions immediately before apply, and the state machine advances only from typed Lazily accepted/visible receipts. Duplicate-prompt repair is response-block aware and operates on the verified canonical result before disk projection; it never adopts post-preflight operator scratch text into an agent-owned snapshot candidate.
- `agent-doc route` defaults to a bounded 500ms quiescence gate before it inserts a missing session id, scrubs duplicate prompt comments, or submits a managed/dispatch-only reopen. The route gate must observe both filesystem mtime idle and the shared editor typing indicator idle for the debounce window; if either remains active through the bounded wait, route fails closed before document mutation or pane input. Editor integrations may pass `--debounce 0` only after they have saved the focused document themselves; the JetBrains `Run Agent Doc` path uses that focused-save fast path so dispatch is not delayed by a second debounce.
- Direct-pane route submit acceptance must not treat a single empty pane capture as proof that the harness received the prompt. Empty captures must remain stable before acceptance, visible drafted triggers still get a bounded submit-key retry, and Codex accepted-without-dispatch-start proof must attempt one late Enter retry when the same routed prompt is visibly sitting in the input. Once the full trigger transport succeeds, absence of dispatch-start proof never authorizes another full-payload send; post-send recovery may send only a bare submit key while the exact routed draft remains visibly present.
- When `route --dispatch-only` queues a prompt-bearing editor rerun behind a busy actor in `agent:run`, the rerun must be inserted **ahead of queued active-loop items** (priority preempt, `#jb-run-preempt-autoloop-priority`): a manual `Run Agent Doc` preempts the loop instead of landing at the tail. Route-owned queue writes must never add `auto`; when they touch a legacy `agent:run auto` tag they strip `auto` while preserving other attributes. A bare slash-command line such as `/clear` in an exchange diff is prompt-bearing even without a `❯` prefix, and route must short-circuit it into `agent:run` for the idle supervisor instead of submitting it as a normal agent-doc turn. The priority insert lands after any leading queue directive (preset / start fence) and must not supersede a lone active-loop prompt, so the queued item is preserved (manual prompt first, then the queued item) rather than replaced. If an explicit editor run finds no new prompt-bearing diff but the document already has a startable inactive queue head (`queue_active: true`, a start fence, or legacy `auto`), route must promote that head to `queue_active: true`, sync the snapshot, and let the supervisor idle-queue watch drain it after the busy pane returns to idle. The idle-queue watch must treat the hook-owned turn-active marker as authoritative over renderer prompt heuristics: queued work, slash-command heads, and automatic context-reset clears may run only after the full turn reaches the Stop/idle boundary. Queued `/clear` / `/new` heads and context reset clears must use the supervisor's clear submit path, not generic prompt dispatch, so they are recovery controls and remain gate-exempt while still submitting Enter to the owner pane. A non-interrupting `session clear` on a busy active auto-queue must publish exactly one deferred `QueueContextClearDeferred` projection for the supervisor's next proven idle boundary; repeat clears while that deferred projection is pending must report "already deferred" and must not refresh the projection or inject another `/clear` into the active turn. After the idle-watch submits the deferred clear, it promotes the projection to `QueueContextClearStarted` until the cleared pane settles. A synthetic active queue head that consists only of a slash command, ignoring surrounding whitespace, is command-only for preflight, plan, and direct run: it must not open `preflight_started`, must not become prompt targets/repo actions, and must stay live in `agent:run` for supervisor idle submission.
- A managed owned pane must not remain indefinitely split between authoritative ready state and stale busy renderer state. When actor state, supervisor actor state, and controller lease are all `ready` but the live pane probe still reports `alive-busy`/`prompt_ready=false` from a recoverable stale queued-draft cue, route-owned completion and the idle-queue watch debounce that ready/busy conflict for the same four-poll window used by stale-busy idle repair, emit `owned_pane_ready_busy_conflict`, and then let queued work proceed. Genuine active-turn, permission, hook-review, shell-search, help, and clean-exit blockers remain protected. `agent-doc session status` must make the ready/busy conflict explicit and prefer bounded reconcile/clear guidance over pane restart.
- A plain `route --dispatch-only --plain-trigger` reopen (the editor `Run Agent Doc` contract) submits the bare `agent-doc <FILE>` trigger to a live `ready`, `busy`, or `waiting_input` authoritative actor only after any prior open cycle reaches a terminal closeout. An unresolved response or retained component write blocks dispatch; route performs the existing controller-projected closeout drain and fails closed if it cannot settle. After admission, the trigger remains transport-only: it must not derive prompt-bearing queue work from the document diff, mutate `agent:run`, or wait for pane-capture acceptance or dispatch-start proof. This is the single replacement/steering boundary: an interrupted turn whose actor projection still reads busy receives the same plain trigger as a fresh run, and a Run click made with selected text or a live document diff follows the same route instead of a separate supervisor-steering RPC. Legacy `selected_text` / `steering_id` payload fields are accepted only as compatibility metadata and are normalized onto this plain-trigger route. Protected interactive substates and non-turn surfaces such as the Claude artifact picker still fail closed, and a still-booting `starting` pane retains the bounded readiness guard.
- Once route admission classifies `managed_reopen` or `dispatch_only_reopen` as an explicit operator reopen, a stale same-generation in-flight dispatch receipt must not coalesce that controller dispatch. Automatic/non-operator re-dispatches retain durable in-flight backpressure, and the JetBrains action layer may still coalesce duplicate clicks while the same bounded `editor_route` request is alive; those are separate dedupe boundaries.
- Template write paths must fail closed when a response contains patch/replace markers outside code blocks but no closed patch blocks parse. Such malformed patchbacks must log `template_patchback_parse_shape` and `template_patchback_malformed_rejected` with response hash, marker count, patch count, exchange patch count, unmatched length, and source before returning an error; they must never be synthesized into `agent:exchange` as raw unmatched content. Strict template, stream, and IPC closeout routes share the same marker and response-heading validation before durable response capture, even when replacing a pending response. Binary-owned replay may transiently normalize the retired `agent:patch:*` wrapper only for an already-durable, complete, marker-only exchange response; it must not mutate the stored capture or session document during migration. Socket IPC attempts must also log `ipc_socket_attempt` plus lazily visible-write receipt hashes/lengths so corruption reports can distinguish malformed payload parsing, editor projection drift, and stale fallback writers.
- When an `agent-doc` turn also includes ordinary repo `commit + push`, manual git commits must exclude the active session document. Agents may commit the non-session repo files first, but the session document still closes through `agent-doc finalize <file>` / `write --commit <file>`, and the push happens after that binary-owned closeout commit lands.
- Narrowed/path-scoped manual repo commits must fail closed on staging drift. The agent must resolve the exact intended non-session path set first, run stage commands only for that set, stop immediately if any stage step fails, prove the staged diff still matches the intended set before `git commit`, and use an explicit pathspec commit or equivalent isolated-index strategy so unrelated pre-staged entries cannot leak into the commit.
- `session-check` must warn on likely partial manual staging closeouts: if the latest repo commit (or dirty submodule repo surfaced by the owning worktree) changes relevant source/test paths and tracked dirty or staged companion changes remain with overlapping changed string literals, the closeout is suspect because local verification may have run against the dirty worktree while CI sees only the committed tree.
- `agent-doc finalize <file>` is the binary-owned happy path for session responses: it must fail before mutating non-git documents, run the normal write pipeline, invoke commit, and refuse success unless the cycle closes in `committed`. If the active prompt is a synthesized active `agent:run` head and the captured response heading targets that queue item or its `#id`, finalize consumes the queue head even when the visible document had no queue-head diff; unrelated baseline prompts must not consume it.
- A semantic response-cell closeout must not commit ahead of visible convergence. `ResponseCellAdded` proves durable idempotence only; finalize must apply normal typing/ACK backpressure, materialize the acknowledged canonical cut to disk even when an attached authority currently has zero live relay members, and only then snapshot and commit. Materialization proof is semantic across transient ` (HEAD)` and boundary annotations. Before adding the latest complete response, the operation anchors at the last unchanged committed response in `HEAD`, removes only later uncommitted assistant-response nodes, preserves all operator prompts, and emits one terminal boundary; interrupted partial/full variants must not accumulate or require repair. The committed blob and working-tree projection must therefore begin closeout byte-identical instead of relying on later repair.
- Inter-queue-item dispatch is convergence-gated (`#fullboundary`): item N+1 must not dispatch until item N proves a quiescent close — cycle `committed`, the retained editor-delivery settlement no longer blocks a new cycle, this document's editor-IPC inflight count drained to 0, and the authoritative actor idle (dispatch-ready prompt, no active turn). The delivery proof is purpose-scoped Lazily state, not whole-document equality with Git `HEAD`: queue control and newly appended operator queue rows are legitimate next-cycle input and must not retroactively make a completed response look unconverged. A genuinely `Unsettled` retained write blocks; `NoRetainedIntent`, `Satisfied`, and the new-cycle fail-open `Unobserved` verdicts do not. The decision core is the pure `convergence_gate::convergence_gate_decision(ConvergenceFacts)` returning `Dispatch` (all four proofs), `Defer { unmet }` (not yet quiescent, within the bounded timeout), or `Blocked { unmet }` (bounded timeout exceeded while unconverged). A blocked boundary is an ERROR condition and persists a replayable operation-playback artifact (`convergence_playback::ConvergencePlayback`) to `.agent-doc/playback/<doc-hash>/<cycle-id>.json` capturing the ordered IPC attempt sequence (patch_id/transport/receipt/inflight), snapshot/baseline/HEAD hashes, candidate vs `content_ours` lengths/hashes, cycle/run/actor/supervisor identity, and the closeout state-machine transitions, so a recovering agent can root-cause the wedge without guessing. The live supervisor inter-item dispatch (idle-queue watch / drain) is the consumer of this gate and composes with the drain-owner lease (`#kp5z`, dispatch ownership) and `queue_continuation` drainability.
- A preflight mutation wait must not refuse a turn over replica delivery (`#preflightsteeradmit`). A `delivery_pending` observation carries the authoritative current text, so preflight admits on it immediately (with one best-effort urgent drain) and later operator edits reach the turn through mid-turn steering; never disk, never `--force-disk`. Only states with no authoritative text (`missing_replica`, `current_pending`, `authority_unavailable`) wait and fail closed, re-observing Lazily current authority exactly once at the defer boundary so already-visible convergence succeeds.
- The `live_prompt_drift` editor-convergence recovery is component-merge-aware (`#qpcwcmerge`). After the editor applies the convergence patches, the recovered editor buffer is accepted even when it is NOT byte-identical to `content_ours`, provided every divergence lives strictly INSIDE a component OTHER than the agent's response component (`exchange`) — the editor's live queue/backlog/review/status and any plugin-defined component, while the response component, the document's non-component regions (preamble/frontmatter/interstitial), and the component structure all match (normalized). In that case the editor buffer is the correct merged state (the operator's live queue + same-cycle auto-strikes + the response), so committing it makes `HEAD` equal the editor buffer and eliminates the recurring `#pcwc` post-commit worktree drift instead of falling back to the `content_ours` disk write that drops the editor's components (editor-wins, `#queue-user-edit-overwrite`). The discriminator is AST-structure-driven and component-name-agnostic (it keys off `component::parse`, never an allowlist), so a plugin that defines a new component is reconciled identically to the built-in queue. Conservative: any out-of-response divergence, a structural component add/remove, or a parse failure fails closed to the existing block/`content_ours` path.
- `preflight` IPC-truncation recovery may ask the active editor to flush its visible buffer through typed `save_document`, but only through the matching PID-scoped editor socket and with a Lazily receipt. JetBrains and VS Code implement the same intent, record editor-surface outcomes through `agent_doc_record_editor_surface_event`, and never use a file signal or editor-local log formatter. If save proof is absent or the published buffer no longer preserves the committed exchange, recovery fails closed with the operator-visible Lazily cut authoritative.
- Component patch and recovery writes may target an editor only when its live Lazily registration, editor identity, PID, and PID-scoped endpoint agree. With no live registration the document is detached and may project to disk; disagreement fails closed before payload delivery, leaving captured intent retryable.
- The editor-sync barrier observes the retained Lazily projection and live replica frontier. Timeout is a bounded absence of convergence; it never sends a republish, re-registration, save, or ACK request to the editor.
- A durable retained transition is one typed state machine over durable Base → Target facts, current editor/CRDT delivery, and controller generation. Its exhaustive states are no projection, idle, awaiting controller, awaiting delivery, awaiting live editor, awaiting convergence, apply target, target visible, reconcile materialized capture, and typed conflict. One derived optional Effect observes the current delivery projection, compare-and-projects Target, or resumes closeout; waiting and conflict states have no effect. The controller listener must be bound before restored liveness publishes missing-replica targets so the resulting full projection cannot be lost during controller startup. This is reactive Source propagation, not an editor request/ACK protocol.
- When preflight/current-document resolution observes live editor membership but the relay model is missing, it schedules the controller-owned canonical projection and returns the typed retained/pending observation. It never asks the editor to publish its current buffer, never seeds authority from disk while attached, and never blocks the foreground command behind an editor recovery barrier.
- The `#yzer` reconnect-reread is editor-agnostic and lives in the binary FFI (`agent_doc_reconnect_buffer_decision`, owning the disk==HEAD vs buffer==prior-commit staleness decision); both the JetBrains plugin (`reconcileStaleBuffersOnReconnect`) and the VS Code plugin (`PatchWatcher.reconcileStaleBuffersOnReconnect`, run on activation) are thin callers that only re-read disk into a buffer the FFI proves stale, so genuine unsynced user edits are never clobbered (editor wins, `#editorbufwin`). The two plugins must stay behavior-matched through that shared FFI.
- Operator-authored queue prompt order is position-locked by stable identity, not by mutating visible prompt text. During preflight, queue prompts absent from the snapshot and not appended by backlog sync form an operator-authored identity set; priority and auto-DAG queue sorting anchors those identities like operator pins while leaving the line marker-free, including id-backed `do [#id]` heads. Binary-synced backlog mirrors still use append-stable ordering, explicit operator pins still anchor normally, and dependency edges may still outrank an anchor when holding the slot would violate the edge (`#qauthorderpin`).
- A claimed queue-row edit is steering, never implicit unregistration (`#queue-mutation-steering`). Queue alignment pairs unchanged/moved identities first (a same-id prose rewrite is the same row), then inside each Myers replace hunk pairs rows whose text contains the other's or whose character-diff ratio is at least 0.5; two different tracked ids never pair, and a row that gains or loses its id pairs only by containment. The claim follows such an edit with the same owner/generation, and mid-turn steering emits `change=edited dispatch=forward_to_owner previous=... verbatim=...`. There is no positional fallback (`#krwr`): a claimed row deleted while a different row is added in its slot, even in an equal-count hunk, is removal plus new work, so the owner gets `cancel_claimed` and the new row is unclaimed; additions in a different hunk are fresh work too.
- Forwarding to a claimed owner has a generation-fenced unavailable-worker exit (`#staleownersteer`): `forward_to_owner` is not a lossy one-way route. A successful harness handoff keeps the claim and generation unchanged. When the harness explicitly reports that the exact worker is unavailable or exited, the coordinator preserves the operator's verbatim answer/edit in the queue and executes the rendered `agent-doc queue release <FILE> --item <ITEM> --generation <N> --requeue` command. That transition abandons only generation `N`, leaves the edited row dispatchable, and lets normal scheduling bind a replacement under a fresh generation. The coordinator must not drop the answer, report it forwarded, or keep routing only to the unreachable owner. Agent-doc cannot observe an external harness worker lifecycle directly, so the harness handoff result is the one-shot boundary evidence; claim state and the generation-fenced release remain the durable policy/effect boundary.
- Progressive edits to a newly-added id-less queue line must converge to the live operator wording, not accumulate each intermediate spelling as a separate queue item. When a stale merge base predates the text-derived identities, the live/editor free-text run is authoritative only within the same gap between shared durable anchors, including the subset case where the retained agent cut contains old + current spellings while the editor has deleted old and retained current; explicit `#id` items and id-less additions in different anchor gaps remain independent. The causally gated raced-projection repair also recognizes a non-prefix rewrite sequence only when its final spelling contains every earlier draft, plus a two-row fresh residue only when at least eight normalized words form a strict prefix pair; this converges high-evidence revisions without collapsing short, plausibly independent prompts. The recursive CRDT merge, default document-cell merge, and raced-projection repair share this operator-authoritative queue policy.
- Free-text queue heads are struck when answered, regardless of position (`#ftstrike`). The normal leading-head consume only strikes a contiguous leading run and stops at an id-backed head, so a free-text report sitting BEHIND an unfinished `do [#id]` head was never struck even after the response addressed it. On closeout, after the leading-head consume, a position-independent pass (`strike_answered_free_text_queue_heads`) strikes every non-struck free-text head whose text the committed response answers — matched conservatively by requiring the head text (priority-markers stripped, normalized to lowercase alphanumeric words) to appear inside the response's `>` quoted-prompt blockquote region, with a minimum four-significant-word guard. A head merely mentioned in prose (not quoted as a prompt) is NOT struck, so an unaddressed operator report is never silently dropped. A nested child that begins with `Include #subagent:` is release context, not a sub-prompt the parent echo answers (`#nestedechostrike`): echoing the parent together with those include lines does not strike the row while any named include still has a live unstruck queue row whose attempt owner is `subagent:<label>` (for example `🚧 [#subagent:nestedlineage#1] …`). When every named include is done — its row struck or absent — that same echo strikes the parent and its include lines together. A quoted head followed by a deferral (a `**Deferred…**` lead or deferral phrasing in the quote's paragraph, `#deferstrike`) is NOT struck; the deferral veto is anchored to that head's labeled echo (or a four-word quoted-head match), never an unrelated response block that happens to contain a short head word. A worker claim (`#queueclaim`) does not hold an answered head back (`#claimstrike`): an echoed, undeferred claimed head is struck and its claim released in the same closeout, so the strike set equals the session-check `#qheadresidue` set. If the supervisor abandons a cycle before its response is captured but closeout later materializes that exact same-cycle response, the capture retains its answered-head strike authority until terminal closeout proof or a later admission clears it (`#ftstrike-abandoned-closeout`, GH #313); closeout must not commit the answer while leaving the echoed head runnable. The pass is also conservative about in-flight operator edits (`#qstrikeexplain`): a free-text head is struck only when it was already present in the stable pre-turn baseline (the preflight baseline), or when durable cycle state proves preflight selected that exact head and the current response contains its exact labeled echo plus answer prose. A head that first appeared in the live buffer during this turn — a line the operator is still typing — is never same-cycle struck merely because it has a visible marker or fuzzy-matches a quote; it defers to the cycle that actually answers it (editor-wins, consistent with `#queue-user-edit-overwrite`). A missing baseline (rare; preflight writes it each cycle) skips the gate, preserving legacy strike behavior. The pass runs independent of the leading-head `queue_consumption_allowed` decision, strikes the document and snapshot in sync, and is best-effort (a missed strike never fails an otherwise-clean closeout). - The preflight `#qheadresidue` catch-up strike counts only echoes written after the head last entered the queue (`#qheadresiduescope`). The exchange keeps every earlier answer, so an operator who types an already-answered report again (a repeated bug report), or un-strikes an answered head, would otherwise have the new copy struck by the old echo without any cycle answering it. The entry point comes from git history: the walk reads the document's commits newest first while the head's identity (priority markers stripped, whitespace-collapsed lowercase prose, any live `Prompt` row) is live in the queue, and stops at the first commit in which it is not (struck, deleted, or not yet typed). That commit's exchange is the anchor, and only the exchange text after it (`queue_response::exchange_text_newer_than`: the lines between the longest common leading and trailing runs, so `append` and `prepend` exchanges both work, and a compaction of older history only widens the window) may answer and strike the head, including the claimed-head and `#deferstrike` checks. Git history is the source because it survives closed editor epochs, restarts and snapshot rewrites; the operator's captured insert runs (`#retypestruck`) cover only the active epoch, which a non-operator projection closes before a later cycle's catch-up runs. With no commit history, or a head live in every commit back to the document's first, every echo counts (the earlier behavior). The walk reads at most 128 commits; a head still live at the limit is anchored at the oldest version read, which can only hide an echo an earlier pass would already have struck. A skipped strike logs `preflight_freetext_residue_strike_skipped_echo_predates_head_entry`. Recurring-imperative heads (`#qimpstrike`) stay exempt. Closeout is already scoped: finalize's `#ftstrike` and the session-check residue guard judge a head only against the current cycle's captured response, so a closeout that does not quote a re-typed report neither strikes it nor INTERRUPTs on it. The `#syntheticstrike` continuation-head skip uses the same scope: a free-text head the whole exchange would call answered is skipped from the continuation offer (`queue_continuation_required` / the next head) only when an echo written after its entry point answers it, so a re-typed report answered only before its re-entry is offered as the next head. Both sites share one implementation: the walk's decisions (`queue_head_entry::FreeTextHeadEntryWalk`, the entry identity, the 128-commit limit) live in the pure `agent-doc-queue` crate and the git reads in `agent_doc_git_io::revision::free_text_head_entry_anchor_exchange`, which the preflight strike and the `agent-doc-queue-io` continuation adapter both call. The pure `required_continuation_excluding_claimed` keeps the whole-exchange behavior (no history); `required_continuation_excluding_claimed_scoped` takes the entry anchor. The anchor is read only for a head the whole exchange calls answered, so an unanswered head costs no history read. Claimed heads stay out of the continuation offer and recurring-imperative heads are never skipped. A live head of a `loop` queue is scoped further (GH #327 pass 4): the catch-up strike and the `#syntheticstrike` continuation-head skip count only an echo newer than both the commit at or before the current pass's opening and any write that added an echo while retiring the same head in another queue, and neither strikes nor skips a loop head while no pass is open (see `specs/02-document-format.md` §2.5 Queue schedule). Both sites resolve the scope through one path: `agent_doc_queue_io::queue_schedule::head_echo_window` reads the queue's `queue_head_entry::HeadEchoWindow` once (`HeadEntry` for a non-loop queue, `LoopPass` with the open pass's `opened_secs`, `LoopHeld` otherwise), and `agent_doc_git_io::revision::head_echo_scope` resolves each head's `queue_head_entry::HeadEchoScope` (whole exchange, newer than an anchor, or no open pass). The continuation adapter passes that resolver to `required_continuation_excluding_claimed_scoped`, so a `loop` head the residue strike keeps is never skipped from the continuation offer as answered; non-loop queues keep the entry scope only.

- Queue convergence also auto-strikes a LIVE free-text queue head when it is already complete OR a backlog item already addresses it, even if no exchange answer echoes it (`#qftbklgstrike`). During preflight queue maintenance, after the `#qheadresidue` exchange-answer strike, a deterministic (no-LLM) lexical scorer (`memory_cmd::semantic_queue_strike_matches`, the strike sibling of the existing `semantic_completion_match` *warning*) scores every non-struck free-text head (no `#id`) against BOTH the completed `agent:done` archive and the active `agent:backlog` items. Its work closes through coordinator integration and closeout, not a lexical match: striking a `☑️` row here would retire its completion cell (the worker's only in-document report) and its `Reported` claim before anyone integrated it, and striking a `🟡`/`🚧` row would hide a still-running worker's claim behind a struck row. Pinned by `backlog_strike_leaves_claim_projected_free_text_rows_and_their_evidence`; the operator-authored position-lock (`#qauthorder` / `#queue-operator-pin-position-lock`) and existing `#ftstrike` exchange-answer strike are preserved. A **backlog** match additionally requires exact lineage (`#freetextqueue`): the backlog item's own text, with its leading `#id` stripped and normalized to lowercase alphanumeric words, must equal the head's normalized text — the same identity free-text admission mints a backlog id from. No filesystem snapshot sidecar is written or consulted; legacy residue is inert cleanup input and cannot acquire document authority. `reset --from-current` rebuilds typed recovery state from Lazily current markdown; no CRDT, capture, pending, baseline, snapshot, or live-buffer file is imported.
- Cross-process state exchange uses generic `state_plane_publish`/`state_plane_subscribe` transport RPC around canonical Lazily `Snapshot`/`Delta` messages. Producers publish keyed state projections; RPC handlers must not translate those publications into imperative plugin-owned effect retries. Covering snapshots may replace a prior producer, deltas require the exact producer/base epoch, duplicate delivery is idempotent, and subscribers resume from a monotonic controller plane version. Controller readiness probes use the lightweight handoff-status projection; operator status may include durable store diagnostics, but append-only ledger sizes are bounded high-water observations rather than full-table counts, so repeated readiness or health observation cannot rescan the state ledger.
- Pane layout is the first state-plane domain. Editor plugins publish authoritative columns/window/focus, while the controller records the desired tmux target, actor bindings, observed receipt, and convergence status. A tmux attempt is keyed by the exact frontend snapshot generation plus actor-binding state. Convergence retires it; a retryable failure derives stable `retry_pending` while the same latest-wins effect worker retains ownership, waits with bounded backoff, and retries until convergence or supersession. A newer frontend snapshot or actor-authority fact interrupts that wait and wakes the retained worker immediately. The controller must not synchronously poll tmux from its IPC accept loop or create a detached periodic retry timer. Columns and focus are one effect target: convergence requires both matching observed columns and, when focus is requested, a typed receipt proving the final input-revision-fenced pane-selection consequence. The accepted frontend snapshot is committed to `state.db` before tmux effects, so controller restart recovery does not depend on controller-lifetime message history.
- A pane-layout observation must independently compare the model-owned file-to-pane assignment in desired column order with tmux's physical left-to-right pane order; matching document labels alone cannot prove convergence. A live same-window actor outside the desired surface is diagnostic, not terminal ownership: reconciliation may move its pane to `stash` without killing or interrupting the actor, and the generation remains `retry_pending` until the visible pane count and order converge. A missing requested surface document likewise remains `retry_pending`. Focus continues to resolve the requested document through the file-to-pane assignment and must never index directly into physical pane order. A column the layout effect acknowledges as deliberately gated out (`gated_documents`, a stale-supervisor column) is removed from both the expected surface and the focus requirement, so it converges rather than staying `retry_pending`; a stale `stash` pane is promoted only while its durable recycle request is not overdue and only when it replaces rather than adds a column (GH #136, [specs/07-session-tmux-commands.md](specs/07-session-tmux-commands.md)). Safety of the stale-column gate never depends on editor message order, delivery, or timing; the remote (Coder + JetBrains Remote Dev + Zscaler) path is the design point, and the one time budget involved (`AGENT_DOC_STALE_RECYCLE_CONSUME_BOUND_SECS`) is a configurable liveness bound only.
- **Pane-order invariant (`#tmuxpanesreversed`).** After every layout operation, the panes of the wanted layout, read left to right by tmux geometry (`pane_left`, then `pane_top` inside a stacked column), are exactly the wanted column-major order. `pane_index`, `list-panes` line order, pane creation order, `base-index`, and `pane-base-index` are never ordering inputs. Panes outside the wanted set (for example a protected busy pane) neither satisfy nor break the invariant. Sync enforces it with one pure check and planner (`agent_doc_tmux::pane_order`): after tmux-router returns, it re-reads geometry past the observation cache, and when every wanted pane is present but misordered it applies the minimal `swap-pane -d` plan (at most n-1 swaps), restores the operator's active pane, and re-reads. A violation that survives that one repair is reported as an error, never retried in a loop or accepted silently. Every layout pass writes one `tmux_pane_order outcome=held|repaired|violated|incomplete|unobservable` ops.log line carrying the tmux server version, `base-index`, `pane-base-index`, window size, the wanted pane order, and pane positions before the operation, after it, and after any repair.
- **Frontend layout authority; no structural guessing (`#tmuxpanesreversed`, GH #343).** While an editor frontend is connected, its complete layout snapshot is the sole authority for column membership and left-to-right order. The backend does not own or derive a second editor layout: it retains the last accepted frontend snapshot with its generation, copies that column vector unchanged into the desired tmux effect target, and records observed tmux convergence. Selection-only, `unknown`, partial, stale, failed, or timing-ordered evidence may update focus intent only; it must preserve the last accepted structure or defer. It must never insert, replace, remove, regroup, fold, or reorder columns. Authenticated Remote Dev connection/lease establishment activates pending frontend authority before the first snapshot, including the 75 ms capture debounce, EDT capture, up-to-5-second schema negotiation, and Fleet RPC interval; backend fallback is suppressed throughout that window and after transport failure until explicit retire/release. Snapshot schema 3 carries the frontend-authored exact column vector directly; the backend validates paths but does not reconstruct columns from bounds. Between snapshots it may continue enforcing only the last accepted vector. Manual `Sync Tmux Layout` replaces stale structure only from a complete positive frontend capture; an incomplete/unknown capture preserves or defers, so retrying Sync cannot ratify stale backend structure or invent a column. Its refusal names `flat_evidence_has_no_column_geometry` for the Remote Dev case. A manual Sync of a document with no started agent session is the exception (GH #382): Remote Dev flat evidence bootstraps that one document, or the installation's measured columns when they show it, instead of the install-plugin refusal, and does not reconstruct a multi-file split. A started session keeps the refusal. An explicit foreground `sync_tmux_layout` that would refuse because flat evidence leaves the focused document out of the retained columns, or leaves no authoritative snapshot, waits up to 5 seconds for a published editor-ordered surface that already contains the focus and adopts that vector unchanged (GH #383). If none is published, the deferral names `frontend_authority_absent`, `frontend_generation_mismatched`, or `frontend_connected_without_accepted_publication` instead of collapsing the first two into one install-and-restart failure; only the absent and generation-mismatched cases carry that remedy, and a connected frontend that has not published an accepted layout reports `recovery=retry_after_published_layout`. Flat evidence still never reconstructs columns. When the frontend publisher stays unavailable, every operator-facing backend warning, route failure, and Sync refusal must carry the same effective local/custom-install remedy: install the same modular plugin ZIP in JetBrains Client/Gateway and the Remote Dev backend, verify both sides report that exact plugin version, restart both, then retry the failed command. A restart-only instruction is invalid because restarting cannot install the missing frontend module. An explicit foreground `Run Agent Doc` `ensure` route with unknown geometry may use positive live-tmux observation only to prove that the target already has a pane and dispatch focus-only. It must not replace even a same-width live set: width equality proves neither editor membership nor left-to-right assignment, and filling live slots from an unordered visible set is structural guessing.
- **Remote Dev structural readiness is a two-sided generation invariant (GH #360).** A modular backend is structurally ready only after the matching JetBrains Client/Gateway frontend establishes its authenticated lease and publishes measured columns from the same plugin generation. After the bounded startup grace, a connected Remote Dev session with only flat selection evidence is classified `frontend_authority_absent_or_generation_mismatched`, not as a generic transient layout state: diagnostics report `readiness=blocked`, keep structural routing blocked and the last accepted tmux layout unchanged, and limit the backend fallback to focus evidence for an already-live document. Retrying cannot load an absent or incompatible frontend module and must never reconstruct columns. The local/custom-repository recovery is to install the same modular ZIP on both peers, verify both report that exact plugin version, restart both, and retry. Only Marketplace hosting automatically synchronizes a compatible plugin to the Remote Dev peer; until release automation publishes all three compatibility-ranged updates there, two-sided installation is an explicit distribution requirement. The combined `frontend_authority_absent_or_generation_mismatched` token remains the editor-route and post-grace backend diagnostic. Explicit foreground `sync_tmux_layout` distinguishes `frontend_authority_absent`, `frontend_generation_mismatched`, and `frontend_connected_without_accepted_publication` after the published-layout wait (GH #383).
- A JetBrains `Run Agent Doc` route or `Sync Tmux Layout` command must name the authoritative editor surface snapshot the controller retains (`surface_reference = { surface_id, min_sequence }`, capability `surface_layout_reference_v1` advertised in every `editor_surface_observe` reply) instead of sending `--col` arguments read at click time. The controller copies a complete snapshot's columns and order unchanged into the tmux effect target and derives only non-structural routing metadata. `Sync Tmux Layout` fails closed (`surface_reference_<reason>`) on a missing, retired, incomplete, unknown, or older snapshot, or a foreground focus outside the columns. `Run Agent Doc` with unknown Remote Dev geometry may focus an already-live target but otherwise fails closed without publishing structure. A non-`exact` route whose `--col` fallback names no document (GH #373, Remote Dev backend with no selected editor) is the undetected single-file `ensure` route for its own routed document and takes that same unknown-geometry path; only an `exact` route with no column fails with `editor route requires the exact visible layout before dispatch`. Before that fallback, such a route on a modular Remote Dev backend takes the JetBrains Client's measured forward of its own installation (`jetbrains-rd@<installation>`) when one shows the routed document; when none is retained and the route names `layout_authority = "frontend_measured"`, the controller awaits that forward within the route's own `--wait-for-ready` budget unless the routed document already has a live pane (GH #376). The route consumes that forward only after the forward's own surface `Sync` publication has settled, so the route's fresh intent is always the newer desired-layout generation (`publisher=route`). The plugin keeps the `--col` publication only as a logged compatibility fallback for a controller whose reply lacks the capability, a cross-root command, or a surface it could not publish. See `specs/08-session-routing.md`.
- A foreground editor `Run Agent Doc` route must treat its complete frontend layout snapshot and focus as one exact-visible tmux target and await the corresponding convergence receipt before dispatching to the routed pane. Before publication, the controller canonicalizes editor-relative paths and requires the routed document in those columns; it never materializes a missing focus into a column. A focus absent from the authoritative columns fails closed before desired-state publication or dispatch.
- Route focus is a typed authority effect: `select-pane ⇔ authority = standalone_foreground ∧ target_placement = foreground`. Background and controller-layout authorities never select a pane or window, and a stash or unproven target placement fails closed. A route re-entering from its document's own parked pane is background exactly when `current_pane_present ∧ owner_matches ∧ pane_is_stashed ∧ ¬controller_layout_owned`; it may inject work into that proven existing pane, but must not rescue it, select its window, or mutate the foreground layout. An explicit operator/editor route remains able to focus only through the controller's generation-sequenced layout authority.
- Pane-layout status `phase` and `reason_code` are wire-stable enums; optional `reason_detail` is diagnostic only. Version 1 uses Lazily's canonical JSON envelope and typed JSON node payloads. Protobuf may be added as a node payload codec for additional language runtimes, but it is not required by or embedded into the Lazily state-plane core.
- Layout-owned startup stages a fresh pane in a detached window and returns its binding without changing visible geometry or focus. Only the current layout Effect places it; a superseded or concurrent startup cannot append a third visible pane after a two-column reconciliation. Standalone route placement and first-window bootstrap keep their existing behavior.
- A pane-layout effect receipt is a source fact, while its applicability is a computed join of desired state, actor-binding state, and receipt state. The exact file-to-pane assignment returned by the effect remains attached to that desired-generation/actor-binding pair and takes precedence over actor-store or process-tree inference during observation. A receipt or observation from a superseded generation or actor binding cannot prove convergence or select a pane for newer editor navigation. This controller-owned rule is editor-neutral and therefore applies equally to JetBrains, VS Code, and Zed publishers.
- `install-full` removes repository-owned compilation outputs only after the binary, native library, and editor plugins have been installed successfully. It preserves Cargo's global dependency caches and supports `AGENT_DOC_CLEAN_BUILD_ARTIFACTS=0` when an operator intentionally wants to retain incremental outputs.
- Exchange prompt-prefix normalization must preserve exchange prompt-prefix state already committed in `HEAD` in both directions: previously prefixed user-prompt lines must keep `❯ `, and previously unprefixed agent response lines must stay bare. A `content_ours` fallback may add `❯ ` to newly typed prompts, including every nonblank line in a blank-separated multi-line prompt run after a stale inserted response block, but it must not add that prefix to prior agent response lines simply because the snapshot/baseline pair is stale. Inserted assistant response blocks stay assistant-owned until an explicit `❯` line, component/boundary marker, or canonical prompt-target diff opens a new prompt run; prompt-shaped assistant prose such as questions is not enough by itself. When IPC sidecar verification rejects a plugin-side normalization result and computes a `content_ours` fallback, that fallback must first merge current disk edits against the explicit pre-response baseline, then deliver the normalized repair through narrow editor IPC. If editor delivery is skipped or unproven, the write must fail closed before saving a snapshot, CRDT state, commit, or direct working-tree repair. Concurrent user edits outside `agent:exchange`, including deletions of scratch HTML comments, must remain editor-owned and must not be restored by normalization retry. Post-commit prefix repair must not propagate historical bad prefixes from assistant evidence labels such as `Commit / push:` into later assistant responses, and patch/content prefix application must still refuse to prefix those assistant labels if a stale target list includes them, even when a historical stale target list contains `Commit / push:` and a later response has a fresh bare `Commit / push:` label. A temporarily prefixed response heading such as `❯ ### Re:` is still an assistant response boundary; prefix repair must not treat matching response-body lines after that heading as prompt targets. Prompt-prefix overrun protection logs and passes through when more than `MAX_NORMALIZE_USER_LINES` prefixes would be applied; it must not force-commit from inside normalization now that typed repair decisions own disk/snapshot/editor recovery.
- Binary-authored Markdown blockquotes, especially `> **Queue prompt:**` response scaffolds, are response envelopes rather than user-prompt normalization targets. Normalization removes a legacy `❯ ` prefix from those quote lines and collapses immediately repeated identical queue-prompt scaffold lines before captured-response materialization checks, making captured-finalize retries idempotent instead of appending one new scaffold per retry.
- Sync live-owner recovery must rank file-specific evidence by freshness: path/supervisor provenance first, then the latest open session-log owner, and only then generic same-file process-tree matches. An older pane that still has a same-file harness process must not steal authority back from a newer pane that already recorded the latest `session_start`.
- Sync must also treat the latest alive `session_end origin=registry_rebind ... next_pane=...` successor as authoritative live-owner evidence before generic same-file process-tree fallback. A pane handoff proven by tmux/session-log provenance must not fail just because the supervisor PID or foreground process tree changed afterward.
- When `route --dispatch-only` reuses a live pane through direct tmux input, startup-window reroutes must first observe a harness-specific dispatch-ready prompt in that pane. A Codex status/footer line such as `gpt-5.5 high · ... · Context ...` is not a prompt by itself. OpenCode startup-window prompt probes must use the longer OpenCode redraw budget, including the same harness-specific recovery wait used for starting actors, because the idle splash can become dispatch-ready after the short Codex-style boot probe. During that startup prompt-ready wait, route owns the pane input window and must publish controller-backed `RouteSubmitStarted` / `RouteSubmitSettled` facts before any supervisor idle-queue context reset can enqueue or submit `/clear` / `/new`; pending `QueueContextClearDeferred` / `QueueContextClearStarted` projections and orphan visible clear drafts must wait while the route-submit projection is pending. Accepted-without-dispatch-start proof records `RouteSubmitBlocked` for the bounded blocked window. Dispatch proof must separate pane-input acceptance from dispatch-start evidence. Accepted shared text+`Enter` delivery is a successful dispatch-only result for Claude Code, Codex, and OpenCode, and logs `proof=accepted proof_scope=accepted_only` when dispatch-start proof is absent. Codex hook proof and OpenCode pane-state proof are still logged as stronger `dispatch_start` evidence when available, but missing stronger proof does not make the editor action fail. Editor-triggered JetBrains routes must propagate the durable Run Agent Doc attempt id into the binary process, and route/tmux diagnostics must include that id on the input-delivery and proof lines so a live click can be correlated across `.agent-doc/state/editor-route-attempts/`, `ops.log`, and preserved route-submit pane snapshots without replacing tmux-router reconciliation.
- Claude readiness treats a bare `⧉ <label>` line as an attached-artifact composer chip and continues scanning for the real idle `❯`/permissions prompt; `<label>` is arbitrary session content and must never be hard-coded. Only the complete picker shape (`Enter to open` plus a `claude.ai/code/artifact/...` URL) is an operator-owned dispatch blocker.

In that shape the binary warns and skips tmux-router reconciliation instead of collapsing the remaining foreign pane set into a new authoritative layout, but it still reselects an already-visible requested focus pane inside the preserved window.
- Full/manual `agent-doc sync` is the binary repair path behind editor `Sync Tmux Layout`: before applying the frontend-authored tmux target, it must invoke the same file-scoped doctor repair used by `agent-doc session doctor <FILE> --repair` when a focused/session document is available. That repair must close recoverable `jb_cache_conflict_cancel` commit-boundary drift (visible document and snapshot already contain the response while `HEAD` does not) before pane liveness can short-circuit, and must normalize the inferred tmux session to `0:agent-doc`, `1:stash`, and adjacent overflow `N:stash` windows, renaming `stash-*` aliases back to `stash`, even when the editor supplied a stale `stash` window target or sync starts while the active window is named `stash`. Passive `sync --no-autostart` remains non-destructive and does not run that repair step.
- A full/manual sync that provisions a missing document pane owns one terminal create-and-route boundary: resolve the intended tmux session, create and register the pane there, wait for the harness to become dispatch-ready, and submit the document reopen before returning success. The Project Controller receipt records that this strict path was selected. Automatic/passive editor sync remains admission-oriented and must not wait on or claim this manual route boundary.
- A foreground `sync_tmux_layout` command must name its focused document in the authoritative frontend columns after project-root canonicalization. Membership includes every comma-joined tab in a column, not only its first session document: when the focus names a session document later in that stack, that focused document is the column's tmux-pane representative without changing the frontend's column grouping or left-to-right order. A focus outside those columns is an impossible terminal target: the controller refuses it before durable snapshot memory or desired-target publication, rather than spending the effect retry budget. Passive automatic observations may omit an inactive focus and retain their existing focus-suppression behavior.

A passive editor-surface observation arriving after the command publication is deferred—even when its columns and focus are identical—so it cannot replace `no_autostart=false` with passive `no_autostart=true` before a missing local or cross-root pane is created. JetBrains must await the terminal command receipt and surface a refused, superseded, timed-out, pane-start, or route failure instead of reporting state-plane admission as successful completion.

If no live actor binding exists after the pre-lock handoff, reuse the latest matching pane when one is known, otherwise fall back to an alive exclusive registered pane rooted to the same document, and only then cold-start a new pane. The slower supervisor/process-tree recovery still applies to non-passive paths and non-happy-path recovery.
- Automatic editor syncs that have a complete visible markdown snapshot must pass `--exact-visible` with `--no-autostart`; the binary must use the exact frontend column vector and skip remembered focus-only sibling expansion, so stale panes do not reappear after the editor switches away from a document.

That survey may replace the prior controller-managed column; an unexpected live actor without either recovered supervisor or structural-assignment evidence remains operator-owned and protected.

The explicit `--done <id>` todo-own-id lifecycle remains the documented exception that may atomically check the todo and strike its matching annotated queue row. A `starting` actor is not dispatchable until it refreshes to `ready`; route may promote a healthy starting actor to `ready` only after the current generation's live pane shows a harness-specific dispatch-ready prompt, and if it remains `starting` after the bounded route wait, route must fail closed before tmux or supervisor input is submitted. If the same pane/generation later shows dispatch-ready prompt proof after route has marked it blocked for `starting_actor_timeout`, route may clear that timeout and promote the actor to `ready` before submitting. Reads of this per-document timeout projection must use the indexed `(document_hash, fact_type, id)` state-event path and must not replay the project-wide state-event ledger; editor focus polling may exercise route readiness while otherwise idle. Startup wait failures must persist a single typed diagnostic with elapsed time, pane id, generation, actor state, supervisor health/runtime state, prompt-ready status, and last lifecycle transition so the editor route error points at the exact failed phase. The current-generation ready-prompt barrier must also accept an `idle_pane_reconcile` transition as ready proof (`#monster60stimeout`): the supervisor's idle-watch only records that reason after `supervisor_pane_has_busy_cue` returns `Some(false)` (direct pane evidence that the pane is not busy), so the route must not wait the full 60s timeout when the edge-triggered pty redraw missed re-emitting a recognized prompt shape but the supervisor already proved the pane idle.
- When a document explicitly changes `agent:` to another harness, a healthy authoritative actor record for the old harness must not hard-fail future `Run Agent Doc` routes with "bound to harness X, not Y" (`#actor-switch-rebind`, `#harnesshotrebind`). Route treats that explicit frontmatter change as a typed boundary handoff: it accepts the operator request without dispatching any prompt bytes into the old harness, preserves an active old-harness turn, and lets the supervisor idle watch spawn the newly resolved harness at the first safe `prompt_visible && !turn_active` boundary and auto-trigger the owning document exactly once. Repeated routes coalesce with an in-flight handoff. A paused queue holds the accepted handoff until queue resume and must not require a supervisor restart. The supervisor IPC `state` payload reports `current_harness`; when the live runtime has already switched but the actor record is stale, route repairs that record and proceeds instead of starting another handoff. For an old-harness actor that is **not a live authority** (closed/blocked, or its pane is no longer dispatch-ready), route falls back to the normal create/rebind path. A healthy live authority is never cold-replaced (`mismatched_authoritative_actor_can_be_replaced` remains false), and `agent_change_restart: false` remains an explicit fail-closed policy. Without an explicit document harness change, a healthy ready actor from another harness also remains fail-closed.
- Harness conversation identity is stored as a `resume:` map with explicit `claude`, `codex`, and `opencode` entries. Every launch, same-harness restart, controller cold recovery, direct run, and stream reads only the selected harness key; recording or clearing one harness id preserves the other harness histories. The producer harness is an explicit input to every mutation: managed paths use the running backend, and manual `resume-id` requires `--harness`; neither may infer the target key from the document's possibly switched `agent:` value (`#frontmatterintentmisclass`). Ownership checks still inspect all entries so two documents cannot claim the same conversation. A legacy scalar remains readable only as the document's active harness id and migrates into that harness's map entry on the next managed resume write (`#harnessresumemap`).
- Resumed agent prompts must restate the changed exchange tail as ordered user-authored prompt-bearing changes. The canonical subtypes are `prompt_target`, `content_edit`, `recovery_artifact`, and `boundary_artifact`. The turn-completeness contract is oldest-first: do not anchor only on the newest question, do not treat the turn as complete until each `prompt_target` item is answered or explicitly grouped into one response, and treat `content_edit` items as source-of-truth corrections while artifact items route to normalization/repair instead of ordinary conversation.
- Prompt-cache replay metadata is part of direct-run prompt assembly. Only durable response contracts, harness-neutral instructions, turn-payload reading rules, cache-control metadata, and provider replay-key material may live above the cache boundary. File paths, queue heads, diffs, current document excerpts, status text, prompt-bearing change sections, compaction/accretion diagnostics, bounded context packs, session ids, and recovery markers must stay in the volatile suffix after the boundary. The provider cache key must include the agent-doc key version, routing-affinity hash, and stable-prefix SHA-256; the volatile suffix must never contribute to that key. The stable prefix SHA-256, provider cache key, cache-control policy, and routing affinity must remain identical across consecutive resumed agent-doc turns whose changes are only volatile session churn such as no-op closeout diagnostics, status edits, queue-head/list churn, boundary markers, diffs, or bounded context packs. Durable response-contract/instruction changes must change the stable-prefix fingerprint and provider cache key, even when the routing affinity is held constant.
- Prompt-cache session-cost diagnostics must make cache misses explainable without raw JSON analysis. Given two cost samples, miss ranking compares stable-prefix fingerprint, adapter state, routing affinity, cached-input token delta, and creation-token spike, then reports ranked causes with the highest-impact invalidation cause first. When no prior sample is available, the diagnostic must still print the current fingerprint, adapter state, routing affinity, unknown token deltas, and an explicit `baseline_required` rank state so later history persistence can feed the same ranking path. The token/performance gate persists prompt-cache effectiveness samples as JSONL records keyed by provider, harness, and real transcript id (for example Codex/OpenAI and Claude/Anthropic transcripts). Trend checks must compare the current sample with the latest matching workload history and fail with an operator-readable summary that includes provider, harness, transcript id, previous observation time, cached-input delta, creation-token spike, thresholds, and the same ranked miss causes used by the session-cost diagnostic.
- Prompt-prefix preservation is part of that same contract: append-mode exchange canonicalization must derive required `❯ ` transcript prefixes from the prompt-bearing classifier (not a separate ad hoc heuristic). That invariant still applies when `repair` dedups an already-present template response: `AlreadyApplied` is a canonicalization-capable outcome, not proof that transcript normalization can be skipped. Prefix repair must remain structurally scoped to prompt runs: once a `### Re:` / `❯ ### Re:` / `## Assistant` response block starts, assistant prose and verification/list bullets must not become `❯ ` targets merely because their trimmed text matches a `normalize_prefix_lines` entry; targeted repair may leave the response block only when the line matches the explicit target set and also starts a prompt run, or when a boundary/component marker has already closed the response. `session-check` must fail closed when a bypassed response leaves bare prompt-target lines in the changed exchange tail, and when prompt-bearing user edits exist without any newer cycle start at all.
- The prompt-bearing classifier itself must suppress stale-boundary prompt runs that are already visibly answered by a later response in the same changed tail, including raw assistant completion prose without a formal `### Re:` heading. `preflight`, `plan`, routed admission projection gating, prompt-prefix normalization, and write-path snapshot decisions must all consume that same filtered actionable list instead of re-deriving their own stale-tail heuristics.
- Unstarted exchange-prompt detection must not be snapshot-gated on a fresh session (`#codex-exchange-prompt-no-dispatch`). The queue path activates independently of any cycle snapshot, so a queue write dispatches `Run Agent Doc` even before the first snapshot exists; the exchange path keys off the snapshot↔file diff. When no snapshot exists yet, `first_unstarted_prompt_bearing_change` must fall back to the committed `HEAD` blob (then to an empty baseline for untracked docs) so a freshly typed exchange tail prompt is still detected and routed, instead of leaving exchange writes inert while the same text in `agent:run` starts a turn. The HEAD fallback stays exchange-scoped — queue components remain stripped from this diff and keep their own activation path.
- Component/comment parsing must never panic on valid UTF-8 document content. Ordinary HTML comments near multibyte glyphs such as `❯` must either parse normally or be ignored as prose; malformed agent markers still surface as structured parse errors instead of byte-boundary crashes.
- The state backbone is the Cycle State Machine plus typed event-sourced projections, not one global FSM for every subsystem. The cycle FSM owns only turn closeout phases. Queue, document, transport, supervisor, route, and proof state must be represented as typed append-only facts reduced into deterministic projections, with live mutation guarded by owner actors, epochs, and leases. Local FSMs are allowed for small closed subdomains, coroutines may express linear protocols, and behavior-tree-style logic may be used only as policy over projections; GOAP/MPC-style planning is not the durable state model for correctness-critical closeout.
- FlowCore is the typed ownership layer for the direct session cycle, routed reopen, closeout, document mutation, operator clear, and orchestration batch hot paths. The first phase is mirror-mode: existing commands still execute behavior, but high-risk branches emit `flow_event` ops lines with `flow`, `stage`, `outcome`, and tokenized `reason`, and `agent-doc ops summary` groups failures by flow stage. The same summary must also emit ranked bug clusters that correlate closeout/captured-response drift, route/start replay gaps, Codex warning storms, SQLite counts, cross-harness markers, session-review guardrails, and working-tree drift by file/session/cycle/thread keys. Closeout/document-mutation guard reasons, including pre-write/pre-commit pending capture blocks, patchback parse shapes, repair recovery boundaries, committed-cycle late fallback rejection, and disabled full-content decisions, must use FlowCore enums or document-mutation decision helpers instead of adding more free-form proof strings. New tactical fixes in these hot paths should prefer FlowCore enums and pure decision helpers over adding more free-form proof strings.

- A failing test step is never lost to a deleted log (`#flakyintegrate0494`). Every step `make test`/`check` runs (nextest, the batched cargo-test packages, doctests, the plain cargo-test fallback, `sim-medium`, `sim-net`) runs through `scripts/test-run-record`, which keeps its combined output, exit status, command line, a snapshot of other test runs alive at its start (pid, working directory, load average), and, for nextest, a copy of that run's JUnit report (nextest's `junit.xml`, which stores each failing test's stdout/stderr) in one per-invocation, per-checkout directory `tmp/test-runs/<UTC start>-<make pid>/` (`TEST_RUN_ARTIFACT_ROOT`), outside `target/` so `cargo clean` and disk sweeps cannot remove it. A JUnit report left by an earlier run is deleted before the step starts, so a run is never filed with another run's report. A failing step prints the directory it kept. Pruning keeps the newest `AGENT_DOC_TEST_RUN_KEEP` (default 20) runs and any run with a failing step among the newest `AGENT_DOC_TEST_RUN_KEEP_FAILED` (default 100). - The full local gate is hermetic with respect to checked-in editor locks and build-path selection (`#check-hermetic-target`). `make check` bootstraps the locked VS Code dependencies when `node_modules` is absent or stale, honors `CARGO_TARGET_DIR` for both `AGENT_DOC_BIN` and native-plugin library discovery, and defaults test scratch files to a short writable non-project directory (preferring `/var/tmp`) while preserving an explicit `TMPDIR` override.
- Tests never adopt a real project as their root (`#testisolationtests`). `.agent-doc` project-root discovery honors `AGENT_DOC_ROOT_CEILING_DIRECTORIES`, a `PATH`-style list of absolute directories with `GIT_CEILING_DIRECTORIES` semantics: the walk examines its starting directory, then each parent, and never climbs into a ceiling directory or above it; relative and empty entries are ignored. Unset, production discovery is unchanged (including users whose `$HOME/.agent-doc` serves as a lazy root for scratch files). A cargo test binary with no explicit ceiling bounds its own in-process discovery at its temp root. `make test`/`check` and the other test targets, and the nextest `test-isolation` setup script, run `scripts/check-test-tmpdir`, which refuses a `TMPDIR` that has an `.agent-doc` ancestor and exports the ceiling `<TMPDIR>:<workspace>` to every test process (an inherited ceiling is kept, but the guard appends this checkout's own `<TMPDIR>` and workspace when it lacks them, so a list another checkout's `make` exported never leaves this workspace unbounded; `#checktmpdirleak`) and the binaries and controllers they spawn, so a test tempdir under `$HOME` cannot write the operator's `~/.agent-doc` state.db, ops.log, proof ledger, or snapshots, or start a controller with `--project-root $HOME`.
- The `AGENT_DOC_LOG` debug log goes through the same bounded discovery (`#tracingrootceiling`). Its directory is `<root>/.agent-doc/logs/` of the nearest project root that `find_project_root` resolves from the working directory, and that `logs/` directory is created the way `ops.log` creates it. The tracing setup used to climb from the working directory with no limit to the first ancestor that already had `.agent-doc/logs/`. It ignored `AGENT_DOC_ROOT_CEILING_DIRECTORIES`, so a bounded process could write `debug.log.<date>` into `~/.agent-doc/logs/`, and a nested project without `logs/` logged into an outer project. With no project root inside the ceiling, file logging is disabled with a stderr note. There is no user-level fallback directory, and an ancestor above the ceiling is never adopted. `tests/tracing_root_ceiling.rs` pins this behaviour. A positive control without a ceiling proves the ancestor would otherwise receive the log.
- Tests are never handed a live project either (`#testisolationleaks`). Discovery ceilings stop a test from walking up into a real root, but the `/proc` walks behind the install fan-out (`controller_project_roots`, `controller_serve_pids`, `open_supervisor_processes`) used to return every controller and supervisor on the machine. `recycle_supervisors_all_projects_force_enumerates_without_error` ran the real fan-out from inside each lib-test run. Each concurrent `make check` then checkpointed the operator's live documents, so the test binary connected to the live editor sockets with a bare `0.35.509` hello (lib-test binaries carry no `AGENT_DOC_BUILD_ID`) and the editors rejected it as an IPC build mismatch. It also appended an `install_fanout` recycle request to every live project's `state.db`, so open supervisors recycled with nothing installed (19:40, 19:56 and 20:27Z on 2026-10-15). A test process now has a runtime scope (`agent_doc_fs::test_runtime_scope`): `std::env::temp_dir()` for a cargo test binary (an executable in a `deps/` directory), or the explicit `AGENT_DOC_TEST_RUNTIME_SCOPE` list. `make test`/`check` and the nextest `test-isolation` setup script export that list, so the `agent-doc` binaries an integration test spawns are scoped too. Cross-root discovery returns only roots and documents inside the scope. Driving a runtime outside it panics with `#testisolationleaks`: an existing controller socket connect, a controller recycle request, a supervisor recycle over IPC, a route-owned document CRDT checkpoint, an install recycle request, or a `state.db` open. A panic, not an error, so a fail-open fan-out cannot swallow the escape. A production process has no scope, sees every runtime, and never reaches a guard. The working directory is ambient too. A test's working directory is its crate checkout, and the CWD session registry (`agent_doc_session_registry_io::load`/`registry_path`) used to open and create that checkout's `.agent-doc/state.db` and `state.db.lock`; in the main checkout that is a live project's ledger. `agent-doc route` pruned that registry against the configured tmux server before it checked the file, and `prepare_editor_session` ran a CWD project init. A test process whose working directory is outside its scope therefore has no CWD registry (`cwd_registry_in_test_scope`): `load` answers empty, CWD prune and claim validation are skipped, and an explicit `load_in`/`save_in` or a CWD project init outside the scope fails the test. Production, whose working directory is the operator's project, is unchanged. `process::tests` pins the confinement with a positive control: a fake `agent-doc start`/`controller serve` process under the temp root stays discoverable, and one naming a root outside it does not.
- A live-tmux test's panes are part of its fixture too (`#prunetestisolation`). Stash purge and pane repair resolve a pane's `#{pane_current_path}` to its nearest `.agent-doc` ancestor and, when that root differs from the process working directory, open that root's session registry and supervisor sockets. The `resync::prune` purge tests started their panes in the crate checkout, and tmux gives the stash window's placeholder pane the tmux client's working directory, so both collapsed to whatever ancestor held `.agent-doc/`: the superproject root, or `$HOME` when `~/.agent-doc/state.db` existed. Opening that live `state.db` tripped the `#testisolationleaks` guard, and where no such ancestor existed the leak passed silently. A test that drives purge or repair against panes therefore owns one temp project root (with `.agent-doc/`): its panes start there, it is the process working directory while the tmux client runs, and before the purge it asserts that every live pane on its isolated server resolves to that root, so a leaked pane fails on every machine rather than only where an ancestor `.agent-doc/` happens to exist.
- Developer verification is two-tiered. `make check-fast` derives changed workspace packages and their transitive reverse dependents from Cargo metadata and validates only that affected scope plus relevant non-Rust surfaces. It never creates release proof. Release validation runs cheap version synchronization and editor-parity manifest checks before expensive suites, then independently reuses matching `make check` and `make tmux-ci` receipts. Receipt identity covers repository paths/bytes and toolchain versions, not index, commit, or tag metadata. Cargo targets remain worktree-local, `make install-full` honors an explicit `CARGO_TARGET_DIR`, and an available `sccache` may share only content-addressed compiler results across worktrees.
- `make check` lints the whole workspace (`#clippyworkspacegap`): its `clippy` step runs `cargo clippy --workspace --all-targets --all-features -- -D warnings`. The workspace declares no `default-members`, so a bare `cargo clippy` selects only the root `agent-doc` package and leaves the other members' tests, examples, benches, and every member the root does not depend on unlinted except by `check-fast` when affected. `check-fast` keeps linting only the affected packages; the authoritative gate never narrows its lint scope to the root package.
- `make check` turnaround is measured, not guessed. Every Rust step shares one `cargo build --workspace --all-targets` (the feature resolution nextest's workspace test build uses, which also uplifts `target/debug/agent-doc` and `libagent_doc.so`); steps select test executables from it (`--workspace --bin agent-doc`, `--workspace --test …`, nextest filtersets, `scripts/run-batched-tests`) rather than re-resolving features with `-p` or root-only invocations, which had compiled ~479 units per core-crate edit instead of ~256. The controller-heavy batched packages keep one libtest process per test binary at `--test-threads=$(TEST_THREADS)`, but the binaries run concurrently (`BATCHED_TEST_JOBS`), and any failing binary fails the step. `[profile.dev]` keeps `debug = "line-tables-only"` (backtraces resolve to file:line; `CARGO_PROFILE_DEV_DEBUG=2` restores full debuginfo). `make tla` runs TLC checks concurrently with per-job isolation and skips only on a content receipt over the model files, runner, and JVM. No check is dropped and no timeout is raised by these optimizations.
- A release assembled from claimed queue workers has one explicit batch boundary before version projection. Every completed claim ready at that boundary is integrated into the same version/check/install train; later-ready claims wait for the next release. `make release` performs the batch's only `install-full` after pushing main and the version tag. It emits elapsed time and separate terminal outcomes for the tag/publish handoff and local full-profile install, so a post-push local install failure cannot be mistaken for a failed publication or trigger a duplicate tag.
- A cold launch waits on the child it spawned, not only on the socket path (launch exit masked as a timeout). `connect_or_launch` keeps the detached controller's exit observer. As soon as the child exits before publishing the public socket, the wait makes one last connect to adopt a peer that won the race. If no peer answers, it fails with the child's exit status and the tail of `.agent-doc/logs/controller-stderr.log`. It does not poll out the launch budget and then report "timed out waiting for project controller". The timeout is left for a child that is alive but has not yet bound. Live repro (load flake, 2026-10-15): every captured instance of `timed out waiting for project controller` in `agent-doc-preflight-io` was a controller that had exited with status 1 within the same second. It exited on `state db is corrupt … first16=2026-10-15T17:…`, a `state.db` header overwritten by a log timestamp (the `state.db` fd-clobber bug, fixed on `fix/statedb-fd-clobber`).
- A unit fixture whose assertion needs a controller RPC hosts a warm in-process controller (`start_state_actor_for_tests`) instead of letting its first timed RPC `connect_or_launch` a detached `agent-doc controller serve` (`#visiblewriteloadflake`). The detached launch charges exec, runtime hydration, and first-touch `state.db` convergence to the 2s test-mode connect/RPC deadlines, so a busy runner, not the code under test, decides the outcome. The in-process actor hydrates before it binds its socket and serves each client on its own thread like production, so one client's long-poll cannot starve another client's RPC. The same holds for the already-applied receipt fixtures in `agent-doc-write-runtime-io` (`#flakyintegrate0494`): their receipt is recorded strictly against a warm actor and each asserts no detached controller was cold-launched, because a receipt RPC that timed out was silently discarded and sent the code under test down the missing-receipt branch.
- A fixture that simulates an editor socket uses `agent_doc_test_support::SimulatedEditorListener` (`#flakyreceipthelpers`), never a hand-rolled `ipc_io::start_listener` that records receipts and discards the result. The fixture ensures the process's shared warm in-process controller (`ensure_state_actor_for_tests`, the same actor a closeout owner claim uses, so the two never steal each other's socket) before it binds; records every visible-write receipt strictly, answering a failed record with a rejected receipt instead of a false `applied`, printing it, and failing the test when it drops; asserts on drop that no detached controller was cold-launched; and blocks until its socket serves and joins its listener on drop. It also registers its root in `agent_doc_ipc_io::known_live_test_editors` (feature `test-support`), which makes the client's 6s editor receipt deadline a 30s hang ceiling for that root only: a slow receipt from an always-answering in-process editor is host load, not absence (the `#remainingwallclock` rule for editor IPC). With its core shared with 64 spinners the receipt record's CPU stayed ~50ms while every thread handoff waited a scheduling round, so its wall time reached 3-4s; a fixture that must exercise the receipt timeout keeps an unregistered listener.
- A workspace lib test never cold-launches a detached `agent-doc controller serve` (`#coldlaunchflakes`). When a lib-test harness (`target/<profile>/deps/agent_doc*-<hash>`) reaches `connect_or_launch` for a root with no controller, the process's shared warm in-process state actor (`ensure_state_actor_for_tests`) serves the root instead. The actor binds its socket before it returns, so the connect has no startup race and no launch deadline. Every real spawn goes through `launch_detached_at`, which panics in a lib test that did not opt in with `allow_cold_controller_launch_for_tests`. A new launch path (handoff, recycle, helper) therefore fails the test that takes it instead of reintroducing the race, and `cold_launch_test_policy::tests` pins this guard. An opted-in launch waits only until the child publishes its socket or exits. Its budget is a 150s hang ceiling, below nextest's per-test kill, not the 2s test-mode launch budget. The `agent-doc` binary (a launched controller, or the CLI an integration test spawns) is never classified as a lib test, so it launches exactly as production does. A lib test that routes a document's relay in-process (`seed_embedded_relay_for_file`, a replica registration) models the controller-hosted topology: `reliable_sync_editor_live_for_file` answers from this process's plane, like the controller itself, and does not ask the in-process actor, which shares this process's relay registry. Measured 2026-10-15: one workspace nextest run had 498 cold launches from 17 lib-test binaries before this change and 0 after. Under load these launches produced the `timed out waiting for launched controller pid N` failures in `agent-doc-preflight-io` and `agent-doc-queue-io`, and the empty warning list in `#staleplugwarnflake`.
- The cold-launch guard covers integration-test targets too (`#integrationtesttargets`). The policy keys on who launches. (1) A workspace test harness is any `target/<profile>/deps/<name>-<16-hex-hash>` executable, which covers lib tests and integration tests (`tests/*.rs`, e.g. `session_check-<hash>`). It is served in-process exactly like a lib test: `connect_or_launch` uses `ensure_state_actor_for_tests`, and an unopted spawn panics. (2) A process a test harness spawned is any process with a harness among its first 8 ancestors (Linux `/proc`), such as the `agent-doc` CLI an integration test drives. Its controller launch is production behavior. It is admitted only when the test sets `AGENT_DOC_TEST_CONTROLLER_LAUNCH_REASON` (exported as `project_controller::TEST_CONTROLLER_LAUNCH_REASON_ENV`) to a non-empty reason on the spawned command. Without a reason, `launch_detached_at` panics before any spawn side effect, so a target that newly starts launching controllers fails instead of adding unbounded cold launches. Each CLI-driving target sets its reason once in its command helper. A controller that a harness launched after `allow_cold_controller_launch_for_tests` inherits the opt-in through that env var, so its handoff replacement stays admitted. Every admitted launch waits only for the child to publish its socket or exit, with the 150s hang ceiling instead of the 2s test-mode budget. The `test-support` CLI no longer serves closeout-owner claims from its own short-lived in-process actor. That path sent `test_shutdown` to the test project's launched controller and died with the CLI, so the project's next command cold-launched again. The CLI now adopts the project's controller as production does, and one launched controller serves every command of a test project. A CLI started inside a tmux pane (parent: the tmux server) or on a non-Linux host finds no harness ancestor and is unguarded. Measured 2026-10-15 on the integration-test targets (`nextest -E 'kind(test)'`, 1234 tests): 546 launches before this change (403 from harnesses calling library code in-process, 143 from the CLI, up to 12 per test) and 237 after (0 from harnesses, 237 from the CLI, at most 2 per test, 1 per test project). The CLI count rose because the roughly 90 tests whose closeout used to run in a CLI-hosted actor now launch the production controller once. Summed test time fell from 2071s to 1877s. With a shim delaying each `controller serve` by 3s under `stress -c 64`, the targets went from 14 failures (19 `timed out waiting for launched controller`) to 0. Without the shutdown-and-relaunch per command, a CLI closeout on tmpfs finishes in well under a second, which exposed a whole-second tie in the `#chatprompt` ledger prune. A committed cycle now prunes a chat prompt only when the cycle opened strictly after the prompt was noted. A prompt noted in the same second as the cycle start is kept: dropping it would lose an unanswered prompt, while keeping it at worst carries an answered prompt into one more contract.
- A unit test whose writer runs concurrently with the code under test synchronizes on the writer's completion signal, not on a wall-clock deadline (`#visiblewritewallclock`). A poll that returns empty is a defect only if the writer had already recorded its receipt when the poll began; otherwise the test waits for the writer's receipt event and re-polls with a zero budget, so the predicate alone decides. Production poll helpers keep their timeout APIs; only the test's waiter changes. Raising a test timeout is not a fix.
- A fixture that simulates the editor's CRDT delivery on a thread (`project_crdt_deliveries`) never runs it concurrently with a single non-blocking settlement pass whose result depends on whether that delivery has landed (`#retainedsettlerace`). A retained-capture or retained-committed settlement pass samples `delivery_converged` once and returns retained when the editor has not projected yet; production re-drives the pass on the next replica-state edge. `retained_capture_repairs_legacy_welded_queue_close_before_validation` applied its welded-close repair through the authority without gating on the receipt and then sampled convergence in the native-save step, so it settled only when the simulated editor's 5ms pull loop ran inside a window of about 20ms, and it failed under `check-fast` load (2026-10-26). Such a fixture asserts the retained pass first, including that disk was not forced ahead of the editor, then runs the delivery to completion and joins it, then asserts the re-driven pass settles. A fixture whose foreground blocks on the delivery receipt (`atomic_write_through_authority`, a pre-write delivery barrier) may run the delivery concurrently, because the foreground waits for the event instead of sampling it.
- A fixture that rewrites a live controller's `.agent-doc` never opens its own SQLite connection at a path a controller writer may hold (`#detachedexitci`). It builds the replacement database elsewhere on the same filesystem and renames it into place. A controller connection opened before the fixture unlinked `state.db` commits on the unlinked inode and deletes `state.db-journal` by path. POSIX locks cannot order connections on two inodes, so that unlink removed the fixture's journal for the new file and the fixture's commit failed with `SQLITE_IOERR_DELETE_NOENT` (5898). `controller_exits_when_its_public_socket_is_unlinked_under_a_surviving_root` failed 1 in 30 full parallel `agent-doc-controller-io` runs this way. A probe running the real exit-reap writer against the old fixture failed 846 of 2000 writes, and the rename fixture failed none.
- Reactive controller tests await the matching state-plane publication instead of treating any frame as proof and then polling a replaceable map (`#state-receipt-test`). Wake-map mutation and its covering Snapshot share one publication order, and a same-capture retained-settled wake cannot be downgraded by a later generic wake before closeout consumes it.
- An agent-doc self-development install schedules its own idle-boundary handoff. An active response cycle must close with `respond` before an explicit project recycle; recycling before closeout competes with the editor projection and manufactures retained-convergence churn (`#closeout-before-explicit-recycle`).
- `CycleContext`/`ActorContext` are the lazily-backed read cache boundary for per-run global configuration and transactional document/project registry snapshots. Long-lived actors must explicitly invalidate those slots on controller events. Read-only route/sync/resync/gc lookups may reuse those snapshots for a single logical operation, but every registry read-modify-write path must still execute through the state-store transaction boundary.
- Harness-specific launch controls are explicit: `agent_args` is generic, `claude_args` applies only to Claude, `codex_args` applies only to Codex, `opencode_args` applies only to OpenCode, and `codex_network_access` controls whether agent-doc preserves, removes, or forces `CODEX_SANDBOX_NETWORK_DISABLED` for Codex child sessions. `claude_model: opus`, `/model opus`, and the built-in Claude Code high tier are deferred to Claude Code: agent-doc emits `--model opus` so Claude Code resolves its current latest opus, and attribution is self-stamped by the running agent instead of a pinned version (agent-doc stores no concrete opus version, so launch and attribution can never lag a release). Explicit non-alias model ids (e.g. `claude-opus-4-8`) pass through unchanged. `opencode_model` / `opencode_args` allow managed OpenCode panes to launch as `opencode --model <provider/model>` with OpenCode-specific flags, while direct `agent-doc run --agent opencode` uses `opencode run`. Managed Codex capability proof is off unless document frontmatter sets `managed_proof: true`. When opted in, `codex_network_access: enabled` must prove host DNS plus a bounded `codex exec --json` child DNS/HTTPS command under the same launch args before route may trust the pane as network-capable; managed OpenCode startup uses a bounded `opencode run --format json` child probe for network checks. Opted-in Codex proof children use `--ephemeral`, `--ignore-rules`, and low reasoning effort, and combine network plus writable-root checks in one child when both are required. Managed OpenCode startup also records `opencode_capability_proof` for documents with `required_ssh_targets`, and that proof must run an isolated SSH check inside the OpenCode child before auto-trigger, supervisor injection, managed route, or dispatch-only route may submit prompt work. Successful proof events must include per-phase `timings_ms` for network, SSH, writable-root, and total proof time. Successful and failed managed proof summaries must be surfaced as tmux status messages through `display-message` on the owned pane, not written into the child pane transcript; the full proof event remains in the session log. For OpenCode, an otherwise chrome-only `context ... % used` status footer counts as an idle composer even when no standalone `>` prompt line is captured after proof completion. When Codex writable roots are required, successful proof events must also include a normalized `writable_root_contract` fingerprint, and route/session-status may treat a Codex proof as current only when that fingerprint matches the active document's resolved `--add-dir` set after the latest `session_start`. When a Claude/Codex document lives in a submodule, harness launches must also auto-add any writable roots outside the submodule that the session lifecycle may need: the superproject working tree for parent-repo document patchbacks plus the external git metadata directories (`.git/modules/...` for the submodule and the superproject `.git` for pointer updates). If a resumed Codex `exec resume <id>` turn reports the local-browser/CDP EPERM signature (`Operation not permitted` on `127.0.0.1:9222` / `localhost:9222`), agent-doc must treat that as stale resumed-session capability drift, retry once with a fresh `codex exec`, and let the successful fresh thread replace the saved `resume` id instead of trusting the poisoned resume state again. Because `codex exec resume` cannot accept new `--add-dir` roots, a direct resumed Codex backend turn whose current launch args require writable roots must fresh-start with the full root set instead of attempting resume. Required SSH metadata may come from document frontmatter (`required_ssh_targets` or `required_ssh_profile`) or from project-local `.agent-doc/config.toml` mappings for known ops docs. If a configured SSH-dependent document cannot resolve any targets, preflight/startup must fail closed before launch. Those pre-launch SSH capability probes must run in isolated mode (`ControlMaster=no`, `ControlPath=none`, `ClearAllForwardings=yes`, `PermitLocalCommand=no`) so they cannot create or reuse shared SSH multiplexing state that would affect later operator shells. When a document resolves required SSH targets, that same resumed-session recovery must also treat bare `socket: Operation not permitted` command output as required-SSH capability drift when the `command_execution` event proves SSH command context for one of the required targets, while still excluding the localhost/CDP drift family and historical capture/log grep output from the SSH path. For resumed required-SSH streaming turns, early assistant chunks from the resumed session must stay buffered until required SSH is proven safe or the turn completes successfully, so a fresh retry can discard stale prelude text instead of leaking it into the final response. A transient capability-proof failure must not permanently disable the session: the proof retries with bounded exponential back-off (configurable via `managed_proof_max_attempts`, `managed_proof_retry_backoff_secs`, and `managed_proof_probe_timeout_secs` in frontmatter or `.agent-doc/config.toml`; defaults 3 / 2s / 45s), keeping the gate `Pending` between attempts and only committing to `Failed` after the budget is exhausted. Operator recovery is gate-exempt: only real prompt dispatch (`Inject`, auto-trigger, auto-queue) is gated, while the supervisor control methods (`Clear`, `Stop`, `Restart`) and read-only methods (`State`, `Pid`) bypass the gate, so `agent-doc session clear` / `session interrupt-clear` can stop or clear a proof-`Failed` session without `kill -9` (`#codex-capability-proof-unrecoverable`).
- `### Re:` response headers must use the resolved model short name for attribution (for example `gpt-5`, `opus-4-7`), never the harness label (`codex`, `claude`). The agent authors the model and local timestamp from the preflight contract; strict closeout canonicalization preserves an already-valid attributed/timestamped heading byte-for-byte through the production write path.
- Bundled skill/install content is part of the external contract: Claude/Codex/OpenCode hot-path instructions must render from one shared source surface, with differences limited to harness-specific invocation wording and frontmatter description. Harness installs must write trigger-scoped managed skill files (`.claude/skills/agent-doc/SKILL.md`, `.codex/skills/agent-doc/SKILL.md`, `.opencode/skills/agent-doc/SKILL.md`) and must retire old generated root `AGENTS.md` / `.codex/AGENTS.md` copies instead of refreshing them as always-on mirrors. `audit-docs` must fail generated managed skill surfaces that carry agent-doc managed frontmatter but no longer match the running binary, and must fail retired generated `AGENTS.md` surfaces until `agent-doc skill install` migrates them away. `audit-docs` must also compare every installed runbook bundle to the running binary: a stale runbook, a missing runbook, unbundled Markdown in a managed harness runbook directory, a surviving retired `.codex/runbooks/` mirror, and drift in a directory listed under `skill_runbook_mirrors` are all release-blocking. `make check` runs `audit-docs`, because the release process runs `make check` and an audit only reachable from `precommit` cannot gate a release. Without an explicit `--root`, submodule-local audits check both the git superproject install root used by normal release installs and the submodule checkout itself — `skill install` resolves to the superproject, so submodule-local copies are otherwise touched only by `release-version` and never content-checked; explicit `--root DIR` checks generated surfaces under `DIR` exactly. `release-version` projects the version into bundled skill *sources* only; installed copies are the installer's output, refreshed by `skill install` (`--root DIR` targets an explicit root). Custom root instruction files that do not look agent-doc-managed remain user-owned. Filesystem mtime freshness is advisory for agent-doc audits; source-only timestamp changes may be reported, but generated instruction surfaces are release-blocking only when the rendered content differs. The shared Claude/Codex/OpenCode manual-repair instructions must distinguish adding a missing user prompt from repairing a missed assistant response, use `agent-doc write --commit <file>` for the missed-response path, and not stop after bare `agent-doc write`. The repo-local Codex plugin manifest must stay schema-valid: it must not point `skills` at Claude install paths such as `.claude/skills`; if it exposes Codex skills, the manifest path must resolve to a real plugin-root `./skills/` tree.
- The optional `skill-harness` integration is owned by the focused `agent-doc-skill-harness` crate, never by `agent-doc-core` or by `skill-harness` itself. Its `AgentDocSkillHarnessPlugin` detects the supervised `AGENT_DOC_SESSION` marker at priority 100, resolves `<name>` to `.agent-doc/plugins/<name>/SKILL.md`, and is installed into a consumer registry through `register_agent_doc_plugin` (or `registry_with_agent_doc`). This path is distinct from Agent Doc's own harness bootstrap skill paths.
- Reusable authoring runbooks and OKF concept bundles shipped by `skill install` are part of that same contract. If `runbooks/split-spec-files.md` or `okf/index.md` is referenced from the shared instruction surfaces, it must be bundled into installed harness resources and its ownership rule must stay harness-agnostic across agent-doc-managed surfaces while leaving custom root instruction files opt-in unless they still match the generated baseline.
- Route readiness/trigger acceptance is a binary responsibility: pane prompt detection must be robust to shell startup noise and must wait for actual prompt state rather than treating echoed command text as readiness.
- A route refused because a live editor maps superseded JetBrains plugin bytes must use the same recorded-verdict recovery ladder as preflight and attached-editor admission. Mappings moved by the atomic installer into `<plugins>/.agent-doc-jetbrains-install/backup-*/lib/` still resolve their restart verdict from `<plugins>/.agent-doc-jetbrains-restart-required`; when that marker is newer than a live owner, both route admission and an otherwise byte-unchanged plugin install must prescribe the restart immediately and must not claim that no restart is required. (`#pluginbyteidentity`, GH #257) The owner's start time is the kernel's own record, `/proc/<pid>/stat` field 22 (`starttime`, clock ticks since boot, parsed after the last `)` of `comm`) divided by `sysconf(_SC_CLK_TCK)` plus `btime` from `/proc/stat`; it must never be the `/proc/<pid>` directory mtime, which procfs stamps when it instantiates the inode (seconds before the read) and which made every recorded verdict look older than its process. When the start time cannot be read, the verdict is withheld and the restart-free ladder applies. Every process-age read in the workspace (this verdict, the controller reapers' freshly-launched keep window, and duplicate-supervisor retirement's pid-reuse fence) uses one shared reader, `agent_doc_fs::process_start`. (GH #263)
- Route progress/status diagnostics must also be binary-safe: when `route.rs` trims captured tmux lines for stderr/status output, it must preserve UTF-8 char boundaries so multibyte glyphs in prompt/status lines cannot panic the reroute path.
- Route trigger commands must use absolute file paths (resolved against the invoker's CWD) to prevent submodule CWD-dependent misrouting. That invariant applies to every routed reopen attempt, including post-restart retries after an admission projection stays unchanged; once route has resolved the canonical path, later retries must not fall back to `file.display()` or other caller-relative renderings. When a tmux pane's CWD is narrowed to a submodule root and the same relative path exists in both the main repo and the submodule, a relative path would resolve to the wrong file.

- A stale JetBrains plugin warning must resolve package generation and install state from the live IDE's mapped JAR. A mapping under the installer's deleted `.agent-doc-jetbrains-install/backup-*/lib/` swap tree retains the same IDE data-root identity as the replaced canonical plugin tree, so the warning must inspect the replacement package now on disk and prescribe restart-only guidance when that package is current.
