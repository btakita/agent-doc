**STRIKE BUG FIXED in #zwn5 (agent-doc submodule c5194baf, 0.34.0+).** The binary now treats an operator-pinned bare id head (`:round_pushpin: [#ktw8]` / `[#ktw8]` / `#ktw8`) whose id names a tracked `agent:backlog`/`agent:review` item as an id-backed directive, NOT a synthetic/preset head — so a `### Re: #id` log-check heading no longer strikes it (`response_targets_synthetic_queue_head_id` in write.rs bails). Confirmed live 2026-06-10: finalize logged `[queue] kept head #ktw8 because the response did not record a completion outcome` and the head stayed pinned. So steps 1-3 below (wrong strike → session-check INTERRUPT → snapshot-lock → `reset --from-current --preserve-session` recovery) should NO LONGER occur for tracked-item heads; if they do, the binary predates c5194baf. The "don't auto-loop operator-drive heads" guidance still fully applies (the skill half).

**REGRESSION (2026-06-10, 0.34.0): the #zwn5 protection is DEFEATED by free-text appended to a bracketed id head.** When the operator forces a head as `:pushpin: [#dsqa]. force run` (id-in-brackets PLUS trailing prose), finalize classifies it as synthetic/answered and STRIKES it despite `#dsqa` naming a tracked backlog item — `[queue] consumed: ":pushpin: [#dsqa]. force run"`. So #zwn5 only protects a *clean* id head. Two follow-on traps observed: (a) `pending_done_guard` fires at finalize ("response appears to complete pending #dsqa") — the bare marker `<!-- no-pending-done-guard -->` (exact, no `:`-annotation) suppresses it; (b) every subsequent `agent-doc write --commit`/`finalize` recovery attempt CONSUMES THE NEXT forced head (#q6js, then #ktw8…) and errors, churning. **Cleaner recovery than reset+`agent-doc commit`:** the response is already at HEAD via content_ours auto-recovery — DON'T re-run agent-doc write. Instead `git checkout HEAD -- <FILE>` (drop the failed-write worktree drift), add `<!-- no-queue-removal-guard -->` into the committed response region with the **Edit tool + plain `git commit`** (bypasses agent-doc's consume entirely), then `agent-doc reset --from-current --preserve-session <FILE>` to align the snapshot. session-check then returns `ok committed`. Worth a #agent-doc-bug: extend the #zwn5 id-backed-head classifier to tolerate trailing free-text after `[#id]`.

Operator-drive live-verify backlog items (e.g. agent-doc-bugs2 #ktw8 destructive-/clear, #lvbremain early_ack/visible_write) that carry the `queue` attribute get auto-synced onto the go-mode queue every preflight, but the agent CANNOT complete them — only the operator drives the live test; the agent just checks ops.log for STRUCTURED markers. Historically this produced a churn/thrash loop (now fixed by #zwn5):

1. The agent's response (the log-check report) made `finalize` think the head is *answered*, so the strike heuristic consumed/struck the id-backed queue head — but the backlog item stayed `[ ]` open.
2. `session-check` then INTERRUPTED: "runnable queue head #X removed but backlog item still open ... unrun work silently dropped." (Also `pending_done_guard` fired at finalize: "response appears to complete pending #X but no `--done`" — suppress with `<!-- no-pending-done-guard -->` since the item legitimately stays open.)
3. The snapshot locked the STRUCK version, so `agent-doc commit` kept re-committing struck and refused the worktree unstrike as "post-commit local drift / manual cleanup."

**How to apply:**
- After reporting the log-check, do **NOT** auto-loop. The operator-drive head cannot progress without the operator, so `/loop` just re-serves it. Hand back with a clear "your drive needed" summary even though `queue_continuation_required=true`.
- To restore the consumed head to runnable (matches the operator's pushpin intent — keep manually-queued items pinned, see [[reference markdown_annotations]] N/A), use `agent-doc reset --from-current --preserve-session <FILE>` then `agent-doc commit` to adopt the worktree as the snapshot. A plain `agent-doc commit` will NOT pick up a worktree queue edit because the snapshot is authoritative.
- **Never** use the Edit tool to repair the queue/managed component while the route-owned IPC supervisor is active — it races your write and can corrupt adjacent text (saw `## Queue` → `## Queu` mid-cycle; the supervisor later re-converged it). Related: [[feedback_agent_doc_supervisor_self_race_finalize_block]], [[feedback_post_commit_worktree_drift_checkout_head_recovery]].

**Why:** these items are `queue`-attr backlog items by design (operator wants them prioritized), but "agent checks logs / operator drives" means the agent's turn can never close them — the queue machinery assumes a responded head is a completed head.
