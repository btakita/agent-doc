On a `session-check INTERRUPTED: cycle state committed but snapshot does not match HEAD ... snapshot_len=29441, head_len=44146 ... Recovery [queue_metadata_drift]: agent-doc commit <FILE>`, running `agent-doc commit` did NOT auto-recover — it committed the **smaller snapshot (29442)** over the **larger correct HEAD (44147)**, silently dropping 37 backlog items. (Unlike the response-loss case where `agent-doc commit` auto-recovers via `live_prompt_drift_auto_recovered`.)

**Why:** the recovery text claims "queue/status metadata only — user/response content unchanged," but when the snapshot is *smaller* than HEAD, committing the snapshot regresses HEAD. The working tree (48039, the live editor buffer) was the correct fuller doc all along.

**How to apply:** Before trusting `queue_metadata_drift` recovery, compare lengths: `git show HEAD:FILE | wc -c` vs `wc -c < FILE` vs the snapshot_len. If HEAD/working-tree is LARGER than the snapshot, do NOT `agent-doc commit` (it shrinks HEAD). If you already did and HEAD regressed: the working tree holds the correct fuller doc — `git add FILE && git commit --amend --no-edit` (when the bad commit is the repo tip), then `agent-doc reset --from-current FILE` to resync the snapshot. Verify `git diff prev-good-HEAD FILE` shows only legit additions (no corruption) first. Related: [[feedback_compaction_stale_snapshot_reset_not_commit]], [[feedback_post_commit_worktree_drift_checkout_head_recovery]].

**Variant 2 confirmed 2026-07-02 (JB buffer ALREADY holds the response; ack proof failed):** a `finalize --stream` printed `IPC proof insufficient invariant=live_prompt_drift_after_preflight` and `--force-disk` then refused on the visible-write guard (`visible editor buffer differs from expected disk state; save or discard`). Root: the JB plugin HAD applied my response patch into its buffer, but the ack proof failed so the binary never committed and refused to overwrite the (now response-bearing) buffer from disk. Diagnosis that unblocked it: inspect the per-editor live-buffer sidecar JSON (`.agent-doc/live-buffer/<stem>.<editor_id>`, has a `content` field) and diff its content vs disk — the buffer-only lines were MY OWN response (no new operator text), i.e. the buffer was the correct authoritative state (disk + response). Recovery: write the sidecar `content` to disk, verify integrity (prompt=1/response=1/exchange markers balanced), reposition the boundary marker to AFTER the response + strip ` (HEAD)` (committed-blob shape), then direct `git commit` + `agent-doc reset --from-current --preserve-session --force-disk`. `agent-doc commit`/`finalize` both refuse here ("direct response patchback without agent-doc cycle" once the cycle is closed) — direct git commit is the escape. Backlog `--backlog-add` items then need `--force-disk` too if the JB listener is `send_failed`. Also: `--backlog-add` text MUST use bracketed `[#id]`; a bare leading `#id` is silently dropped (no item added).

**Variant confirmed 2026-07-02 (stale JB cdylib buffer, NO supervisor running):** first `finalize --stream` failed `live_prompt_drift_after_preflight` + `ipc_dedupe` (JB cdylib was the ONLY IPC responder, all controller/ipc socks 0-byte dead, answering with a stale PRE-compaction buffer holding 4 dup prompts). `finalize --force-disk` correctly applied my response to DISK (CRDT ours-wins) but its COMMIT step refused on the editor guard ("live editor buffer unflushed ahead of disk" even with edit_epoch==last_synced_epoch). `agent-doc admin reload-lib` (re-announces cdylib broadcast, editor_projects=2) cleared the wedge so `agent-doc commit` succeeded — BUT that commit's `content_ours` merge REGRESSED HEAD to an OLDER compaction summary AND dropped the operator's prompt line (`#exchange-prompt-dropped-on-merge`), even though the working tree stayed correct. Recovery that worked: (1) integrity-gate the working tree (prompt=1/response=1/boundary=1/correct-compaction), (2) direct `git add && git commit` the verified working tree (write --commit refuses "empty response"; commit was tip so plain commit is fine), (3) `agent-doc reset --from-current --preserve-session --force-disk` to align the stale snapshot to the corrected HEAD, (4) session-check → ok. Add non-exchange backlog items (`--backlog-add ... --commit`) AFTER — they bypass the exchange reconcile and commit clean even with the editor still stale.
