# agent-doc bugs 3

## Status

Tracking the `claudescore-3.md` post-turn closeout-bypass bug separately from the older missed-trigger and interrupted-commit families. In this case, the last binary-owned `agent-doc` patchback committed successfully, but later edits to the active session document were recorded as `out_of_band_write` / `post_commit_local_drift` and left dirty without a new `write --commit` / `finalize` cycle.

## Backlog

- [ ] [#hookfailvisibility] A fail-closed `UserPromptSubmit` preflight is invisible to the model, so a correct diagnostic reads as "the hook did not fire". `src/preflight_hook.rs:89` writes the failure to **stderr**, and its comment gives the right reason — "stdout is injected context, and a diagnostic must not be mistaken for a cycle contract" — but Claude Code discards stderr, so the agent sees an *empty* hook result. Those are two different failures with two different remedies, and the agent cannot tell them apart. Observed 2026-08-09 on `src/haiven-dev/tasks/haiven-dev.md`: preflight was refusing every turn with `found likely direct response patchback without agent-doc cycle: ### Re: ...` plus the exact recovery command, and three consecutive turns died without the agent ever seeing it — the diagnosis only appeared after piping the hook binary's stderr to a file by hand. **Do not simply move it to stdout:** the skill fail-closes on the *absence* of the `[agent-doc] cycle contract` marker, so a bare diagnostic there risks reading as admission. Shapes that keep both properties: (a) emit a distinctly-marked refusal line — e.g. `[agent-doc] cycle contract REFUSED: <reason>` — and teach SKILL.md to read it as a fail-closed reason with the named remedy; or (b) write the reason to a known path SKILL.md tells the agent to read whenever the marker is absent. Either way, "capture the hook's stderr by hand" should stop being the only way to find out why a session will not admit a turn.

Plan: `tasks/agent-doc/plan-claudescore-3-post-turn-closeout-bypass.md`

- [ ] [#wedged-transport-false-commit] Wedged file-IPC transport yields non-provenance (false-committed) closeout with no durable fallback. Observed `boost-client/tasks/monsterrodholders.md` 2026-06-18 (CLI 0.34.3 vs stale 0.1.0 route-owned supervisor): all 14 registered `jetbrains-<pid>` editors were dead, so `file_ipc` writes loop on `invariant=no_ack recovery=retry_without_disk_write` forever and a valid response can never reach HEAD, while a prior cycle was internally marked state `committed` with its body absent from HEAD (provenance gap that then blocks every later closeout). Fixes: (1) probe editor PID liveness before choosing `file_ipc` and fall back to durable disk write when none are alive (treat all-editors-dead as not-installed); (2) gate the `committed` transition on durable-write/ack proof, never on patch-queued; (3) GC dead-PID `jetbrains-*` registration files on recycle; (4) `session restart-supervisor` for a stale-binary owner must re-exec the freshly installed binary, not relaunch the stale target; (5) first-class "clear stuck `response_captured` cycle" recovery. Manual recovery: rm dead-PID patches + `admin reap` orphan + `reset --from-current` + `write --commit --force-disk`. Plan: `tasks/agent-doc/plan-wedged-transport-false-commit-no-fallback.md`
