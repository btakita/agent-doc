# Closeout Commands

Strict write entrypoints validate free-text queue response evidence before
capture, including early stream mutation-plan capture. Preflight records the
exact selected free-text prompts in durable cycle state; the visible (`🚧`)
marker is only transient UI, so marker loss during CRDT convergence or supervisor
recycle cannot bypass the gate. A generic
completion response with no exact prompt identification is rejected with the
missing prompt and `> **Queue prompt:**` remedy. An exact answer or deferral
quote passes to the existing terminal-completion policy; selection itself never
authorizes a strike. Unselected, struck, id-backed, and foreign-exchange work is
outside this gate. The pure policy owner is `queue_closeout_guard`; no new
retry loop, cache, or state authority is introduced.

When an exact free-text quote is followed by a scoped `**Deferred:**`, the
operator-facing closeout diagnostic must say that the head remains pending
because of that deferral; it must not claim the exact Queue echo was missing.
The diagnostic also names the next executable step: resolve the blocker and
rerun `agent-doc <FILE>`. For an active `go` queue, the committed deferral is a
new continuation edge and the supervisor schedules that rerun automatically.

## Response checkpoints and sealing

`response-checkpoint <FILE>` reads a cumulative response from stdin and accepts
only semantically complete assistant response nodes. It evaluates the response
cell against the apply-time Lazily canonical document, replaces the prior
uncommitted response tail, preserves every operator prompt, and materializes the
acknowledged projection. It does not mark the response `write_applied`, consume
queue heads, apply backlog/done mutations, update the baseline, or commit.

`salient-checkpoint <FILE>` reads one complete, standalone conclusion from stdin
and upserts a cycle-scoped `Live response (not final)` exchange node. The node is
controller/CRDT materialized, never proves that queue work was answered, never
commits, and is removed by final response application, including replay cleanup.
Removal is path-independent: the controller response-cell
insertion and every patch-applying fallback (force-disk writes, retained or
captured-finalize replay, compact's active-capture compose) remove every
salient node from `agent:exchange` whenever a response lands there (an
`exchange` patch or unmatched response text), so the next committed response
also sweeps orphans left by an abandoned cycle. A write that patches only other
components leaves a live node in place. The node is binary-written protocol, so
the dialect lint gate must accept its `agent:salient-response` open and close
markers (see §2 element registry); the gate refusing it once told the operator
to "fix the directive", and hand-deleting the markers turned the live node into
plain exchange text that no cleanup could recognize.

`choice-checkpoint <FILE>` is the structured native-question adapter for that
same non-final node. It reads JSON containing only a concise public `context`, a
`question`, and 2–5 `choices` with unique `label` / `description` pairs. Every
field must be a bounded single line, protocol-like HTML comments are refused,
and Markdown punctuation is escaped before rendering. The resulting `Awaiting
developer choice` body is therefore assistant-authored display state, not an
operator prompt, queue-answer evidence, authorization, or hidden reasoning.
Repeated calls in one cycle replace the same salient node through the existing
controller/CRDT mutation. The harness must show the identical ordered choices
in its native UI and preserve the context, choices, and eventual selection in
the cumulative final response, because final response application removes the
non-final node.

`respond` is the primary spelling for the binary-owned seal transition;
`finalize` remains a compatibility alias. The seal
captures the complete cumulative response, records the durable response-cell
receipt, applies closeout mutations, and commits exactly once. Harnesses should
invoke sealing automatically at turn end; response text need not wait until that
transition to become document-visible.

This file covers binary-owned response persistence: commit boundaries, patch/write semantics, recovery, and post-write session validation.

Normative authority is the state-machine contract in
[Real-Time Workflow Authority](14-realtime-workflow.md) and
[Turn Lifecycle Authority](15-turn-lifecycle.md): Lazily is the sole attached
live-text authority; transaction state is in `state.db`; delivery uses named
socket intents and typed receipts; and file sidecars/file IPC are absent from
the hot path. Older tagged regression notes below that mention cycle, capture,
pending, live-buffer, ACK-content, or CRDT file sidecars describe removed
failure modes and must not be implemented as compatibility paths.

## Harness-neutral closeout

The closeout/write path is shared by every harness. Claude Code may enter it
from a slash-command skill, Codex may enter it from a plain `agent-doc <FILE>`
prompt plus Codex hooks, and OpenCode may enter it from its command wrapper, but
the durable response boundary is the same: parse/validate the assistant
payload, mutate the document through the write pipeline, project verified text,
and pass `session-check`.

No harness gets a private response patchback path. In particular, Codex direct
turns and the Codex Stop hook are recovery/backstop inputs to the same
`finalize` / `write --commit` machinery; they must not commit console text,
full-document transcript dumps, or editor `fullContent` replacements outside
that machinery. Harness-specific code may choose how to launch, resume, route,
or prove capabilities, but it may not change the closeout semantics.

When a response branch is reconciled with a concurrently visible template
document, boundary markers are merge control state rather than user content.
The document-model merge must retain the response branch's boundary ID exactly
once at the terminal exchange position before the integrity gate runs; it must
not preserve the superseded live-document boundary as a second marker.

A rejected or incomplete editor receipt is transaction failure, not a partial
success. Closeout must restore the exact converged pre-write projection and may
retain the complete response capture for automatic binary retry, but it must
not leave a response fragment for operator repair or substitute an unproven
full response in the document, snapshot, or commit.

An editor receipt that is ahead of the controller canonical is not yet a
divergence (`#receiptcanonicalcatchup`). A programmatic editor apply reaches
canonical through the replica's next delta, and a replica generation handoff
(for example the library reload after `make install`) can land that delta a few
seconds after the receipt. The receipt check therefore parks on the canonical
delivery-revision edge, never a timer poll, and re-reads canonical after each
revision. Without a cell scope it accepts only exact equality, and it refuses
when the projection-observation ceiling passes or the revision stops moving.

Collision detection is cell-precise (`#cellcollide`). A response write owns
only the components its target changes relative to its baseline, plus every
component a patch names. An operator edit in a different component (the queue,
the backlog, any other named cell) while the write is in flight is not a
collision, and neither the live-prompt-drift guard nor the receipt check may
report it as one:

- The visible-write live-prompt-drift guard keeps a proven editor receipt, with
  no `ipc_proof_insufficient` / `live_prompt_drift_after_preflight` record and
  no `ipc_snapshot_adoption_blocked` latch, when every difference between the
  receipt and `content_ours` is either in a component the agent did not write,
  or a non-overlapping operator edit already merged into a non-exchange
  component the agent did write (the receipt contains the agent's delta). It
  logs `live_prompt_drift_unowned_cells_preserved` with the drifted and merged
  cells.
- The receipt check judges the receipt against canonical only on owned cells.
  When they agree, canonical is adopted (`editor_receipt_owned_cells_converged`),
  so operator edits newer than the receipt survive into disk and the commit;
  the receipt never replaces canonical. When an owned cell in canonical still
  equals the pre-write cut, the receipt is pending rather than divergent and may
  wait up to three catch-up budgets for the editor delta (a replica generation
  handoff can land it late). An owned cell matching neither side refuses at the
  ordinary budget and names the cell (`diverged_owned_cells=`).
- `#appliedresponsefold`: when the pending budget runs out and every differing
  owned cell in canonical STILL equals the pre-write cut (no owned cell
  diverged), the receipt is the controller's own patch landing (keyed by its
  `patch_id`) that the editor replica never published — programmatic editor
  mutations do not publish operator deltas. The controller folds exactly those
  owned cells from the receipt into canonical through the compare-and-swap
  boundary, keeping canonical's newer operator cells, logs
  `ipc_visible_write_pending_owned_cells_folded`, and re-verifies the receipt.
  It never folds a cell canonical changed since the cut, a duplicated
  component, or a pseudo-cell; those still refuse. Leaving the response in the
  editor but out of canonical strands the captured response and makes every
  later replay see a drifted, response-less baseline.
- `#editorbaseunblocker`: when replay of a captured response finds its
  baseline drifted and cannot prove benign drift, the printed unblocker leads
  with the editor-preserving replica re-registration
  (`agent-doc admin reregister-editor <FILE>`, or reopen the tab), which
  re-bootstraps the authority from the editor text without retiring the native
  generation that owns the open cycle. `admin reload-lib` is not this recovery:
  its anti-stranding gate deliberately defers a generation replacement while
  any attached document cycle is open, and an explicit deferred reload exits
  nonzero instead of claiming the recovery ran.
  `reset --from-current --preserve-session` resolves "current" from the
  authority and saves it over the editor, so it is offered only as the
  headless fallback.
- `exchange`, the unscoped text outside components, and the component
  structure stay strict: any difference there keeps the existing live-prompt
  handling, so a prompt or directive typed into those cells is never absorbed.
  An empty or unparseable ownership set falls back to exact equality.

A same-cell overlap still fails closed: an operator edit at the exchange tail
where the response lands, or an operator rewrite of the queue head the
response consumes.

When retained closeout recovery observes that live editor authority and disk
diverge, it retains an exact continuation keyed by the authority revision.
Editor-visible and disk projections are ordinary Sources; their equality and
structural validity derive settlement in Computeds. The resulting Effect resumes
checkpoint/commit work exactly once. Closeout sends no save, refresh, replay, or
ACK request and never polls for a receipt. If the editor changes again, is
unavailable, or its replica is absent, the continuation remains retained without
a direct disk write.

When a materialized captured finalize replays its tracked-work half before that
continuation's terminal commit, the replay inherits the continuation's commit
ownership. A captured `--done` therefore archives and removes the item in that
same replay target; the internal `pending-only` transport must not demote it to a
visible `[x]` row that the immediately following commit would make durable.

A retained Compact Exchange continuation owns the same new-cycle and terminal
closeout gates even after the response cycle is committed and any ordinary
document-write intent has settled. Until identity-matched compact settlement or
supersession, a partial native-save projection is not an unanswered document
edit and must not be admitted as the next prompt. The gate observes the existing
controller projection; it does not replay storage, poll, retry, force disk, or
mint a second continuation.

Current-document resolution follows the same rule. A live editor without a
usable controller replica remains a missing projection; disk is never promoted
to live authority and no imperative recovery command is sent. Registration,
visible state, and native persistence must propagate through the normal editor
replica lifecycle before the retained continuation becomes eligible.

After a response is committed, an editor/CRDT replica may not regress authority
to that capture's pre-response baseline. When the current authority is proven
equal to the capture baseline, the captured response is absent there, and the
same committed capture is materialized in `HEAD`, recovery must restore `HEAD`
through exact authority CAS, align the snapshot, and clear superseded deferred
intents. Any failure in this response-recovery stage aborts preflight before the
generic commit path; recovery errors are never advisory warnings.

Historical committed-capture recovery compares the editor-visible materialized
response, not the byte-exact capture transport. Patch wrapper comments and
transient control markers (including `no-pending-capture`) may be absent from
the visible document without making an otherwise complete response eligible
for replay or partial-line removal. Recovery must leave that response intact.

When `session-check` collides with a foreground closeout for the same captured
operation, it follows the exact controller-owned cycle projection. The owner
PID may be a long-lived route supervisor and therefore cannot prove that one
finalize request is still running. Terminal-cycle and request-owner-release
facts wake recovery immediately; owner release, controller reconnect, or a
bounded 30-second crashed-owner fallback retries the keyed operation once.
Foreground lease expiry remains a safety stopgap, not the normal synchronization
mechanism. A newer controller document-state edge preempts any lease-expiry
retry derived from the prior state. In particular, an identity-matched retained
delivery wake that authorizes captured-finalize handoff must trigger the next
attempt immediately rather than waiting for the superseded foreground lease
deadline.

If a route becomes stale after a turn stage's entry probe—for example, queue
convergence times out while waiting for a terminal receipt—that stage must
schedule an automatic safe-boundary editor/supervisor recycle before returning.
Stale-route detection is continuous across the turn, not entry-only.

An editor process lease protects unsaved-buffer authority; it does not prove the
plugin delivery worker is routable. Maintained plugins publish a separate
periodic owner heartbeat from the delivery execution context. Closeout may route
a canonical target only to a fresh worker heartbeat. If the process remains live
but that heartbeat expires, closeout retains the exact target, refuses disk
projection, and requests supervisor recycle at the first checkpoint with no IPC
handler in flight. An open capture-backed cycle does not defer this recycle,
because the missing delivery projection is itself what prevents the cycle from closing.

Editor-visible convergence is never proved by an empty replica set. When the
last live replica disappears during a pending delivery, settlement requires an
exact durable visible-write receipt for the target; otherwise the target remains
retained for reconnect recovery. Likewise, a failed tmux liveness query is an
unknown observation, not evidence that every actor pane died, so registry prune
must preserve its records and retry later.

Captured-finalize mutation replay must converge from every prefix already
published by the interrupted closeout. In particular, a captured backlog edit
paired with a gate accepts the item either in Backlog before the gate or in
Review after the gate, and produces the same gated, edited Review item. This
commutative recovery behavior is scoped to captured-finalize replay; ordinary
backlog edits continue to reject Review-only targets.

## commit

`agent-doc commit <FILE>`

- Commits the saved snapshot, not arbitrary working-tree drift.
- **Requires a git repository (`#commitoutsidegit`).** A document outside any git work tree has no `HEAD`, so `commit` must not report `nothing to commit: ... already matches HEAD` or exit 0. Before any snapshot is created, the boundary is repositioned, or anything is staged, `commit` fails nonzero with `commit requires a git repository so the document can reach a committed state: <FILE> is not inside a git work tree, so there is no HEAD to commit to and nothing was committed`, followed by the next step: run `git init` in the document's directory (or move the document into an existing git repository), then rerun `agent-doc commit <FILE>`. This holds with or without a `.agent-doc/` project ancestor. `compact --commit` refuses the same way (`compact --commit requires a git repository ...`) right after its integrity and lint gates and before it captures, tags, archives, or rewrites the document, instead of compacting first and then blaming a stale-supervisor CRDT replay for the missing `HEAD` image. A relative `<FILE>` is resolved against the process cwd before the check, so a document inside a repository named from a non-git cwd still commits. `write --commit` / `finalize` keep their existing `... requires a git repository ...` refusals; `write --commit` on a non-session document still skips the commit silently, and `notify` (whose commit is a side effect, not its reported result) is unchanged.
- Narrow self-heal is allowed only for agent-owned drift that preserves the redacted component structure, or for exchange-only already-committed historical response growth proven by `HEAD`.
- `agent-doc compact <FILE> --component exchange --commit` may archive finalized `### Re:` response history that is already present in `HEAD`; when non-exchange components are preserved, that exchange-only archival is not `typed_component_drift` and must commit successfully, including after the compacted exchange converges through editor IPC.
- Plain user prompts must remain uncommitted.
- If `snapshot == HEAD` but the working tree still differs, `commit` must classify that state as later local drift rather than a missed patchback.
- **Pending completion cells do not block a standalone commit (`#statussynccommitrefusal`).** `queue report-complete` publishes its binary-attested cell (`#subagentcompletionfeedback`, `specs/02-document-format.md`) to current authority without attributing it to the document baseline, and a later focused agent write such as `status set` attributes only its own delta. The staged snapshot is then exactly current authority minus the pending cells (compared with blank lines ignored, matched by keyed marker). That snapshot is a faithful forward projection of authority, not committed-historical drift: the `committed_capture` snapshot repair must not rebase it to `HEAD` (it logs `snapshot_repair_skipped ... reason=pending_completion_cells_only`). Rebasing discarded the attributed status update, after which the `snapshot == HEAD` refusal read the cell's inert `### Re:` heading as an uncommitted response and named `write --commit` with a body the agent does not own, contradicting the final status-sync checkpoint that had just prescribed `agent-doc commit`. With the snapshot intact, the commit absorbs the binary-owned cells as a safe out-of-band exchange mutation and lands them with the attributed change, exactly as the next preflight's document-only auto-commit would; `HEAD` then equals current authority. The `snapshot == HEAD` refusal `the working tree has response-bearing exchange edits that are not committed` also excludes structurally attested cells that `HEAD` lacks. A cell whose body was edited is no longer attested and still counts as response-bearing drift.
- If `snapshot == HEAD` while an active response capture still exists, `commit` must prove that the captured response body is present in the staged snapshot/`HEAD` before closing the cycle as already committed. A prompt-only `HEAD`-current snapshot with a missing captured response must fail closed and leave the cycle at `response_captured` for `agent-doc write --commit <FILE>` replay instead of logging `commit_already_current`.
- When the editor endpoint has crossed the unregister threshold and controller authority reports zero live replicas, the shared retained-write verdict names `agent-doc commit <FILE>` as the stranded-write recovery. That command must terminate coherently: if controller-authoritative current text contains the exact durable captured response, the staged snapshot does not, and adopting current would consume neither a fresh unanswered prompt nor unproved typed-component drift, `commit` checkpoints that exact authoritative cut and continues normal staging. The recovery is allowed even when generic IPC snapshot adoption was blocked, because capture identity supplies the missing proof; it logs `commit_adopted_unowned_editor_capture_authority` and preserves exact-once response materialization. If any proof is absent, commit remains fail-closed but must not prescribe itself again: the durable same-capture resume transition is the remedy. This path never asks the agent to resend the response, force disk, recycle the controller, or reload an editor.
- Response-before-prompt repair may move content across an exchange boundary only when the response block before that boundary has the complete captured response-cell identity. A matching heading or individual signature line is insufficient: a transient boundary may bisect a multi-paragraph response, and the captured suffix after it must remain assistant-owned until retained-response replay or boundary cleanup reassembles the cell.
- If that later drift is a follow-up prompt after an already-committed response, `commit` must say the no-op is not a full closeout for the follow-up prompt, name both `agent-doc <FILE>` and `agent-doc write --commit <FILE>` as the next commands, and log the benign `post_commit_user_follow_up` marker instead of `prior_patchback_without_response_body` or `out_of_band_write`.
- If `snapshot == HEAD` and the only working-tree difference is deletion of safe escaped conversation content outside `agent:exchange`, `commit` may adopt and commit that cleanup. If the same diff also contains a fresh prompt inside `agent:exchange`, the prompt must remain uncommitted for the next cycle.
- Direct assistant patchback in the working tree without a newer binary-owned cycle must fail closed.
- Historical self-heal must fail closed if typed components such as `status`, backlog, or pending changed, or if the repaired tail would still contain a bare prompt target.
- The command serializes the staging/commit critical section with a git-dir scoped advisory lock.
- The commit tree is built from a private index rooted at the observed `HEAD` and advances `HEAD` by compare-and-swap. The session document is the only selected path; unrelated real-index entries remain staged and are never included in the response commit.
- **Concurrent-supervisor superproject write-back must serialize (`#ipc-drift-writeback-serialize`).** The git-dir-scoped commit lock is keyed on the resolved absolute git dir, so every write-back into one superproject — a submodule document's parent gitlink (`submodule pointer`) commit *and* a sibling superproject-root document's closeout — contends on the same lock. Two supervisor processes writing back to the same superproject at once cannot interleave partial commits or strand a captured response outside `HEAD`; the second waits for the first to finish its staging/commit critical section. A submodule document additionally holds its own submodule-scoped lock for the inner commit, then acquires the superproject lock for the pointer update, so the inner submodule commit and the superproject pointer update are each serialized at their own repo scope.
- For submodule-hosted documents, `commit` must carry the closeout through the parent repository gitlink commit. If the document snapshot is committed in the submodule but the parent `HEAD:<submodule>` pointer still differs from the submodule `HEAD`, closeout remains incomplete and recovery is `agent-doc commit <FILE>`.
- Successful post-commit cleanup must leave the committed blob, snapshot, and user-facing file in the same clean shape except for genuine later user edits.
- **Late answered-free-text strikes survive pre-convergence Git success (`#lateftstrikewriteapplied`).** Git may commit a materialized captured response before snapshot convergence advances the durable cycle from `write_applied` to `committed`. If the asynchronous answered-free-text projection then lands, a commit retry must accept the exact capture-owned annotated strike (or its existing exact projection variants) in either phase and commit it forward. Phases before `write_applied` have not established a visible response write and remain ineligible; unrelated typed-component drift still fails closed.
- **Late owned projections compose (`#runchildresumesowner`).** The committed cycle's own late-landing projections can converge through the live editor together after Git committed the response: the captured closeout plan's `--status` (projected with the same `update_status_content` the closeout replays), the claim ledger's reported-handoff count (`#queuehandoffstatus`), and the capture-scoped answered-free-text strike. Each single-projection proof requires the others to be absent, so a commit retry must also try their compositions (plan status, then handoff count, then the strike) against `HEAD` and commit forward when one equals the editor-authoritative document byte-for-byte, logging `commit_reconciled_late_binary_owned_projection ... parts=<a+b> capture_id=<id>`. Only a cycle in `write_applied` or `committed` whose capture belongs to it is eligible; a status the captured plan never carried, or any operator byte beside the composition, still refuses as `UnansweredEditPending`.
- **The closeout commit seals after the cycle's own late projections.** While the cycle is open, a controller `commit_document` refusal stamped `recovery=await_live_projection_then_retry_controller_commit` (the editor has not saved the converged canonical, or the answered free-text strike has no exact application receipt) is never sealed around by the local commit fallback: the closing command awaits the delivery-convergence frontier and asks the controller again, and the controller re-publishes queue authority on every ask so the strike lands in the cut it seals. A `--status` held back by a retained tracked-work transaction is landed by the closing command after the deferral converges and before the commit. Without an open cycle, on any other refusal, or once the bounded budget is spent (`controller_commit_live_projection_wait_exhausted`), the local commit runs and the composed late-projection proof above remains the backstop. Tests force the ordering through a receipt handshake, never a sleep.
- **No commit seals a cut a live editor holds text beyond** (`#clobberfollowups`). The relay commit barrier, which both the controller's `commit_document` and the local fallback (including `local_commit_then_composed_late_projection_proof`) consult, refuses while any live editor replica is quarantined and still owes the canonical projection (`crdt_commit_barrier_refused_quarantined_replica ... recovery=await_editor_roll_forward_no_commit`); that editor holds operator text the canonical lacks. The editor's projection receipt or its departure releases it. A ready barrier is still refused while the durable `editor_holds_unmerged_visible_text` record describes the document (`commit_blocked_editor_holds_unmerged_visible_text`), with that state's remedy. Both refusals write nothing. On 2026-10-27 the local fallback sealed `206af5eef3` from a canonical that lacked the operator's quarantined typing; `--force-disk` stays the explicit operator override.
- **A refused commit names its reason** (`#inflighttypinghold`). The relay commit barrier answers a verdict, not a bare `bool`, and every CLI refusal site (`write --commit`/`commit` through the live-buffer guard, closeout, and `finalize`'s best-effort commit) renders it through `commit_barrier_refusal`. A quarantined live replica prints `state=crdt_commit_barrier_refused_quarantined_replica` with `quarantined_replica_commit_remedy` (the editor holds the operator's text; do not force disk, re-send, or re-commit; run `session-check` and retry once the editor converged) and logs `commit_blocked_crdt_quarantined_replica` / `commit_editor_authority_unavailable reason=quarantined_replica`; a pending inbound cut keeps the "CRDT relay convergence is still pending" text. The controller RPC returns the verdict only to a client that asks (`{"verdict":true}` payload), so older clients and older controllers keep the `bool` contract.

## compact

`agent-doc compact <FILE> [--component NAME] [--message TEXT] [--tag NAME] [--commit] [--lint off|warn|strict]`

- `--lint` overrides only the dialect lint gate mode, matching `write --lint`. A blocking dialect finding's message names every escape that works for the interrupted command: `--lint off` on `write`/`compact`, frontmatter `agent_doc_lint_dialect: off`, or project `[lint] dialect = "off"` (GH #227).
- Before creating a checkpoint tag, archive, summary, snapshot, or commit, compact must pass the mandatory document-integrity gate: the component tree is balanced and every active id-backed queue reference names open tracked work. Dialect `off` cannot disable this gate.
- Before that gate, compact and recovery-capable session-check may canonicalize only the proven retained-replay shell: an empty `### Re:` heading whose normalized topic already has an earlier non-empty response. The repair removes only that redundant heading line, preserves every body, prompt, comment, and unrelated response byte, and records the normalization. Session-check applies it through the same CAS/realtime authority repair used for other retained replay artifacts, so finalize cannot be blocked by the exact interrupted shell that its retained capture proves how to recover. A unique empty heading or any other malformed structure still fails closed without tag, archive, document, snapshot, or commit effects.
- Once operator-facing session-check applies any proven retained-response replay canonicalization, that repair owns a narrow commit boundary: current authority and disk must be exact, normalizing the `HEAD` document must reproduce those exact bytes, and a private-index compare-and-swap commit may select only the session document. Session-check must checkpoint and re-prove authority/disk/`HEAD` convergence before reporting `OK`; after a process restart between repair and commit, the same proof must resume from `HEAD`. Unrelated staged or working-tree content remains untouched.
- A repair CAS whose exact target remains owned by the controller's retained reactive document graph is a typed projection deferral, not a failed write merely because canonical authority or disk has not reached byte equality in the same foreground stack. The repair path preserves the retained intent for its subscribed convergence effect and performs no polling, duplicate submit/republish, direct disk write, or controller recycle. Only an exact target-hash owner earns this deferral; an unowned mismatch still fails closed before snapshot, commit, or terminal session-check success.
- A semantic no-op compact must return without committing unrelated working-tree, snapshot, capture, or editor drift. Compact is never a repair/commit escape hatch for an invalid document.
- Before Compact Exchange's semantic integrity gate, compact may perform only two exchange-proven conversation-scaffold repairs. It may remove a queue-prompt quote scaffold stranded inside `agent:run` when the same canonical quote block exists in `agent:exchange` and the queue placement is isolated between queue rows or component boundaries. It may also remove one byte-identical copy of the latest complete queue-prompt/response turn welded inside `agent:review` when deletion reconstructs exactly one ID-backed `- [/] [#id] ...` row. Queue-prompt text inside fenced or inline Markdown code is documentation rather than a scaffold and remains untouched. Non-identical or multiple response copies, unmatched live scaffolds, invalid reconstructed rows, surrounding response prose, and every other ambiguous corruption remain fail-closed.
- Rewrites exchange or another component into a compacted summary/archive-pointer state.
- Template compaction owns only the archiveable region of the selected component cell. After visible CRDT convergence, concurrent edits in sibling cells (for example, queue item deletions while `exchange` compacts) must be rebased into both the live and committed projections before snapshot/commit, so neither projection is rewritten from the stale base; the committed projection is then confined to the compact-owned cell (next bullet). For Compact Exchange, the compact-owned committed content is the archiveable prefix before the live tail; operator edits after the last `agent:boundary` are an independent live cell and must survive without a same-cell failure, while the committed snapshot continues to omit that unresolved tail. The pre-write rebuild guard still proves compaction did not itself alter non-target items or markers; a post-write count comparison against the stale pre-compact document must not reject authoritative sibling-cell changes. Drift inside the compact-owned prefix remains fail-closed (`#compact-independent-cells`).
- **Compact commits only the cell it owns (`#compactabsorbsedit`).** The live projection keeps every sibling edit, but the committed projection, which becomes the snapshot baseline and `HEAD`, is re-rooted on the pre-compact snapshot at the snapshot/commit boundary: frontmatter, prose, and every sibling component (`queue`, `backlog`, `status`, scratch text outside `agent:exchange`) come from that baseline, and only the target cell's compact-owned content comes from the compaction. The retained-continuation completion applies the same confinement before its checkpoint. An operator edit outside the target that no turn has answered is therefore never committed as answered work: it stays live drift, and the next preflight still diffs it as the operator's edit, exactly as `commit` refuses to absorb it (`commit_blocked_unproved_head_current_component_drift verdict=unanswered_edit_pending`). This includes a replayed paused editor-op deletion (`#compactcachedeletetombstone`): the deleted row is gone from the live document and stays in the snapshot until a turn answers it. Binary-owned sibling drift that was not yet committed stays live too and is reconciled by the next `commit` through the retained-write ownership verdict. Confinement only applies when the baseline carries the target component; a document with no baseline keeps the compacted projection (`compact_committed_baseline_unavailable`). - **Paused editor-op reconciliation applies to compaction (`#compactcachedeletetombstone`).** Before parsing or rebuilding the selected component, normal compact replays an exact base-keyed durable editor-op epoch into its semantic input cut. The separately observed authority bytes remain the convergence compare-and-swap base, so the replayed operator cut and compact rewrite land atomically. The epoch is cleared only after the authoritative write and snapshot succeed; validation or convergence failure retains it for recovery. `--force-disk` remains the explicit bypass. Compact and `run_stream` (finalize / `write --stream`) consume the replayed epoch through one helper, `agent_doc_op_capture_io::consume_replayed_editor_op_epoch` (`#compactclearidempotent`, `#loadbudgettests`): each clear uses the causal-fence budget, and a clear that errors is followed by a state read, so an epoch that reads back absent logs `<source>_pending_editor_cut_consumed … outcome=already_absent_after_clear_error` rather than `clear_failed`. Only an epoch still projected after every attempt logs `clear_failed`. A loaded host whose actor applied the clear but answered after the budget therefore does not misreport the cut as unconsumed.
- The CLI and editor actions are command submitters only. The CP owns the full
  Compact Exchange transaction: authoritative read, archive/summary computation,
  CRDT mutation, visible projection proof, and optional commit. Its in-process
  mutation scope must not issue document or commit RPCs back into its own socket.
- A stale caller/controller binary mismatch fails before mutation and performs at
  most one reconnect/promotion retry. The command uses a compact-operation
  deadline, not the short generic controller-response timeout.
- While a retained compact continuation owns the document, a repeated request
  reuses that single-flight operation without another mutation. The CLI emits
  exactly one `pending` diagnostic containing the continuation identity,
  requested commit mode, retained-delivery state, and editor-restart recovery;
  it must not precede that diagnostic with a duplicate generic pending notice.
- After writing the archive markdown, compact best-effort upserts that archive into `.agent-doc/archive-index.db`; indexing failure warns but must not roll back archive creation.
- For exchange compaction without an explicit message, the default summary must include an archive pointer plus a digest of the compacted exchange content. It must not duplicate live `agent:backlog`, `agent:run`, or `agent:icebox` component content into `agent:exchange`.
- When compacting an exchange that already begins with a compacted `### Session Summary`, the default digest must summarize only that prior summary's compact metadata. It must not recursively embed the previous `Prior summary/context` payload or replay detailed ordered-list response lines into the new live summary.
- A response capture whose body is no longer inline because exchange compaction archived it is still materialized when the staged/committed document references a compact archive under `.agent-doc/archives/` and that archive contains the exact captured body. This evidence permits both commit closeout and later stuck-cycle reconciliation. An absent archive, an unrelated archive, or response-like text that does not materialize the capture remains fail-closed.
- `#stuck-capture-queue-echo-false-positive`: the "is this captured response materialized in HEAD" check (`response_already_applied`) matches the captured response's normalized lines as one contiguous block. Queue consumption inserts a `> **Queue prompt:**` echo blockquote (`#queue-prompt-echo-in-response`) between the response heading and body, which would otherwise break that contiguous match and make `stuck_captured_cycle` falsely warn after every queue-consumed cycle. The normalizer therefore strips the `> **Queue prompt:**` echo blockquote on both the captured-response and document side before matching.
- `#stuck-capture-compact-false-positive`: that archive-suppression check is not durable on its own — if the referenced compact archive is later garbage-collected, the same capture would re-flag as stuck and re-suggest a `write --commit` that would re-inject an already-archived response. So `preflight` first runs `reconcile_compacted_committed_capture`: when a committed-cycle capture's body is absent from `HEAD` but proven present in a HEAD-referenced compact archive, it durably marks that capture `Discarded` (the same terminal state compaction assigns via `discard_captures_for_archived_responses`) and logs `reconcile_compacted_committed_capture`. Reconciliation advances only the active capture (loaded by the cycle's own `capture_id`), is idempotent once discarded, and after it runs `stuck_captured_cycle` sees a discarded capture and returns no warning even if the archive no longer exists.
- `#stale-capture-after-compaction-blocks-route`: when compaction archives a response topic, the matching captured transaction in `state.db` is retired only after semantic containment proves the archived response cell. A genuinely pending intent remains active; there is no capture file to discard or later rediscover.
- `#stale-capture-deadlock-autoretire`: a transaction already at `WriteApplied` resumes forward through visible proof, disk projection, and commit. If Lazily current no longer contains the semantic response cell, it stays typed `InterruptedBlocked`; recovery never rebuilds live CRDT state from files or alternates closeout commands.
- `#stale-capture-captured-only-drift`: a `ResponseCaptured` transaction may retire as superseded only when Lazily current or a terminal transaction proves the same prompt was answered. The immutable response history stays in `state.db`, while `load_active` returns nothing for `Committed` or `Abandoned` cycles.
- `#queueeditcap`: a `Captured` response whose write/commit was interrupted may still be replayed when the live file drift is proven to be queue-only. The safe signature is: the captured snapshot hash still matches the current snapshot, the live file hash drifted, and replacing the live `agent:run` body with the snapshot's `agent:run` body makes the documents byte-identical after managed pipeline stripping. In that case `capture::validate_replay` refreshes only the capture's file hash, logs `capture_baseline_refreshed_for_queue_only_drift`, and lets the normal replay path apply the preserved response onto the current queue-edited document. Any non-queue drift, missing/multiple queue components, snapshot drift, or structural marker drift stays on the existing fail-closed path.
- A salient-response node is display state for one open cycle, never history. Before archiving, exchange compaction (full and `--keep N`) separates every salient node from the exchange: none is ever written to the archive or the committed target; the node owned by the still-open cycle (cycle state `is_open`) is re-appended to the live target only, so it stays visible until that cycle's final response removes it; a node owned by any other cycle is a stale orphan and is dropped. A semantic no-op check ignores salient nodes, so an exchange holding only a salient node is a no-op.
- `--commit` proves only that the compacted document state itself crossed the commit boundary; it does not also persist any later human explanation.

## write

`agent-doc write <FILE> [--commit] [--template] [--stream] [--ipc] [--force-disk] [--origin ORIGIN]`

- **The cycle baseline is binary-owned and has no CLI surface (`#respondbaselineflag`).**
  `write`, `respond`, and `finalize` accept no baseline/snapshot path argument, and
  `preflight` emits no `baseline_file` field. The pre-response baseline is the
  snapshot recorded in `state.db` cycle state (`snapshot_hash` /
  `normalized_snapshot_hash`), rebased onto `HEAD` where the explicit-baseline rules
  below require it. Instruction surfaces must never tell an agent to pass a baseline
  path; `agent-doc-workflow`, `agent-doc-turn`, `agent-doc-flow-io`, and `plan.rs`
  all assert emitted commands contain no `--baseline-file`.

- **Paused editor-op reconciliation is binary-owned.** Before the detached-base
  shortcut accepts `disk == cycle_base`, `write` replays any exact pending
  editor operations recorded against that base. The disk bytes remain the
  atomic-write expectation; the replayed operator cut becomes the semantic
  current document for response merge, snapshot construction, and queue
  reconciliation. A successful write consumes those operations. A failed
  validation or write leaves them durable for a later retry. This preserves
  operator deletion of struck queue rows across capacity pauses
  (`#pauseddeletetombstone`).
- **Projection-race queue edits keep only the newest line version.** When the
  realtime write state proves that an agent projection raced the editor, a
  single snapshot-authored free-text queue line immediately followed by one
  live-only strict extension is one in-place edit, not two queue items. The
  queue policy owner replaces the stale baseline version with the completed
  text before semantic response rebasing. Two fresh prefix-shaped items, two
  versions already authored in the snapshot, duplicate snapshot multiplicity,
  multiline entries, and id-backed heads remain distinct. Without the existing
  projection-race evidence this normalization is never applied.
- A session-document response requires `finalize` or explicit `write --commit`. Bare/non-committing `write`, including `write --stream`, fails before stdin, response capture, document mutation, queue mutation, or lifecycle advancement; partial response checkpoints may exist only in recovery sidecars.
- Strict response placement, answered queue-head removal, backlog/review/done mutations, snapshot publication, and commit are one transaction. A failure before terminal proof must not expose a response prefix or mark a queue head consumed. `AlreadyApplied` is valid only when the visible document proves the exact complete expected final response from this transaction.
- Every tracked-work flag in one closeout is evaluated against one virtual
document transaction. Removes/resolves and ungates precede additions/edits that
depend on them; semantic validation completes before the primary document or an
external done archive is published. Any tracked-work error publishes none of
those projections, and the MCP surface preserves the complete causal error
chain needed to diagnose the rejected envelope.
- Done-id queue marking is per semantic queue item, not all-or-nothing by raw occurrence count. If the live document contains extra duplicate queue occurrences that are absent from the preflight snapshot, closeout must still mark every independently matched snapshot occurrence and retain the unmatched live occurrences for later reconciliation; a count mismatch is a recovery warning, not permission to skip all snapshot-side progress.
- Parses `patch:*` blocks from stdin, applies them against the baseline, merges with current disk content when needed, and saves snapshot/CRDT state.
- In strict template mode, a response with no parsed patch blocks is rejected before response capture, pending-operation mutation, queue consumption, or document mutation. Template, stream, and IPC routes run this same marker-and-heading guard before capture, including retained-recovery calls that set `allow_replace_pending`. Both `<!-- patch:exchange mode="append" -->` and `<!-- /patch:exchange -->` are required. Append-mode compatibility may still accept plain response text, but strict closeout never guesses that omitted markers meant an exchange append. Binary-owned replay may transiently translate retired `agent:patch:*` markers only for an already-durable, complete, marker-only exchange response; the stored capture and visible document remain unchanged until the canonical replay succeeds.
- Strict closeout normalizes a fully escaped one-line exchange patch before response-heading canonicalization only when the input has no physical line endings and decoding literal `\n` / `\r` sequences proves exactly one complete `patch:exchange`, no unmatched text, and a real `Re:` heading. This prevents shell-quoted response markdown from landing as visible escape sequences under a synthetic `### Re: Response` heading. Already-multiline responses, ambiguous one-line prose, and even backslash runs that represent literal escape examples remain byte-exact.
- **A turn that prints a subagent report still prints the consolidated report (`#consolidatedreport`).** The end of the turn prints both into `agent:exchange`. The subagent report stays. A subagent report is a structurally parsed blocking `[#subagent-operator-request-<unique-id>]` packet (`#packettodo`) or a binary-attested subagent completion cell (`#subagentcompletionfeedback`). The consolidated report is present when the response has coordinator prose before the first of those reports, a real `### Re:` heading other than the synthetic `### Re: Response` heading and other than a completion heading, or a `queue_worker_binding:` line. Trailing worker detail after a report that opens the response — publication notes, commands, tests — is not the consolidated report. Closeout refuses that response before capture and before tracked-work mutation, leaving the turn open and writing nothing. A response that contains both is written in full. A response with no subagent report is unchanged, including an ordinary closeout under the synthetic `### Re: Response` heading. Coordinator prose before a blocking packet, as in an existing `#packettodo` closeout, still lands.
- Attached documents use typed editor intents over the PID-scoped socket and Lazily receipts. Detached documents use the explicit `DetachedDisk` authority. Transport availability never changes which source is current.
- `--force-disk` applies to the full strict closeout boundary: response placement, queue consumption, done-id queue marking, snapshot updates, and commit. A forced recovery must not place the response directly and then re-enter editor convergence for queue consume, because that strands the answered head active after the visible response is already on disk.
- A response-only patchback containing exactly one append exchange is one idempotent semantic cell add against Lazily current, not a whole-buffer finalize merge. The intent may contain ordered assistant response headings but no operator prompt nodes. Operator prompt nodes are retained, queue deletions from newer generations remain deleted, and the boundary is canonicalized to one terminal marker. The controller records `ResponseCellAdded` and the write-pipeline phase in `state.db`; before commit it requires matching `ReplicaAccepted`, `ReplicaVisible`, and `DiskProjected` proof. A zero-member editor state retains the same intent and waits for re-registration; it is never vacuous delivery proof.
- Socket acceptance is not response proof. The Lazily visible receipt must match the intent, generation, causal frontier, and expected response body before the pipeline advances. Missing or mismatched proof logs the exact invariant and leaves the intent at its recorded phase.
- Repeated socket timeouts do not elect another transport. The controller applies bounded backoff and re-registration to the same PID-scoped endpoint and intent. If the document becomes genuinely detached, the authority resolver may choose `DetachedDisk`; an attached document never falls back to a file or direct disk write.
- **Typed closeout recovery instruction (`#closeout-repair-churn`).** The scattered "try `finalize` / `write --commit` / `commit`" recovery chain is collapsed into one classified state with a single recovery command. `flow::closeout::classify_closeout_recovery_state` maps current durable intent, Lazily visibility, disk projection, and commit evidence to a typed state including `blocked_capture`, `queue_metadata_drift`, `recovery_projection_visible_drift`, or `unsafe_user_content_drift`. `session_check::closeout_recovery_hint` renders exactly one next action. A `blocked_capture` names `agent-doc repair`, never a response write: repair saves the payload under `.agent-doc/repair-blocked/`, retires the invalid capture, and abandons the poisoned cycle so a fresh admission can answer the still-visible prompt. `direct_response_patchback` is detected via response-specific evidence before generic drift; `nested_parent_pointer_stale` is detected when the session document is clean but the parent repository pointer lags. `duplicate_committed_response` (`#closeoutduplicatedcommit`) wins over `direct_response_patchback` when the current document authority carries more copies of a response block than `HEAD` (compared modulo binary-owned decoration, `committed_text_integrity::added_response_copy`): the extra `### Re:` heading is a copy, not a patchback, and the patchback remedy `write --commit` refuses a response already in HEAD. Its single recovery is `agent-doc dedupe <FILE>`, then `agent-doc commit <FILE>`. Like the other `commit`-naming states it absorbs the visible document, so it is replaced by the steering-preserving recovery while an operator prompt is pending. The guidance must terminate (GH #131): every state names a command that is executable in the state it describes.
- **A retained owner verdict supersedes its lease snapshot (`#closeoutownerterminal`).** When a Stop hook waits on an exact keyed closeout owner, observes its release, and performs the one allowed exact resume, the resume result stays typed. `Committed`/terminal results re-inspect the session, retryable or state-edge results remain a controller-owned wait, and `NeedsOperator`/unlandable results surface their exact reason and recovery. A terminal operator verdict must never be collapsed back into the stale "owner still in progress; wait" message that preceded the release.
- **Committed-response replay refusal terminates (`#closeoutduplicatedcommit`).** When `write --commit` / `finalize` is handed a response that is already committed in HEAD while the cycle is `committed` (`baseline_replay_rejected ... response_already_in_head`), the refusal says the work is durable and that there is nothing to replay. It never tells the agent to run `preflight` and retry: that reopens a cycle and re-applies the committed response, which is the duplicate the gate prevents. It names `agent-doc dedupe <FILE>` then `agent-doc commit <FILE>` for a visible extra copy, and `agent-doc session-check <FILE>` otherwise. The other refusal reasons (`empty_response`, `no_head_baseline`) keep the reopen-and-retry guidance.
- **Closeout recovery action decision (`#smcloseoutdecision`).** The classified state above feeds `flow::closeout::CloseoutRecoveryDecision`, the policy boundary route/JB/write/repair code should consume before deciding what to mutate or surface. Outcomes are `AlreadyCommitted`, `ReplaySafe`, `RetireStaleCapture`, `RefreshRecoveryProjectionsFromVisible`, `QueuePromptForAfterCloseout`, and `Blocked`. `RefreshRecoveryProjectionsFromVisible` is cold recovery only; it never becomes a current-document authority or delivery transport. A routed/JB prompt with prompt context maps to `QueuePromptForAfterCloseout`, so the prompt is queued behind the unresolved closeout rather than typed into the active pane.
- **Route closeout-block consumption (`#smrouteconsume`).** Routed/JB pre-dispatch drains must preserve the `CloseoutRecoveryDecision` returned by the policy boundary through their wait/fail branches. Active queue heads may wait behind an unresolved closeout, and terminal route failures may surface only the typed `closeout recovery ...` reason with state, missing proof, and recommended command; raw captured-response baseline, snapshot, or capture replay errors are evidence inputs, not route-facing blocker text.
- **Closeout recovery mutation primitive (`#smrecoverymutate`).** Any recovery path that mutates a recovery projection, visible markdown during restore-from-HEAD, retained intent, or closeout state must go through `flow::closeout::apply_closeout_recovery_mutation`. The primitive logs `closeout_recovery_mutation file=<path> action=<action> reason=<reason>` and is the single place that implements reset-from-visible, restore-from-HEAD, safe queue-only baseline refresh, and retained-intent retirement. Policy remains outside this primitive: callers must first prove the relevant `CloseoutRecoveryDecision`, queue-only replay condition, supersession proof, or metadata-drift authority.
- **Transition table coverage (`#smtransitiontests`).** The closeout recovery policy table is test-owned at three levels: pure decision-table tests over every `CloseoutRecoveryState`, a property-style integration test that generates prompt-context and supersession-proof combinations, and SimWorld scenarios for queue edits during capture/write fragmentation, stale compaction/full-content sources, stale/sidecar receipt proof, already-applied receipt recovery, and JB `Run Agent Doc` during open closeout with and without prompt context. New closeout states or decision variants must update all three layers.
- **Closeout recovery evidence (`#smcloseoutevidence`).** `flow::closeout::gather_closeout_recovery_evidence` reads Lazily current generation/hash, the active `state.db` transaction, semantic response-cell presence or supersession, queue-tombstone progress, disk/HEAD projection status, editor identity/capabilities, and controller freshness. The typed `CloseoutRecoveryEvidenceRecorded` fact is reusable only while its observed Lazily generation still matches. Callers extend this seam instead of rereading disk or inventing lifecycle state from snapshots, logs, or cold recovery files.
- **One-command recovery apply with authoritative-side determination (`#recursive-repair-apply` / `#recovery-drift-authoritative-side`).** `flow::closeout::apply_closeout_recovery` (CLI: `agent-doc repair --apply-recovery <FILE>`) performs only an unambiguously safe recovery. `queue_metadata_drift` and `recovery_projection_visible_drift` are auto-applied only when `metadata_drift_authority` proves the direction. Queue deletion is monotonic: an item absent from the newer Lazily generation cannot be restored by an older disk or recovery projection. Distinct live continuation heads without consuming-response proof are ambiguous and fail closed.
- **Repair authority CAS and materialization proof.** Template normalization, prompt-prefix cleanup, duplicate-scaffold cleanup, and completed-backlog reap must pass the exact realtime content used to compute the repair as the expected-current operand of the authority writer. The repaired image is successful only after the realtime resolver and disk projection both equal that exact image. Snapshot publication, commit, and success output follow those proofs; a stale disk/editor projection conflict leaves them untouched and returns an error instead of whole-document merging the stale projection back into the repair. When that CAS has retained the exact target in CRDT + Lazily state but the editor owner has zero registered replicas, explicit repair may finish through the audited force-disk authority and re-prove both images. The resulting pending state must retain force-disk reconnect lineage so a stale editor buffer is reconciled against the repaired target. This exception is repair-only; ordinary editor-owned writes remain deferred.
- Lazily current must not be replaced by `content_ours`, disk, or a recovery projection when the operator added prompt-bearing exchange, queue, or scratch edits after preflight. The controller instead rebases the narrow response/queue mutation onto the exact newer current generation. An unresolved expected-node conflict leaves the intent captured and visible operator text untouched.
- Typed receipts are observations of the current lineage, not whole-buffer authority granted to transport. A first-party editor must publish `lazily_transport_receipts_v1`; missing support is an incompatible version that fails closed. Duplicate prompt/scaffold detection rejects the candidate before projection or commit and retries the same rebased intent.
- **Typing-during-closeout verification marker (`#6cmx`/`#wy0y`):** if current generation changes after observation, the path logs `finalize_typing_during_write` with intent id, expected/current generation, delta size, and response presence, then performs no mutation. The retry uses the newer Lazily current and the same intent id.
- **Late intent rejection:** Once a cycle reaches `Committed`, every delayed intent or receipt for that cycle is rejected by the durable phase and generation fence. A timeout before commit leaves the same intent in `state.db` and performs no local write. No queued filesystem payload exists to clean up or re-apply.
- **Stale-cycle response identity is body-exact.** A delayed closeout may be treated as already present in `HEAD` only when every non-empty response patch body is present there in full. Reusing a `### Re:` heading is not identity: the same heading with different prose must remain a new response and follow the ordinary captured-response delivery path.
- **Accepted conflict replay repair:** If accepting a JetBrains File Cache Conflict after `commit_success` replays a stale editor/cache payload, `session-check` must classify the state as an accepted-conflict replay when `dedupe(current)` matches committed `HEAD` modulo transient `(HEAD)` and boundary markers. The next preflight must remove the duplicate response from the working tree, save the repaired snapshot, and avoid a redundant commit because the repaired document is already in `HEAD`.
- **Dropped exchange-prompt guard (`#exchange-prompt-dropped-on-merge`):** When a user types a new prompt into `agent:exchange` while an editor holds `ipc.sock`, the visible-write candidate can carry a stale `content_ours` buffer that predates the prompt. The `live_prompt_drift_after_preflight` guard already adopts `content_ours` (snapshot stays at `content_ours`; see the concurrent-user-prompt rule), but a post-commit disk diff cannot reliably catch the loss because the editor may overwrite the disk prompt via IPC buffer convergence before `session-check` reads it. To make the data-loss class fail closed regardless of that race, the write path must **record the dropped user prompt-bearing exchange line(s) at adoption time** (the divergent candidate still carries them) into cycle state (`dropped_exchange_prompts`, ops-log `dropped_exchange_prompt_recorded`). `session-check` then runs a `dropped_prompt_guard` that interrupts when any recorded dropped prompt is still absent from the committed `HEAD` exchange, and clears the marker once the prompt reaches `HEAD` (resolved on a later cycle). The guard reads persisted adoption-time evidence, not the live disk tail, so it is immune to the editor-overwrite race. Full source-level prevention (converging the editor buffer to the merged disk content instead of re-asserting the stale buffer) remains the shared plugin-protocol work tracked under `#adoc-queue-ipc-buffer-divergence`. The same recording exists for user-authored `agent:run` edits (`dropped_queue_prompts`, ops-log `dropped_queue_prompt_recorded`, `#queue-user-edit-overwrite`), but a queue item that `content_ours` **consumed (struck `~~…~~`) this cycle** is answered, not dropped, and must count toward `content_ours` coverage rather than being recorded as a dropped user edit (`#dropqueue-consumed-falsecount`); otherwise a correct closeout that consumes a queued prompt trips a false `#queue-user-edit-overwrite` interruption.
- **Semantic-merge conflict projection:** same-node operator value wins. Each non-applied agent operation is recorded as a cycle-local `DocumentCellMergeConflictObserved` fact and projected as a conflict advisory for diagnostics/editor presentation. A new preflight clears the advisory; it is never carried forward as a request for another agent turn. The stable `MergeConflictReason` tokens remain `operator_deleted_agent_edited_node`, `same_node_operator_override`, and `operator_revived_agent_deleted_node`. Old `document_cell_merge_ack_*` ledger facts remain read-compatible only.
- **Live queue edit reconciliation (`#queueeditloss`/`#qdelipc`):** Queue identity and mutation are resolved against the selected Lazily generation. A newer current-value deletion is authoritative operator intent and remains deleted; a stale response target cannot recreate it. User-added prompts remain current and are not silently absorbed as answered work. Queue consume, done marking, and backlog mirroring use expected-node CAS within the same canonical apply transaction.
- **Monotonic queue authority (`#queue-monotonic-authority`):** `queue consume --count N` resolves one editor-authoritative document cut, plans the leading free-text prefix once, and publishes one document/snapshot mutation. It never loops through N independent authority reads or waits, because asynchronous editor projections could otherwise reselect the same logical head. Planning stops before the first id-backed head. The recovery snapshot is a projection, not a competing queue head authority: if its prefix is stale, it is rebased to the exact post-consume document queue and logs `queue_consume_snapshot_rebased`. Queue deletion tombstones are anchored to both the committed snapshot and the last observed editor-authoritative active-id frontier, so deleting a head added after the snapshot cannot resurrect it from the backlog mirror. An explicit `stop` in either frontmatter or the queue marker dominates a conflicting stale `go` and converges the other representation to stopped state.
- **Late-IPC committed-response over-application repair (`#duplicate-response-after-commit`):** A late IPC reposition / stale-patch replay can re-insert a response that already reached `HEAD` into the working tree — possibly wrapped in redundant `<!-- agent:boundary:* -->` markers and **non-adjacent** to its original (the consecutive-only `dedupe(current)` collapse misses this shape, so the generic `detect_bypassed_response_write` guard would otherwise misclassify it as a manual direct patchback and `write --commit` would dead-end with `empty response — nothing to write`). The same replay can concatenate a complete second copy of the committed document, producing duplicate singleton components and exchange boundaries before response-block classification can run. `session-check` must classify either state as a committed-response over-application: response-block replay requires identical non-response scaffold (modulo blank lines and boundary markers), the same set of distinct `### Re:` blocks as `HEAD`, and no new or lost response content; whole-document replay requires two or more complete copies whose non-empty lines each match `HEAD` after transient marker normalization. Detection compares against `HEAD` directly rather than relying on consecutive response adjacency. When recognized, the next preflight must restore the committed `HEAD` content over the working tree and snapshot (logging `late_ipc_response_overapplication_repaired`) and avoid a redundant commit because the repaired document is already in `HEAD`. Any genuine new response content, lost response content, or scaffold drift must fall through to the normal patchback guard.
- **Exchange write diagnostics and duplicate prompt repair:** Every write path that touches `agent:exchange` must append an `exchange_write_diagnostic` ops-log line with writer pid/executable, source, write mode, patch id when available, cycle id, before/after content hashes, live-exchange drift, prompt-duplication, and prompt-normalization flags. Direct disk writes, socket IPC, file IPC, and retry-only repair decisions after disabled full-content IPC attempts all participate. Final template reconciliation, visible-write normalization retry, socket/file IPC snapshot paths, and snapshot-staged commit closeout must pass through canonical duplicate-prompt artifact repair before saving the snapshot or committing. That repair removes adjacent duplicate response blocks, exact already-answered prompt tails after the latest boundary, generated post-exchange duplicate prompt comments without baseline/snapshot/current-visible ownership proof, extra copies of prompt lines that were already present in the before-content, and adjacent live prompt prefix variants; it logs `duplicate_prompt_artifact_repair` with a per-artifact report while preserving the existing narrower logs such as `ipc_prompt_duplicate_repaired`, `post_exchange_duplicate_prompt_comment_removed`, and `live_prompt_prefix_variant_repaired`. Commit pre-stage repair is narrower than response write repair: it only repairs in-exchange prompt duplicates against the snapshot, collapses adjacent prefixed/raw copies of the same prompt line, updates the snapshot only when the repaired working tree is prompt-prefix-equivalent to the snapshot, and logs `commit_pre_stage_prompt_duplicate_repaired`. It is intentionally **not** wired into the live guard yet; wiring plus drift-reproduction validation stays gated as `#bkx9` because this guard governs every closeout and a false positive would wedge all closeouts. Its known false-positive class — a single `### Re:` heading that answers `do #A` + `do #B` but names only `#A` flags `#B` — is pinned by unit tests so the `#bkx9` wiring must address it before going live.
- `#jb-codex-nochange-after-repair`: `run.rs` no-change short-circuit must not return `Clean` when the latest cycle was a committed no-response bookkeeping-only closeout (repair/reap following an abandoned recursive invocation or failed run). When `compute_run_diff` returns `None` (document matches snapshot) but `cycle_state` shows `Committed` with no `capture_id` / `response_sha256` and has bookkeeping evidence (`had_pending_mutations`, non-empty `pending_done_ids`/`reaped_pending_ids`/`pending_gated_ids`/`pending_kept_open_ids`, or `pending_added_this_cycle`), the classifier must return `Abnormal` with a typed diagnostic naming the cycle id, the last event, and the recovery command. This prevents JB `Run Agent Doc` from showing plain "No changes were detected since the last run" after a repair cycle that followed a recursive self-invocation abandonment. A committed cycle with a response body remains `Clean` regardless of bookkeeping.
- Empty stdin with no recoverable visible response and no tracked-work mutations must fail before any commit/session-check closeout attempt. It must leave live prompt drift in the working tree for the next response cycle instead of committing that prompt as a repaired assistant closeout.
- Bare session-document `write` is not a terminal success path: if it preserves a response and leaves the cycle open at `response_captured` / `write_applied`, the command must fail closed with recovery intact instead of returning success and waiting for a later `agent-doc commit`.
- `#retainedprojexit1`: a closeout whose tracked-work mutation phase fails after the response half landed must classify that failure before it renders a message. A refusal stamped `retained=delivery_projection_pending` is a **deferral**: the mutation envelope reached the editor authority and its keyed worker converges on its own, so the command reports the deferral, exits 0 without committing, and names ONLY the await-and-observe path (`agent-doc session-check <FILE>`). Half-applied framing and its resubmit remedies (`agent-doc commit <FILE>`, re-running the tracked-work half via `write --commit <FILE> --backlog-only ...`) are reserved for a cycle PROVEN half-applied — this cycle's own recorded mutations still missing from the document per `recorded_tracked_work_is_unlanded`, the same predicate `commit`, `session-check`, and the captured-closeout resume decide provenance from. When landing cannot be proven either way the classification stays on that fail-closed branch; when the mutations are provably visible the failure is reported as a projection-tail failure with no resubmit remedy, because resubmitting a landed mutation double-applies it. Classification and wording live once in `agent_doc_turn::write_ownership` (`classify_tracked_work_mutation_failure`, `tracked_work_mutation_failure_message`); no site re-authors either.

### Write-path invariants

- **Todo-id publication invariant (`#todoidcloseout`, GH #293):** after response and same-cycle tracked-work projection converge, but before any strict closeout commit, the closeout runs the authority-safe todo-id maintenance pass. Let `NewTodoRows(b, d)` be the checklist rows present in authoritative publication cut `d` but absent from the pre-write cut `b`, and `OwnId(t)` mean that row has a valid leading todo id. Then `RequiredCloseoutSuccess(b, d) => forall t in NewTodoRows(b, d), OwnId(t)`. The closeout re-reads authority and rejects publication if any new row remains id-less, so a held typing-gate row, failed authority read, or failed projection cannot defer the invariant to another preflight. The patch is initially merged while id-less, so keyed merge still uses its text identity and cannot duplicate a concurrently edited row. `--todo-add` remains preferred because it declares identity directly.

- Template/CRDT retries and IPC retry paths must adopt an already-visible response instead of appending or CRDT-merging a duplicate block, including when the user is concurrently typing new prompt text inside `agent:exchange`.
- Template/CRDT disk writes and repair replays must prove the visible file still matches the just-merged current content immediately before saving snapshots or replacing the document. A late edit in an HTML scratch comment or exchange tail is a retry blocker, not merge input that may be overwritten by the stale write.
- Final template reconciliation must run the duplicate-prompt repair before the visible document projection for direct disk, CRDT, and retained repair paths.
- Projection settlement must run adjacent response-block dedupe on the exact content it will checkpoint. If dedupe changes that content, the canonical and disk projections must converge to the same deduped document before commit.
- The commit transaction must re-run adjacent response-block dedupe on the staged snapshot content while holding the commit lock. A successful closeout must never rely on a later `agent-doc dedupe` or cleanup commit to remove a duplicate response block that was visible before staging.
- Prompt-prefix normalization for append-mode exchange comes from the shared prompt-bearing classifier, not ad hoc line-shape guesses.
- Once preflight selects a live exchange prompt target, it projects the working state as `❯ 🚧` on the target's first free-text line and `❯` on subsequent free-text lines. List items and fenced regions remain byte-identical. An ATX heading remains a heading and carries the decorations inside its text (`### ❯ 🚧 prompt`), never before the `#` syntax. The `🚧` marker is cosmetic and is removed at closeout while the prompt prefix remains (`#exchange-active-prompt-marker`). This UI-only projection is best-effort: it must never enter the durable serialized-write pipeline, create a closeout intent, or fail preflight when an editor delivery projection is delayed. A retained 0.35.0 serialized-write intent proven prefix-equivalent to its expected exchange content may be retired without a native-save proof because it carries no semantic document change.
- Recovery may also retire a historical compact/reposition intent without replay only when both its target and the current exchange are valid binary-generated compact summaries, the current archive timestamp is strictly newer, current canonical/disk/editor delivery is exact, the target hash validates, and the source/reason is one of the narrowly admitted 0.35.0 compact composition paths. Queue or exchange cells from that older target are never restored over the newer compact projection.
- Lazily visible verification and post-commit prompt-prefix repair preserve duplicate prompt-target occurrences by count; one earlier prefixed line cannot mask a later bare duplicate.
- A narrow normalization/reposition intent carries expected current-generation proof. If the generation changes, it is rebased; it is never promoted to whole-buffer authority. Failed repair leaves current text untouched and records the blocked state-machine phase for `session-check`.
- A committed cycle rejects late apply and receipt events. `session-check` may reconcile only through a new, proven canonical intent; it never restores `HEAD` over newer operator text.
- Snapshot/HEAD closeout recovery classifies the parsed tracked-work `in_progress` marker (`🚧`) as binary-owned projection metadata. A marker-only difference may auto-commit with other queue/status metadata drift, while changes to an item's id, checkbox state, task text, continuation, or surrounding prose remain user-content drift and fail closed.
- A retained compact projection is generation-fenced by durable response capture. If a later `ResponseCaptured` fact names response bytes absent from the compact live target, that capture supersedes the compact continuation and the older target is no longer publishable. An already-running publication remains guarded by exact compare-and-swap; response replay follows it in controller order. This is the compact equivalent of discarding a superseded temporary write before atomic rename (`#compactcapturefence`).
- The duplicate-content regression fixture exercises delayed intent, restart, and fresh typing. It proves that an older canonical candidate cannot overwrite a newer prompt or duplicate a response/boundary after reconnect.
- The live-typing finalize fixture replays the same scratch-comment window through accept, visibility, disconnect, reconnect, projection, and commit phases. Lazily receipts prove a narrow intent's delivery, while the current document remains the editor-owned value throughout.
- Prompt-prefix overrun protection is diagnostic-only. If a normalization cycle would apply more than `MAX_NORMALIZE_USER_LINES` prefixes, the binary must log `normalize_threshold_exceeded action=passthrough` and leave content unchanged for the typed repair/closeout path to handle; it must not force-commit the working tree from inside prefix normalization.
- The repair/redelivery transition logs are intentionally temporary high-signal observability. Keep `ipc_repair_decision`, `canonical_normalization_recovery*`, narrow-repair result logs, full-content disabled/scope skips, and duplicate-prompt counts until local full-suite verification and the tmux/CI leg have stayed green across representative socket IPC, file IPC, and disk-fallback runs. Cleanup may then reduce success-path noise, but must preserve blocked/stale proof, corruption, duplicate-prompt, and visible-write diagnostic events.
- IPC snapshot adoption runs a default-on forensic detector for the `#ipcfullprompt` corruption shape (`#ipcfullprompt-recur2`). Independently of the fail-closed snapshot guards (which protect what is committed), every socket and file IPC adoption compares the live editor buffer (the candidate, captured before the guards replace it) against the pre-response baseline and logs `ipcfullprompt_corruption_suspected` to `ops.log` — plus preserves the baseline and candidate under `.agent-doc/logs/ipcfullprompt/` — whenever a previously-committed `### Re:` response block is deleted or duplicated in the candidate. The detector (`agent_doc_document_realtime::ipc_corruption::detect_response_block_corruption`) ignores brand-new response headings and the working-tree-only `(HEAD)` annotation, and is detection-only: it never changes the adoption decision. This captures the not-reliably-reproducible editor-side full-document corruption without any manual editor debug opt-in. The adoption hook also runs `detect_duplicated_scaffold` on the candidate (no baseline required): the full-tail duplication shape — captured live in `brandon-cinquegrana.md` — copies the post-exchange scaffold (close marker + Queue/Backlog/Icebox) around an in-progress prompt, leaving two `<!-- /agent:exchange -->` markers, which the `### Re:`-keyed response-block check does not see. It flags any canonical structural component marker (counted only on its own line, so inline mentions do not inflate it) that appears more than once.
- Active IPC timeout must not commit a response at all: it leaves the queued patch/pending response for retry and logs `recovery=retry_without_disk_write`. Direct disk and repair paths that do write must still fail closed if prompt/response order cannot be proven. `agent-doc repair` must apply the same ordering repair when a pending/captured response is already visible in the document.
- `content_ours` prompt-prefix normalization must preserve committed `HEAD` prefix state before adding prefixes for new prompt targets; assistant response tail lines that already exist in `HEAD` without `❯ ` must stay bare even when a later user prompt is inserted directly below them.
- Post-commit prompt-prefix repair must use opt-in prompt-run criteria inside agent response blocks. A line being already prefixed with `❯ ` is not sufficient evidence by itself; repair may leave a response block only for an explicit normalization target or a line that independently looks like a prompt, question, imperative, or soft request.
- Explicit-baseline writes must classify live disk drift against the pre-response baseline before the response is present. If a concurrent user prompt is added after preflight but before `finalize` / `write --commit`, the prompt may enter the committed closeout only through a lazily visible-write-proven realtime candidate that also materializes the agent response. Otherwise the closeout snapshot stays at `content_ours` or fails closed, and `session-check` must interrupt with the unresolved `prompt_target` instead of treating the just-written response as an answer to that later prompt.
- The visible document recorded by `start_preflight` is the current response's application base when the cycle is still `preflight_started`, the explicit baseline hash equals the cycle's recorded `snapshot_hash`, and the visible content hash equals its recorded `file_hash`. This admits a prompt that was already visible when preflight opened into the same response snapshot. The witness is captured before pending-response persistence advances the cycle; a `response_captured` replay or any visible hash divergence after preflight keeps the older explicit baseline so later prompts remain carry-forward.
- For strict template/CRDT append-mode writes to `agent:exchange`, the explicit baseline must not be allowed to subtract committed exchange history. If the explicit cycle-state baseline lacks exchange content already present in `HEAD`, `finalize` / strict `write --commit` must rebase patch application onto `HEAD` before computing `content_ours`, IPC payload baselines, IPC snapshots, or commit-staged snapshots. Later live user drift is still compared against that effective pre-response base and can only enter the closeout through lazily visible-write-proven realtime authority. The write path must log `explicit_baseline_rebased_to_head` when it takes this repair path.
- Template/CRDT writes and `agent-doc commit` must fail closed before mutating or staging when a cold persisted projection is significantly larger than Lazily's visible document and the difference is not classified as a safe binary-owned mutation. This shape indicates a manual cleanup with stale recovery evidence; recovery is `agent-doc reset --from-current <FILE>` so the state ledger is rebased from the current visible markdown without creating or electing another live document authority.
- **`#exch-intermix` auto-recovery exception:** the larger-snapshot fail-closed above has one narrow binary-owned recovery. When that wedge is the benign `live_prompt_drift_after_preflight` closeout race — the IPC drift guard already adopted `content_ours` as the snapshot this cycle (`ipc_snapshot_adoption_blocked`), the response fragmented out of the visible file, and the snapshot provably owns every prompt-bearing `agent:exchange` and `agent:run` user line still on disk (no disk-only prompt target, and every recorded `dropped_exchange_prompts` / `dropped_queue_prompts` entry is still present in the adopted snapshot) — `agent-doc commit` must auto-recover the response and commit it, logging `live_prompt_drift_auto_recovered`. If an editor IPC listener is active, recovery must first send component-level `op: "replace"` convergence patches for the changed snapshot components, accept the repair only after the lazily visible-write receipt matches the adopted snapshot modulo transient markers, and log `[jbstalecache] editor_convergence_succeeded` plus `transport=editor_ipc`. If the listener is active but editor convergence is unavailable, rejected, missing visible-write receipt, or mismatched, the binary must log `[jbstalecache] auto_recovery_disk_write_blocked ... reason=editor_ipc_unconfirmed` and fail closed instead of writing behind the editor. Only when no editor listener is active may the binary use the direct working-tree write, logging `transport=disk_fallback`. The recovery is automatic data mutation, so it fails closed (leaves the existing larger-snapshot guard to error) the instant any genuine post-preflight user content on disk is absent from the snapshot; it never auto-recovers a snapshot that would drop a user prompt or queue item. A `dropped_exchange_prompts` / `dropped_queue_prompts` entry does not by itself block recovery: the drift-time record compares the divergent IPC candidate against `content_ours`, so a queue item consumed (struck) this cycle, or a prompt `content_ours` preserved, is recorded as "dropped" yet survives in the adopted snapshot. Only a recorded dropped prompt whose text is genuinely absent from the snapshot is real loss and keeps the fail-closed guard (`#exch-intermix-falsedrop`). `#closeoutduplicatedcommit`: the recovery appends a snapshot response block only when the live document does not already hold it — neither as a contiguous normalized substring nor as a block with the same `response_block_signature` (modulo binary-owned echo lines, `❯ ` prefixes, boundary/`(HEAD)` markers and blank lines). A recovery target that would carry more copies of any response block than the document it is rebased onto (`committed_text_integrity::added_response_copy`) yields no target. On 2026-10-15 (cycle-1792108257994) the response had already materialized, the binary had embedded a done-id echo under its heading in the live document only, and the containment check called the response missing; the editor convergence re-appended a whole second copy that a later repair committed. `#jbstalecache`: the `live_prompt_drift_auto_recovered` ops.log marker must record `ipc_listener_active=<bool>` and `transport=<editor_ipc|disk_fallback>`, and with the current contract `transport=disk_fallback` implies `ipc_listener_active=false`.
- When an explicit-baseline template/CRDT write answers a prompt target that was typed as raw text inside `agent:backlog` / legacy `agent:pending`, the write path must remove only those newly-added prompt-target lines from the backlog after merging the response. Normal tracked backlog edits, backlog state changes, and unrelated concurrent non-exchange edits must remain intact.
- Concurrent non-component user edits, including markdown or HTML comment tails directly below `agent:exchange`, must remain visible in the working tree/editor buffer and stay outside the assistant closeout commit unless the user explicitly asks to commit that edit. The same rule covers compacted exchange summaries where the live prompt sits after a compacted `### Session Summary` and boundary inside `agent:exchange` while the scratch comment is being edited below the closing marker. Closeout may scrub stale post-exchange HTML comment text only when that duplicate prompt text is absent from both the pre-response baseline/snapshot and the visible current document read before the response write. If equivalent duplicate prompt residue remains as ordinary post-exchange Markdown after comment cleanup, closeout fails closed instead of guessing whether to delete or relocate it.
- Carried-forward formatting directives from historical `❯ ...` prompt blocks must be re-injected into new agent prompts when they still read as active document-level requirements.
- Orchestrate-origin template writes may synthesize a patch-free, clean single assistant response into `agent:exchange`, but patch-bearing orchestrate writes must include `patch:exchange` and must not carry unmatched text outside patch blocks. Plain orchestrate responses with transcript prompt lines, `## User` / `## Assistant` headings, multiple `### Re:` replies, or full-document component markers are invalid.
- Template writes fail closed if live conversation content would end up outside `agent:exchange`, including the inter-component gap between the exchange close marker and later components such as backlog, except for the narrow duplicate-close / duplicate-open repair shapes the binary knows how to normalize safely. A duplicated template scaffold between two exchange close markers is repairable only when the segment is pure scaffold. If that duplicated scaffold is mixed with live prompt text, the write path fails closed and logs a typed document-mutation flow event instead of moving or deduplicating that prompt text automatically.
- Template patchback shape classification belongs to `flow::document_mutation` and runs before visible document mutation in template, stream, IPC, and repair replay paths. Patch markers with no closed patch blocks are `malformed_patch`; patch blocks plus unmatched output are `mixed_output`; a patch-free response that instead carries fully-formed raw `<!-- agent:NAME -->` component blocks is `escaped_component_markers`; transcript-shaped dumps are not valid template patchbacks unless a command explicitly owns a narrow normalization path. Orchestrate-origin plain-response synthesis and malformed plain-response rejection also use this same document-mutation gate.
- `escaped_component_markers` must fail closed before any snapshot save or commit. This is the raw-template form (`<!-- agent:status -->` / `<!-- agent:exchange -->` blocks piped to `finalize` / `write --commit` instead of `<!-- patch:* -->` blocks); committing it as plain text escapes the markers into the live exchange (`#closeout-repair-churn`). The typed diagnostic must point to the supported `<!-- patch:exchange -->` form or to rerunning `agent-doc write --commit <FILE>` to absorb an already-visible `### Re:` response, and must leave the document, snapshot, and `HEAD` unchanged. Boundary markers (`<!-- agent:boundary:HASH -->`, no close marker) and markers inside code fences are not component blocks and do not trip this guard.
- Boundary markers are binary-owned. The write path removes stale boundaries, inserts a fresh end-of-exchange boundary, applies the response, and re-inserts a fresh boundary at the new exchange end.
- Exchange append replies must bind to the oldest compatible unresolved prompt block rather than skipping earlier prompts still ahead of the old boundary.
- **Prompt-edit-resilient anchoring (`#patchback-prompt-edit-resilience`).** The anchored exchange append locates the insertion point by exact match of the baseline (`original_doc`) unresolved tail against the current document — the fast path. When the operator edits the prompt between baseline capture and closeout (a typo fix, or adding/removing the `❯ ` prefix), that exact match no longer holds. Instead of failing closed (which forces manual baseline-drop + prefix-repair retries), the append falls back to **position-based** anchoring when the unresolved tail is a single prompt block: because the boundary has already been repositioned to the end of the component, the sole (possibly edited) prompt is the trailing content of the user region, so the response anchors at its end. Only the genuinely ambiguous multi-prompt-edit case fails closed, and it does so with an actionable `re-run agent-doc preflight to refresh the baseline` diagnostic rather than the prior cryptic "failed to locate unresolved prompt tail" error.
- Response-replay / stale-cycle recovery hash matching is immune to queue churn. The normalized hashes used to decide whether a **stale** `preflight_started`/committed cycle is safely recoverable neutralize the `agent:run` component body, its opening-tag attributes (for example `auto`), and the `queue_active:` frontmatter flag before hashing, because queue maintenance rewrites those on essentially every cycle independently of the response body (which always targets `exchange`/`output`). Store-side (`cycle_state`) and compare-side (`repair`) normalization must stay identical so queue-only churn produces a hash match while a genuine response-body change still fails closed. A matching hash does not itself prove a fresh empty preflight is orphaned: every empty-cycle hash-close path must first cross `STALE_EMPTY_PREFLIGHT_TTL_SECS`, unless committed historical `HEAD` content independently proves that a response already landed. This keeps the recurring `stuck_captured_cycle` symptom from wedging an IPC-owned document without closing the cycle under a response that is still generating (#adoc-queue-ipc-buffer-divergence root cause #4).
- Visible-write snapshot adoption must preserve component ownership: assistant response prose may materialize only in `agent:exchange`, while `agent:run` remains operator-owned. Before a candidate replaces `content_ours`, compare its queue against the canonical exchange; if a response line appears as a standalone queue prompt or inside a malformed multiline prompt, reject the candidate, retain `content_ours`, fingerprint the editor bad state, and redeliver the canonical projection. This guard has no one-shot bypass; `session-check` applies the same classifier as a closeout backstop.

## respond (`finalize` compatibility alias)

`agent-doc respond <FILE> [write flags...]`

- Strict happy-path closeout for session responses.
- Validates git-backed context before mutation, runs the normal write pipeline, and only enters the commit closeout after the write path succeeds or performs an explicit empty-response recovery. Pre-write guard failures must leave the document, snapshot, queue, and active cycle open for retry instead of committing an unanswered cycle, and must emit a typed FlowCore `closeout/pre_write_guard` blocked event for operator forensics. Successful closeout still fails unless the final cycle state is `committed`.
- When the active prompt is synthesized from an active `agent:run` head and the visible document itself has no queue-head diff, `finalize` must still consume the queue head after a successful write if the captured response heading explicitly targets the queue item or its `#id`. A response to an unrelated prompt already present in the baseline must keep preserving the queue head.
- Queue-head consumption must be identical across every successful closeout path, not only the strict `write_with_options` Phase 3c return path (`#queue-consume-on-stream-ipc-timeout`). Active IPC timeout or missing-proof failures commit nothing, leave the queued patch/response for retry, and must not consume the queue. Successful writes run the same consumption decision (`queue_consumption_allowed_for_response`: explicit `--done`/`--backlog-gate`/`--review-resolve`/`--backlog-edit`, synthetic/preset heading-id match, or an answered free-text head) before committing.
- A free-text queue head is answered only when the current response explicitly targets that same head, normally by carrying the `> **Queue prompt:**` echo for its text. A nested leaf's echo is its nest vector (`#nestvector`), which targets that leaf and not its ancestor labels; the bare leaf line remains an answer for that same leaf. That vector is also the submitted lineage of a nested leaf in `agent:loop`, `agent:review`, `agent:backlog`, `agent:icebox`, `agent:github`, `agent:gitlab`, and `agent:jira`; the shared path attaches the prompt tree after it as context. Historical residue may also recover from a `### Re:` topic that repeats the head's exact long underscore-delimited code identifier; ordinary headings, filenames, short symbols, prose mentions, deferred responses, generic repair/no-op responses, and responses to unrelated exchange prompts must leave the head runnable (`#qstrikework`).
- The answered-free-text-head decision must be robust to prompt-prefix normalization (`#free-text-head-consume-genuine-not-struck`). `cycle_answered_foreign_exchange_prompt` diffs the *normalized snapshot* baseline against the *live* editor buffer, and the buffer preserves `❯` prompt prefixes on already-answered prompts that the snapshot normalized to the bare form. A pure `do x` → `❯ do x` prefix flip on an already-present prompt must NOT be read as a new foreign exchange prompt — a `❯` added line counts as foreign only when its normalized text is absent from the baseline entirely (a genuinely new, unrelated prompt), never when the same text already existed at baseline in either `❯ X` or bare `X` form. Otherwise the prefix flip wrongly blocks the free-text head strike and treadmills the auto-loop. Set `AGENT_DOC_DEBUG_QUEUE_CONSUME` to log each `❯` added line and whether it was classified as a prefix flip or a foreign prompt.
- For submodule-hosted documents, strict closeout also verifies the parent repository pointer reached the new submodule commit; a best-effort pointer update failure must interrupt instead of reporting success.
- When strict closeout crosses the latency budget, it must surface phase timings for git commit, retry, cycle-state, session-check, and cleanup work in a `closeout_latency` diagnostic so operators can tell which closeout layer delayed response durability.
- When the session document moves after preflight, closeout resolves the
  transactionally rekeyed typed baseline under the current document hash. It
  must never retry or import a hash-keyed baseline sidecar.
- Empty normalization-only template payloads are invalid; the response must contain real response-body proof.
- The same pre-write pending-capture, backlog-required, and pending-done gates apply here before the document mutates.
- `--no-followups` (alias `--no-pending-capture`) is the first-class closeout declaration that the response intentionally creates no actionable follow-up work. The write runtime records it as transient captured-response evidence before the pre-write guard, preserves it across idempotent retries and pre-commit verification, and strips the marker from the visible/committed document. Agents should choose this flag on the first `finalize` attempt rather than probing help or retrying only to inject an internal guard comment.
- Referring to existing tracked work, leaving its queue/backlog items open, or releasing their claims is not evidence that this response created or mutated follow-up work. A closeout with no tracked-work mutation flags must carry `--no-followups` when that is intentional; the strict capture gate must not infer the declaration from response prose.
- `--done <id>` is a tracked-work mutation for `do #id` closeout, so it satisfies backlog-capture guards without requiring a synthetic `--backlog-add` or `<!-- no-pending-capture -->`. If the id was already reaped into canonical `agent:done`, into the repo-relative external `.done.md` archive named by `agent:done archive=...`, or recorded as resolved in the active cycle, the flag is idempotent and emits a warning instead of failing the closeout. Legacy `agent:backlog-done` and `agent:pending-done` markdown components are not accepted as completed archives; run `agent-doc migrate` to rewrite them.
- If a response appears to complete a tracked backlog/icebox item whose live line has a malformed checklist prefix, strict closeout must fail before writing the response. A damaged line such as `_- [ ] [#id] ...` is document corruption, not proof that the item is absent or complete.
- A bare `compact exchange` request blocks ordinary finalize/write closeout and must route through `agent-doc compact <FILE> --commit` instead.
  - Only exchange prose counts. A line inside a managed list component (`agent:run`, `agent:backlog`, `agent:review`, `agent:todo`, `agent:icebox`, `agent:done`) is a task entry and never a directive, whether or not it carries a bullet; this covers multi-line `---`-separated free-text queue heads (`#qcompactnoun`). The component is tracked from marker lines in the hunk context and reset at each hunk; a hunk that starts mid-component falls back to the bullet skip (`#qcompactfp`).
  - A continuation that reads as a statement about the command (a finite verb or modal such as `fails`, `should`, or a report noun such as `error`, `bug`, `issue`) is a report, not a request (`#compactfp-prose`, `#qcompactnoun`).

## repair

`agent-doc repair <FILE>`

- Repairs open `response_captured` / `write_applied` cycles, deduplicates already-applied responses, and can adopt a visible response already present in the live document when the snapshot still lags behind.
- Visible response adoption never adopts binary-attested subagent completion cells (`#subagentcompletionfeedback`, `02-document-format.md`): completion-only drift yields no orphaned response to replay, and a bypassed response beside such cells is extracted without them. The replay guard likewise never counts a completion cell's heading as a repeated or already-committed assistant heading, while still refusing a genuinely repeated response topic.
- Visible response adoption is not limited to no-cycle manual repair. If an open agent-doc cycle proves the interrupted write path already owned the response, repair adopts that response rather than reporting it only as a direct patchback bypass.
- The same repair path also handles stale `preflight_started` cycles when the hashes or safe historical `HEAD` proof make that deterministic, and it may auto-close an otherwise-empty `preflight_started` cycle after the bounded stale timeout when no response capture exists. Hash equality never bypasses the timeout for an empty cycle; only committed historical response proof can close sooner. If that stale empty cycle has unresolved prompt-bearing drift such as `do #id`, repair marks the old cycle `abandoned` without writing a placeholder response; the prompt remains visible for the next fresh preflight cycle. Recent empty prompt-bearing cycles still fail closed with retry/restart guidance instead of being abandoned.
- If interrupted-cycle preflight has an IPC dogfood diagnostic to persist, it must append that diagnostic while the recovered cycle is still open and before repair crosses the commit boundary. Repair then commits one complete recovery image; preflight must not mutate the just-committed document and force a duplicate admit/finalize cycle.
- Historical capture replay is narrow: it requires either an active capture artifact or a matching orphan prompt target in the live exchange.
- Stale captured-response recovery is not replayed indefinitely. If the captured response heading is already answered in the visible `agent:exchange`, repair discards the active capture, marks the open recovery cycle `abandoned`, preserves the capture payload for forensics, and continues from the current visible document. Unproven editor-delivery results (`no_ack` / `retry_without_disk_write` / refused direct write) still fail closed unless the response is separately proven present in the visible document or committed HEAD.
- A retained response whose `### Re:` heading the document already holds is a committed-heading replay (`#qresiduewedge`): the replay guard refuses it on every attempt, so repair parks it instead of failing closed, even when its cycle already committed. The payload goes to `.agent-doc/repair-blocked/`, the capture is discarded and its captured response retired (`committed_heading_replay_parked`), and the outcome is `blocked_capture_quarantined`. Repair also strikes each free-text queue head that replay answers and that the exchange already answers under the head's own title; a head only the parked replay answers stays live.
- The shared pending-response adapter must reject transcript-shaped or full-document-dump payloads before it appends any capture fact, regardless of which run/write/hook adapter called it. Legacy invalid captures must be parked under `.agent-doc/repair-blocked/`, retired, and their poisoned cycle abandoned by `agent-doc repair`; they must never be replayed. Patch payloads may carry only known replay guard comments such as `<!-- no-pending-capture -->` outside patch blocks, and plain progress commentary before the first patch may be stripped so the valid patch body can replay. Session-check may describe repository side effects only from cycle-owned attribution evidence; ambient `git status` dirt is omitted rather than attributed to the current response.
- No-pending repair still runs transcript canonicalization, completed-backlog reap, safe escaped-conversation repair (including the exchange-to-backlog gap case), safe duplicate-close repair, and deterministic stale-boundary repair when applicable.
- Explicit `repair` must fail closed, not print a false clean `No pending response found`, when `session-check` would still block the document after those no-pending repairs. In particular, when a committed historical patchback can be repaired from `HEAD` but later prompt-bearing user drift still remains, `repair` must surface the same interruption instead of downgrading the blocked document to `Noop`.
- A zero-replica explicit repair that performs multiple canonical refinements (response recovery, transient-marker removal, prompt-prefix normalization, boundary relocation) must settle every prior deferred target after each exact projection and preserve only the newest reconnect target. The retained merge base remains the original editor cut across the refinement chain; acknowledging the final target must leave no older intermediate intent able to resurface.
- If the editor advances after a repair candidate is composed, the repair write returns and checkpoints the canonical semantic rebase over that newer operator cut. Zero-replica recovery may project that rebased target only after recomputing and proving the same three-way merge; it must not require byte equality with the stale pre-rebase candidate or checkpoint that stale candidate.
- For git-backed docs, repair must not stop after updating the document or snapshot. The same command must carry the recovered closeout through commit.

## preflight

`agent-doc preflight <FILE>`

- Normal CLI execution publishes typed read facts (diff/baseline, queue view,
  tiers, agent model, claims, linked documents, and accretion) into one
  controller-owned per-document `Computed`, then constructs its JSON output
  from that projection. `--probe` uses the same derivation actorlessly so it
  remains side-effect free. Effect signals enforce `repair -> prior-cycle
  commit -> derived reads -> baseline checkpoint -> cycle-open`; callers cannot
  skip prerequisites, and newly inserted exhaustive effects must settle before
  the terminal gate succeeds. Cycle-open stays a durable exactly-once identity
  rather than a computed value (`#preflightreactive`).
- Runs interrupted-cycle recovery, repair, commit, claims-log drain, linked-doc inspection, diff computation, and HEAD read in one binary-owned step.
- Before diffing, preflight must not auto-compact the exchange just because the session is large or churn-heavy. Session-accretion heuristics remain advisory only, and any future automatic compaction/reload path must require an explicit `agent_doc_auto_compact` opt-in in document frontmatter or project `.agent-doc/config.toml`. When that opt-in is absent, `session_accretion.guidance` must not emit imperative `Run agent-doc compact <FILE> --commit` text that an agent could auto-execute; it must instead emit gated phrasing that names the missing opt-in and tells the agent to ask the user before compacting.
- If the pre-diff tmux layout check detects missing window index `0`, preflight attempts the base-index repair immediately in the active tmux session, re-runs the layout check after a successful repair, and reports only remaining layout issues. It must not defer this repair behind a consecutive-detection counter; when automatic repair cannot run, stderr must name the explicit repair command.
- Planning must not convert advisory session-accretion signals, including repeated no-op closeout churn, into a `compact` handoff unless the prompt or document explicitly requests compaction.
- Open cycle states are `preflight_started`, `response_captured`, and `write_applied`; `committed` and `abandoned` are terminal.
- **An ignored-path commit refusal is a final terminal (`#splicectlcommit`, GH #119, `#ignoredpathwedge`).** When the commit refuses an untracked document `.gitignore` matches, it closes the cycle as `abandoned` with `last_event=commit_refused_ignored_path` and nothing is staged. Every closeout surface treats that cycle as final: `complete_required_closeout` logs `closeout_ignored_path_terminal` and skips only the snapshot-vs-HEAD retries and the parent-pointer gate (they prove a commit this cycle cannot have), while session-check, actor closeout and the terminal proof still run; captured-finalize recovery (`session-check` effects, `repair --resume-capture`, the supervisor idle watch, the Codex Stop hook) returns `ClosedIgnoredPath` for the exact same cycle and stops retrying instead of reporting `captured_finalize_resume_waiting_for_state` for a `committed` projection that can never appear. A stale parent gitlink is never reported against such a document (see [Git Integration](09-git-integration.md)). This holds whether the commit ran in the CLI, in a recovery process, or in the project controller for a live-editor document.
- Every binary-owned frontmatter write (queue control, pipeline state, session/resume ids) goes through `frontmatter::write_preserving`, which keeps each top-level key block the write did not change byte-for-byte. When the raw region does not parse as one YAML value (an operator mid-edit, e.g. a `prompt_presets` line copied to be renamed, which repeats a nested key), the unchanged-key test compares each key's typed value before and after the write instead, so the unparsable block is still kept verbatim (`#presetrevert`). Full re-serialisation is reserved for a repeated TOP-level key or a block that cannot be attributed to one key. A document that spells the presets map with its `presets:` alias keeps that spelling across these writes (`#presetsalias`).
- The optional `agent_doc_pipeline:` frontmatter block (`agent_doc_frontmatter::frontmatter::AgentDocPipeline`, fields `run_id` / `step` / `turn_id` / `queue_task_id`, `#fm-run-id-step`) mirrors live cycle identity and step into the document for crash re-entrancy and observability. `step` is the lowercase `CyclePhase` string and round-trips unknown values; the block is ephemeral runtime state cleared at a terminal phase, never user configuration. `set_pipeline_state` / `clear_pipeline_state` mutate only that block, preserving every other frontmatter field and the body. The read-side is wired (`#fmrunid-wire`): `CycleState::to_pipeline()` derives the view from the authoritative cycle-state (`run_id` = cycle id, `step` = lowercase phase, plus `turn_id` / `queue_task_id`), and `preflight` surfaces it as the `pipeline` output field — preferring live cycle-state and falling back to the document `agent_doc_pipeline:` block only when no cycle-state exists (cycle-state wins on conflict). The mid-cycle frontmatter *writes* at each phase transition remain deferred (`tasks/agent-doc/plans/reentrant-finalize-pipeline.md`) pending a resolved block lifecycle (the plan's "committed at finalize" vs. "clear at terminal" must be reconciled) plus diff/session-check managed-state handling.
- If `route --dispatch-only` saved a busy-actor queued dispatch into the snapshot (`queue_active: true`, `agent:run`) but that snapshot has not reached `HEAD`, preflight must commit the saved route-owned snapshot before diffing. Later visible user edits on top of that queued snapshot remain unstaged and must be surfaced as the next prompt diff; the recovery must not absorb those edits into the queue snapshot commit.
- Boundary-only / `(HEAD)`-only churn is normalized back to `no_changes`.
- If the file diff is empty but the active harness prompt still contains body text after `agent-doc <FILE>`, preflight synthesizes an in-memory diff from that prompt body.
- **Chat-originated prompts (`#chatprompt`, GH #125).** A `UserPromptSubmit` prompt that is not an `agent-doc` invocation, not a harness slash command, and arrives in a harness session already bound to a document is a chat prompt for that document (`agent_doc_prompt_contract::chat_prompt::chat_prompt_text`). The hook (Claude Code and Codex) records it in a per-session ledger (`chat_prompt_session:<hash>` runtime state, newest 8, deduplicated) and emits `[agent-doc] chat prompt for session document <FILE>` telling the agent to insert it into `agent:exchange` and persist through `respond` / `write --commit`; a referenced `prompt_presets` key is resolved to its body. On the next admitted trigger for the same document, every ledger prompt whose non-blank lines the document body (frontmatter excluded) does not carry is **carried by the cycle**: the hook passes them to preflight on the request itself (`PreflightOptions::chat_prompts`; preflight's reads may be served by the project controller, which cannot see harness session state), and the contract lists them in `chat_prompts`, appends each as a `prompt_target` to `user_intent_prompt_changes` (after the active-prompt marker projection, before the queue-preemption decision, so a chat prompt preempts the next queue head like an exchange prompt; it never counts as an unresolved document prompt for owner-pane self-invocation), reports `no_changes: false` with `diff_type: "chat_prompt"` when the document itself did not change, opens the cycle, and records the prompts in the cycle state (`CycleState::chat_prompts`, carried across a re-entrant preflight) and its `prompt_targets` checkpoint, which `plan` reads back as `prompt_targets` for an open cycle. An `[agent-doc] unrecorded chat prompt(s) for this document` notice still precedes the contract, so the contract marker stays the trailing seal. The ledger is cleared after an admitted contract carried the prompts (a refused admission keeps them), so each chat prompt is carried by at most one admitted cycle. **Ledger hygiene:** entries are `{text, noted_at, turn_id, surrogate_id}` (older entries without `surrogate_id`, including a 0.35.448 bare-string ledger, are assigned one on read), and every read or write prunes an entry that the classifier no longer calls a chat prompt (retroactive purge of harness envelopes recorded before the envelope filter), that is older than `CHAT_PROMPT_LEDGER_TTL_SECS` (6h), that the document records (any recording; both identified and legacy `> **Chat prompt (#chatprompt):**` lines count), or that a committed response cycle opened at or after it closed out (the agent's response for that harness turn); the newest 8 survive, and an emptied ledger is deleted. **Prompt identity:** each new `agent:exchange` record uses the hook-issued compact shape `> **Chat prompt (#chatprompt:<id>):** <verbatim>` (`agent_doc_prompt_lines::chat_prompt_record_prefix`). The 12-hex surrogate is stable in the ledger and collision-checked against live ledger entries and existing records in the document, so repeated `#chatprompt` records are individually addressable. Parsers continue to accept the legacy ID-less shape, and ordinary cycles never rewrite historical records; migration is opportunistic only for pending legacy ledger entries. **Closeout accounting:** a no-op commit of an open cycle that carries chat prompts logs `commit_chat_turn` to `cycles.jsonl` instead of `commit_noop`; `session_accretion` counts it as a committed cycle and never in `recent_noop_closeouts`. **Closeout enforcement:** when the latest cycle is `committed`, carried chat prompts, and the current document has no record block (`chat_prompt::chat_prompt_record_present`: a record line plus its `>` continuation lines containing every non-blank prompt line) for one of them, a clean `session-check` prints `[session-check] warning: chat prompt not recorded (#chatprompt)` with each prompt and the repair (pipe a response that begins with the record line through `agent-doc respond <FILE>`, which reopens a committed cycle from HEAD) and logs `session_check_chat_prompt_unrecorded`; it is a warning, never a failed closeout. A pure chat turn (no trigger, no open cycle) records its prompt the same way: `respond` on a committed cycle auto-reopens a fresh one from HEAD and commits the record with the response. Harness-injected prompt bodies are never chat prompts (`chat_prompt::is_harness_generated_prompt`): a prompt whose trimmed text starts with `<task-notification>` (a background subagent's completion event), or that is nothing but harness envelope elements (`<system-reminder>`, `<task-notification>`, `<cross-session-message …>`, `<command-message>` / `<command-name>` / `<command-args>`, `<local-command-stdout>` and kin) is ignored, and envelopes around real operator text are stripped from the recorded prompt. Steering (`#midturn-steering`, closeout, `session-check` pending steering) strips a new record line and every contiguous `>` continuation line before diffing, including a quoted blank separator that also existed in the baseline, so a multi-paragraph agent record remains one prompt and is never reported back as `address_now` operator steering.
- **Subagent hand-backs are not operator intent (GH #139).** A Codex collaboration report framed as `<agent-message …>…</agent-message>` is harness-generated model output. The chat-prompt hook does not ledger it, emit operator-prompt prose for it, or add it to `chat_prompts` / `user_intent_prompt_changes`; therefore it cannot preempt an active queue drain. When any genuine operator prompt does preempt the drain, preflight derives the cycle checkpoint from the same selection verdict as the contract: an unselected synthetic queue head contributes neither `queue_task_id` nor `expect_done_or_gate_ids`, so `session-check` never requires closure of work that `selected_queue_prompts` omitted.
- **Steering absorbed into a closeout commit (`#steerbaselineabsorb`).** Operator text typed while `respond` / `write --commit` is committing can land inside that commit. The turn-boundary steering report compares against the cycle's preflight baseline, so it still announces the item as a new operator prompt for the next cycle, while the next preflight diffs the editor against the commit and would report `no_changes: true`. Whenever a turn-boundary report is acknowledged (`respond` / `write --commit` terminal output, post-commit `session-check`, the hook after close) or `session-check` reports `steering pending`, each exchange item whose every non-blank line is already a whole line of the committed baseline (snapshot, else HEAD) is persisted in a per-document ledger (`state.db` runtime key `midturn_steering:absorbed:<doc>`, `agent_doc_session_check_io::absorbed_steering`). The next preflight carries every pending entry like a chat prompt: the contract lists it in `absorbed_steering_prompts`, appends it as a `prompt_target` to `user_intent_prompt_changes`, reports `no_changes: false` (with `diff_type: "absorbed_steering"` when the document itself did not change), and records it in the cycle state (`CycleState::absorbed_steering_prompts`, read back by `plan`) and its `prompt_targets` checkpoint. An entry is consumed once an admitted cycle carried it, or once a later committed response cycle (started at or after the entry was noted, and not the cycle that absorbed it) closed out. Consumed entries stay until the 6h TTL, and every steering consumer (hook, polls, boundary report, idle wake, `steering pending`) drops an item matching one, so an answered prompt is never re-surfaced.
- **Steering reaches the owning turn, and an explicit send is authoritative (`#claimedsteerwake`, `#steerowneronly`, `#claimfollowsedit`).** Passive delivery is unchanged: the PostToolUse hook after every tool call of the owning turn (subject to the typing gate), the `respond` / `write --commit` / post-commit `session-check` boundary report, and the supervisor's idle wake (`#steeringwake`). Four rules close the gaps observed on agent-doc-bugs.md on 2026-10-04:
  1. *Owner only.* A Claude Code subagent shares its parent's `session_id`; the hook payload carries `agent_id` only inside a subagent. `steering-post-tool-use` returns silently for such a payload before any observation, so a subagent's tool call neither receives the coordinator's steering nor advances its watermark.
  2. *Claimed items forward to their owner.* After observation every consumer re-routes queue items a worker claimed (`midturn_steering::apply_claim_owners` over the claim ledger): `dispatch=forward_to_owner owner=subagent:<label>`, never `dispatch=subagent`. An edit says "forward `previous` -> `verbatim` to that owner; do not dispatch a new subagent or re-claim"; an addition says "already claimed, nothing to dispatch"; a removal says "tell the owner to stop, then release". *Reported lines persist, never re-dispatch* (`#reportedrelease`): a plain `agent-doc queue release` records a release receipt (`state.db` `queue_document_state`, `state_kind = "queue_claim_release_receipts"`, owner + release time; retained while the row is live) for the claim it ends; after the claim owners, every consumer re-routes an unclaimed live line with a governing receipt (`midturn_steering::apply_release_receipts`) to `dispatch=persist_reported owner=<released owner>`, whose action names the exact closeout that strikes the line (the verbatim `> **Queue prompt:**` echo, or `--done <id>`) and forbids a new subagent or re-claim. A live claim supersedes a receipt, `queue release --requeue` records none (and forgets one), and closeout reconciliation (`reconcile_marker`) prunes receipts whose line closed. Observed 2026-10-15 on haiven-dev `tasks/docs.md`: after the coordinator released `subagent:page-status-enum`, the answered-but-unpersisted line was surfaced as `dispatch=subagent change=added` and dispatched to a second worker. The idle wake still ignores a claimed item's ADDITION and a tag/marker-only re-tag (same work identity), but an edit that changes the work identity (an appended note, a corrected URL) wakes the idle coordinator. The claim ledger follows exactly the edits this alignment reports (`#claimfollowedit`, shared `queue_head_alignment::pair_queue_heads`), so an edited claimed line is both forwarded to its owner here and still claimed in `queue_subagent_dispatch` and drainability. When the woken cycle's preflight seeds the steering watermark, `carry_unsurfaced_claimed_edits` keeps each claimed line the agent channel last knew under different text at its prior text, so the cycle's first hook (the preflight command's own PostToolUse) surfaces the edit instead of the seed absorbing it.
  3. *Claims follow annotations.* See `07-orchestration-commands.md` (queue-item claims): a claim follows its head across an appended/removed note at a word boundary.
  4. *Explicit send.* `Run Agent Doc` / `agent-doc route` records an explicit send (`midturn_steering::record_explicit_send`, `state.db` runtime key `explicit_send`) right after route's advisory settle wait, before any dispatch decision. While the document's last change is no later than the send plus `EXPLICIT_SEND_SAVE_GRACE_MS` (5000, covering the editor's buffer flush), every consumer observes with `explicit_send`: the typing gate and debounce are bypassed, every pending item (claimed-head edits included, labelled for their owner) is delivered at once, and each is marked `sent=explicit` (final, never `possibly_partial`). Explicitly sent ordinary queue work is upgraded from `drain_after_current` to `address_now` and must be handled by the owning turn together with its active head; claimed-owner forwarding and subagent dispatch retain their stronger routing. Text typed after the send goes back through the passive gate. Route's own dispatch is unchanged for a hook harness (Claude Code, Codex): an idle pane gets the trigger (a wake), and a busy pane is never sent a duplicate `agent-doc <FILE>` trigger; the owning turn's next hook delivers the flush. A harness whose hooks cannot inject context into a running turn (Grok Build, `#routesyncsteer`) does not treat that bookkeeping as delivery. When the owning pane is busy, route submits the latest unified diff of the authoritative document since the last successful send in this cycle — or, on the first send, since the cycle steering baseline — into that pane as one mid-turn follow-up (`paste-buffer -p -r`, then Enter). The text is steering instructions (`[agent-doc] operator steering arrived mid-turn` plus the diff, and any classified explicit-send items), never a second `agent-doc <FILE>` trigger. Grok injects a follow-up into the live turn when `ui.follow_up_behavior` is `steer`, and holds it until the turn ends when it is `queue`. Route reports `steering_delivered_to_owner` only after tmux accepts that submit, then records the sent document as the next baseline (`state.db` runtime key `route_sync_baseline`) and acknowledges the steering consumers so the same diff is not sent again. An empty diff is not a delivery. A composer that holds an operator draft, or a pane whose composer cannot be read, is not typed into: route records the explicit-send deferral (`steering_delivered=0`, `ui_outcome=deferred_for_operator_proof`) and names why the running turn did not receive the diff. An idle pane is still not typed into. When route meets an open closeout it cannot drain and pending steering exists, it exits `0` with a concise success: `[route] Sent N update(s) to the agent already running for <FILE>; no second turn was started.` carrying `steering_delivered=N sent=explicit ui_outcome=steering_delivered_to_owner ui_outcome_class=ok`. That sentence is a success. It must not say `No second trigger was injected` — that clause belongs to the ambiguous and blocked outcomes, where nothing is working yet. It does not expose the internal session-check blocker. Editors classify this as informational completion, name the delivered count, clear stale route-failure artifacts, and never record the route as blocked or show it as an error, even when a legacy transport wrapped the line in `Error:`. The no-second-turn invariant stays in the success sentence (`authoritative_dispatch::closeout_wait_route_outcome`). Each explicitly delivered version is also a labelled training row for the learned gate (`#steergateperceptron`): `GateLabel::ExplicitSend`, target `1.0` ("complete"), attached and trained at decision time. The gate itself stays: passive delivery still needs it to decide when an unsent edit is finished.
- **Ownerless captured-finalize routing stays phase-accurate (`#capturedfinalizeroute`).** If explicit steering is durable but no live owner turn exists behind an open `response_captured` or `write_applied` cycle, closeout drain returns `RouteCloseoutBlockContext::CapturedFinalizeRecovery`. The blocked route says that the retained captured-finalize worker reacts to controller state and delivery edges and that this invocation already ran immediate repair plus the bounded closeout wait. It must not describe this state as stale-empty-preflight polling. No second trigger or explicit send is injected; the durable steering remains queued until the retained response crosses commit or the exact typed recovery changes editor authority.
- **Already-materialized repair validates one projection (`#materializedintentbaseline`).** Repair selects the retained full write intent (falling back to the capture proof body), proves that same value is materialized in the response cell, and uses that same value for capture-baseline validation. When it belongs to the matching open capture and is visible in the current authoritative cut, the capture baseline advances with reason `materialized_response_intent`; repair proceeds directly to the remaining snapshot/commit boundary. It must not switch back to a smaller canonicalized `response_body`, diagnose the already-applied write as unrelated drift, or ask the operator to replay/finalize it.
- **Queue steering pairs items by identity (`#steeringeditmisalign`).** Mid-turn steering compares the live queue against the acknowledged queue item by item, keyed on the shared work identity (`agent_doc_element_queue::queue_head_identity`: the tracked id, else the marker-invariant free-text key, so `🚧`/pin/priority markers never change it). Items with the same identity pair first, in order and also across a move; a pair with equal normalized text is silent and a pair with different text is `change=edited` with that item's own `previous`. Inside each replace hunk, rows pair only when one's text contains the other's or their character-diff ratio is at least 0.5; two different tracked ids never pair, and a row that gains or loses its id pairs only by containment. Such an edit (or a same-id prose rewrite) is `change=edited`, not unregister + fresh dispatch (`#queue-mutation-steering`). Position alone pairs nothing (`#krwr`): a claimed row deleted while a different row is added in its slot is `change=deleted dispatch=cancel_claimed` for the old row plus an unclaimed `change=added` row. Removing struck lines above claimed, untouched items therefore produces no steering, a cross-hunk removal never borrows an unrelated addition, and a reordered item is not an addition. Candidate keys stay stable across claims and unrelated insertions, so a held candidate accumulates its settle evidence instead of restarting the typing gate on every re-pairing (the persistent "The operator is still typing N more item(s)" was these re-paired candidates).
- **Active-head lifecycle survives concurrent queue maintenance (GH #162).** A selected queue head remains position-locked while it carries the in-progress marker; priority and dependency sorting may reorder only the pending work around it. A stale terminal cycle record does not produce committed/closeout wording while that selected head is still visibly open. Queue-maintenance compare-and-swap refusal with `recovery=retry_crdt_merge` triggers a bounded fresh authority observation, rebases the original maintenance delta over that cut, and retries; it never reuses the refused expected cut. Preflight seeds the mid-turn steering watermark from the same admitted document text that produced the cycle contract, so an edit arriving after admission remains observable rather than being absorbed by a later seed read.
- Preflight must fail closed before diffing when the snapshot/file pair already looks like an uncommitted assistant closeout with no recoverable cycle left to explain it.
- Explicit backlog targets extracted from prompt presets are resolved relative to the project root. If a relative target begins with the current project directory name, that redundant prefix is stripped before falling back to a non-existent doubled path.
- Before any document-mutating recovery, pending maintenance, commit, or duplicate-residue cleanup, preflight must wait for the shared editor typing indicator to become idle. If the indicator remains active through the bounded wait, preflight fails closed instead of writing a cleaned document or sidecar state over a live editor buffer.
- Prompt-tail relocation before diff must ignore ordinary HTML comment bodies after `agent:exchange`, even when those comments contain prompt-looking text or preset names. Scratch-comment text must remain outside exchange instead of being moved into the live prompt tail.
- Known prompt-preset or dispatch-looking text inside ordinary post-exchange HTML comments is non-executable scratch content. Preflight must preserve it outside `agent:exchange`, must not add it to `prompt_presets_requested`, and must emit a visible warning that the comment is a user note unless moved into `agent:exchange` or `agent:run`. Post-exchange comments that contain both a markdown horizontal rule (`---` on its own line) and prose text (non-directive, non-heading lines) are recognized as user notes and the warning is suppressed — the combination of a horizontal rule separator with prose context is a strong signal that the comment is a note, not an accidental executable directive.
- Preflight and route pre-dispatch cleanup preserve ordinary post-exchange HTML comment bodies already visible in the file, even when those comments duplicate or near-duplicate a prompt already present in `agent:exchange`. They must not move comment text into exchange, must not advance the snapshot to include a live prompt, and must leave comment cleanup to write/IPC paths that can prove the duplicate line is generated residue rather than user-owned scratch content.
- Preflight must remove exact duplicate answered prompt tails while they are still after the latest `agent:boundary`, before the commit step can reposition that boundary to the exchange end. Route pre-dispatch must run the same cleanup before submitting an editor reroute. This cleanup is narrower than prompt-tail relocation: every non-comment tail line must match a contiguous prompt block immediately before an existing response heading earlier in `agent:exchange`.
- The cycle baseline preflight records must be captured from the same stable visible-document content used to compute the diff. A response baseline captured before final debounce/stability checks is invalid because editor replay can otherwise leave the baseline cleaner or older than the prompt-bearing document the agent is answering.
- **Opportunistic gated-review verification (`#optverify`).** A gated `[/]` `agent:review` item may carry a typed proof/disproof predicate so the binary can auto-prove or auto-disprove the gate from `ops.log` markers during the normal preflight read — no dedicated live-verify session. The predicate is stored inline on the item text as an HTML-comment annotation (`<!-- gate-verify verify="<marker>" disproof="<text>" set_at="<epoch>" -->`, owned by `agent_doc_element_backlog::gate_verify`) so it round-trips verbatim through the pending parser without changing the `[/<gate_type>]` checkbox grammar. It is set via `agent-doc backlog set-verify <id> "verify=ops_log:<marker>;disproof=ops_log:<text>"` (or `--backlog-set-verify id=<spec>` on `write`/`finalize`; legacy alias `--pending-set-verify`); `set_at` is stamped automatically with the current time. The pure scan (`gate_verify::scan_ops_log`) decides per item: a proof marker seen **at or after** `set_at` with no disproof → `provable`; a disproof marker seen → `failed` (**disproof wins ties**, fail safe); neither → `pending`. Stale pre-`set_at` markers never count, so re-setting a gate re-opens it. **Embedded document prose never proves a gate (`#gng8`):** content-logging ops.log entries (for example `queue_diff_active_prompt_differs ... prompt_changes=["..."]`, route `prompt={:?}`, session `tail={:?}`) embed backlog/response text via `{:?}` debug formatting, which always double-quotes it — so the scan strips double-quoted spans from each message before matching, and a gate description that merely mentions its own marker token stays `pending`. Structured marker emissions (`[claim] cross-session-reject pane_id=...`, `[ipc-socket] early_receipt_accepted ...`, `[s760] clear-decision ...`) are plain unquoted message text and must remain unquoted to stay provable; an unterminated quote excludes the rest of that line (fail safe). The built-in verifier `s760_clear_decision_clear_true` is stricter than a substring predicate: it only accepts an anchored `^[<timestamp>] [s760] clear-decision ...` ops.log line (the bracketed `<timestamp>` is a bare epoch or an ISO-8601 UTC stamp, `#opslogts`) with `optIn=true`, numeric `pct >= threshold`, and `clear=true`; it fails on a structured clear below threshold or a structured no-clear at/above threshold, and it ignores prose-only `queue_diff_active_prompt_differs` mentions. Preflight surfaces one `gate_verify` result per predicate-bearing gated item (`id`, `status`, `marker`, `at`) and emits an `optverify review=<id> status=<...>` line to `ops.log`. The `[/]→[x]` auto-transition is **opt-in and default off** — only when `agent_doc_gate_autoverify` is true (document frontmatter, falling back to project `.agent-doc/config.toml`) does a `provable` gate flip to `[x]` (persisted to both the working-tree file and the snapshot so the step-2 commit stages it); without the opt-in preflight only surfaces the status and never silently flips a human gate. A missing `ops.log`, absent review component, or item without a predicate is a quiet no-op.

- **Hookless harness parity (`#chatprompt`, GH #140).** The shared installed skill is the authoritative fallback when a harness cannot invoke `UserPromptSubmit`. In particular, OpenCode has no such hook, so its agent must recognize a harness-chat prompt itself, write the same canonical blockquote record into `agent:exchange`, answer it in the same cycle, and persist through the normal closeout. Hook availability may automate discovery, but it must not define whether the cross-harness document-turn contract applies.

## session-check

`agent-doc session-check <FILE>`

- Evaluates **one document version per sweep** (`#sccurrentpass`). `session-check` is an observationally stable pass over a single document, so its entry points (`run_with_options`, `inspect_with_warnings`) open a pass-scoped current-document memo: the first resolve wins and every later guard in that sweep reads the same value. This is a correctness rule before it is a performance one — the operator can type mid-sweep, and independent per-guard resolution let two guards disagree about the same document. It is also the dominant cost fix for editor-attached documents, where each resolve was a full controller round trip returning the whole document text (~8 per sweep, ~0.5-1s apiece); `Compact Exchange`, which runs a sweep after its writeback, inherits that saving directly. The memo is never ambient: outside a pass, resolution is unchanged; force-disk resolution bypasses it (different authority); nested entry points reuse the outer pass; and every self-heal / captured-resume / convergence step that can rewrite the document invalidates it so the next guard re-reads.
- **Settle window (`#scsettlewindow`, GH #60).** The CLI waits out a *self-converging* interruption instead of reporting the state it sampled at entry: a cycle still `write_applied`, a retained response delivery or document projection that "will resume automatically", an unsettled retained document-write delivery, scheduled replica/projection settlement after an authority/disk divergence, or a pending binary-owned captured closeout. Each of those tells the harness to do nothing but re-run `session-check`, and the harness contract allows exactly one run after a deferred `respond`, so a single entry sample made the operator's answer depend on how fast the harness typed (the same cycle read `write_applied` ~1s after `respond` and `committed` ~4s after). It re-samples every 500ms for up to 45s (`AGENT_DOC_SESSION_CHECK_SETTLE_SECS`; `0` samples once) and then reports the LAST state, so a real stall is still reported, only later. An interruption that asks the agent to act (finalize, `write --commit`, answer a prompt, dedupe) returns at once. The window belongs to the CLI entry only; the Stop hooks keep their own budget. The check returns INTERRUPTED as a typed `SessionCheckInterrupted` error, and only the entry point prints it and exits `1` after settling (`#scsettleexit`). Before this, the check exited from inside itself, so the settle loop never saw the outcome and the window never ran.
- **A committed cycle does not supersede a session-check refusal (`#respondsettle`, GH #275).** When a strict closeout (`respond` / `write --commit` on an open cycle) fails after its response was captured, the command watches its OWN cycle and, if that cycle reaches `committed`, may report `[respond] closeout committed: ... an earlier transient closeout error was superseded and needs no action` and exit `0` (`strict_closeout_error_settled_committed` in ops.log). `committed` alone proves only that the response landed: the strict closeout commits BEFORE its terminal session check, so a deterministic refusal of the committed bytes (the shadow-backlog guard over `--todo-add` rows on 0.35.508) left the cycle `committed`, `respond` exited `0`, and every later `session-check` failed on the same bytes. The error is superseded only when a fresh status-only session check (`inspect_read_only`) is `ok` or `steering pending`; a self-converging interruption is re-sampled within the same settle window. If the committed document still interrupts, the command exits nonzero with ``[respond] closeout committed cycle `<id>`, but the committed document still fails its session check, so the closeout error was not superseded: <the live refusal>`` and logs `strict_closeout_error_not_superseded reason=session_check_interrupted`. If the recheck itself fails, the original error stands (`reason=session_check_unverified`). The commit is never undone; the agent fixes the document the refusal names.
- **A live preflight is in progress, not abandoned (`#sessioncheckliveturn`).** If an open `preflight_started` cycle belongs to the document's exact durable registry owner pane and that pane has a fresh harness turn-active lease, `session-check` reports `[session-check] IN PROGRESS` with the owner pane and tells observers not to recover, abandon, finalize/write, clear, or restart it. It still exits nonzero: a live turn has not crossed the terminal boundary, so treating it as clean would violate fail-closed closeout. This expected concurrent observation does not emit the dogfood `ACTIONABLE_AGENT_DOC_FIX_PROMPT`. A project-wide marker from another document is never enough; missing, expired, mismatched, or unreadable ownership evidence falls through to the ordinary open-cycle interruption.
- **Route keeps the live-turn verdict (`#routeliveturnverdict`, GH #228).** When a route's closeout drain (`closeout_drain::drain_open_closeout_before_routed_dispatch`) meets an open cycle that session-check classifies as IN PROGRESS, that verdict is the one classification source for the route's outcome. The drain reads it from session-check (`SessionCheckStatus::is_live_owner_turn_in_progress`, or `is_live_owner_turn_verdict` on the closeout repair's refusal, which runs the same check) and returns `RouteCloseoutBlockContext::LiveOwnerTurn`, logging `route_dispatch_drain_closeout_blocked ... context=live_owner_turn`. It does not return `OpenEmptyPreflight`, even though the cycle also has an empty preflight's shape. The live-turn guards (`cancel_preflight_cycle_protected`, `repair_preflight_live_turn_protected`) refuse to touch the cycle for the same reason, and the drain leaves the cycle and document unchanged. Route then treats the turn as busy, not as something to recover:
  - It never surfaces `session cancel-turn`, a `replay_safe [open_empty_preflight]` blocker, `recovery_command=`, or `ui_outcome=blocked_with_exact_unblocker`. The route-visible blocker is session-check's verdict verbatim, not the re-derived closeout-recovery decision.
  - The outcome is benign and exits `0`: `[route] a turn is already running on <FILE>; no second trigger was sent and nothing needs recovery ... owner_turn=live ui_outcome=queued_behind_owner ui_outcome_class=ok` (`authoritative_dispatch::live_owner_turn_route_outcome`, recorded through `invocation::record_route_live_owner_turn`). It is never the `EX_TEMPFAIL` (`75`) deferral. A prompt-bearing route still queues its prompt in `agent:run` for after that turn's boundary, also with exit `0`. Pending explicit steering is still delivered to the live owner (`#claimedsteerwake`). A plain trigger with no drainable queue head yields the same way and does not fail closed. Editor clients may show an informational queued notice, but must not store this typed success as an attempt error or project it as a blocked route.
  - When a drainable queue head exists, route logs `route_dispatch_drain_closeout_live_owner_turn` and says the live turn owns the queue and the head is in its scope. It does not log `route_dispatch_drain_closeout_wait_existing_queue`, and it does not say the head "remains queued behind the closeout", because the live cycle may already be working on that head.
  Without positive owner-turn evidence (no IN PROGRESS verdict), the existing `OpenEmptyPreflight` / closeout-recovery reporting is unchanged.
- **An idle owner pane makes a lease-backed live verdict ambiguous (`#ctrlcrerun`).** The IN PROGRESS verdict rests on the owner's turn-active lease, and a harness that ends a turn without a `Stop` hook (Ctrl+C / Esc) leaves that lease behind until its interrupt record settles (`TURN_INTERRUPT_SETTLE_SECS`) or, for a harness whose interrupt the classifier cannot read, until the TTL. So before route reports a live owner it consults the same two-capture stable dispatch-ready pane proof as `#grokclearroute`, taken at verdict time (a busy result from the drain's own probe is reused; an idle one is re-proven, because the drain's projection wait sits between the two). When the owning pane is proven idle, route does not print "Sent N updates to the agent already running", "a turn is already running", or `ui_outcome_class=ok`. Instead it logs `route_owner_turn_liveness_ambiguous ... (#ctrlcrerun)` and records an `EX_TEMPFAIL` deferral (`authoritative_dispatch::ambiguous_owner_turn_route_outcome`, chosen by `lease_live_owner_route_outcome`): `[route] could not tell whether the agent on <FILE> is still running ... No second trigger was injected ... Run Agent Doc again in a few seconds; if this message repeats, run agent-doc session cancel-turn <FILE> and then Run Agent Doc. steering_delivered=0 owner_turn=ambiguous ... ui_outcome=deferred_for_operator_proof ui_outcome_class=operator`. Pending explicit steering stays durable in the document and is reported as not handed to a running turn. A prompt-bearing route that queued its prompt behind the live owner reports the same ambiguity. The pane proof only changes what route reports. It never retires the lease, cancels the cycle, or injects a trigger, because a rendered prompt is not turn-boundary evidence; the harness's own interrupt record (`#staleharnessturnlive`, `#devclear`, Grok `#ctrlcrerun` in [Turn Lifecycle](15-turn-lifecycle.md#interrupted-turns-staleharnessturnlive)) is what ends the turn and lets the next route re-trigger.
- **A stable empty pane can retire a receiptless cleared preflight (`#grokclearroute`).** Authoritative route closeout recovery evaluates direct pane readiness before it turns an exact empty preflight into an `OpenEmptyPreflight` blocker. This check is lazy and proof-shaped: only after the harness-turn-end receipt reclaim refuses does route capture the exact bound pane, require a structurally empty dispatch-ready composer, wait 250ms, and require a second capture with no active cancel/stop/busy cue. If that stable proof holds, `StableDispatchReadyPane` may reclaim the fresh cycle without waiting for the stall deadline or requiring a receipt. The repair still refuses a live turn lease and the terminal controller append still CAS-checks the same cycle, actor session/pane/generation, and inactive lease in one transaction. This is the Grok manual-interrupt + `/clear` recovery path; a single idle-looking frame, a draft, an unrecognized screen, a changed actor/cycle, or any live-owner evidence remains protected and may still surface the ordinary blocker. Successful recovery continues the same route, so an existing queue head is dispatched instead of reported as queued behind `session cancel-turn`.
- The operator-facing `agent-doc session-check` command remains status-only for general lifecycle recovery: it does not resume captured finalize, settle/replay arbitrary retained writes, request supervisor recovery, or apply unrelated document content. Finalize/write/preflight and the supervisor own those recovery transitions. Its two narrow self-heals are metadata-only repair of an already-committed historical snapshot whose exact `HEAD` content is proven, and exact document-plus-commit settlement of the lossless retained-response replay canonicalization described above. Otherwise session-check reports the typed blocked state and hashes without mutation.
- Runs the mandatory document-integrity gate before reporting a terminal result. A malformed component tree or active id-backed queue reference whose id is absent from open backlog/review/icebox work is an interruption even when cycle state says `committed`; lint dialect `off` cannot bypass it.
- Verifies that the latest response cycle reached a terminal committed state and that no likely direct assistant patchback bypassed the binary-owned write path.
- Before reporting terminal success, requires current canonical editor/CRDT authority to equal the disk projection byte-for-byte. Divergence records both hashes and leaves the retained continuation pending; it sends no recycle or refresh request. Exception (`#operatorleadpendingsave`): while an editor holds authority, disk lagging behind the operator's own edits is not a turn failure. When nothing binary-owned holds the divergence (no open cycle — `write_applied` included —, no retained capture or document write, no unlanded tracked-work mutation) and `admission_divergence::authority_leads_disk_by_operator_edits` proves operator provenance — the authority is not itself a committed plane, and disk equals the baseline or `HEAD` or is preserved line-for-line by the authority — session-check logs `session_check_operator_edit_pending_save`, prints `[session-check] pending-save: …` with any prompt-bearing edit relayed verbatim as pending steering, and continues to the ordinary terminal checks against the authority. It never writes disk for it. A disk projection ahead of or conflicting with the authority, or a divergence with no committed plane to judge provenance against, stays INTERRUPTED. If equal authority/disk content differs from committed `HEAD` only by transient boundary/guard markers, session-check clears every obsolete deferred target, CAS-settles exact `HEAD` through editor authority, and re-proves all three surfaces before continuing; prompt-bearing or otherwise substantive post-commit drift remains untouched.
- **Exhausted replica rebuilds are an operator state, not a pending acknowledgement (`#splicesessionack`, GH #273).** When the controller has spent its replica-rebuild budget on a retained native save and the editor still refuses that exact content (`retained_persistence_replica_rebuild_exhausted ... state=editor_holds_unmerged_visible_text`), the controller records it durably in `state.db` (`document_runtime_state`, kind `retained_persistence_rebuild_exhausted`, keyed by the document state hash, payload = refused `content_hash`/`content_len`, epoch, refusal and rebuild counts). An applied save of the document clears the row; the first refusal of a different content clears it; a refusal of the same content (including a restarted controller's streak) keeps it. Readers hold it only while disk has not reached that content and the live canonical is still that content; a detached editor or an unreadable record reads as not holding, and an unreadable authority keeps the durable fact. While it holds, `session-check` reports `the editor holds unmerged visible text (state=editor_holds_unmerged_visible_text, operator_action=reconcile_editor_buffer_with_retained_write)` with the shared `editor_holds_unmerged_visible_text_remedy` instead of "the exact editor delivery acknowledgement is pending", "retained document-write delivery remains unsettled", the operator-lead `pending-save` line, or another replica-recycle schedule, and stays non-OK even when the required-scope projection would match (fail closed). The line carries none of the settle window's self-converging needles, so the CLI returns it at once. The controller resolves the state itself (`#jetbrainsreplicaloops`): the exhaustion edge asks the editor to roll its visible buffer forward in place, so the remedy says to re-run `session-check` shortly and sanctions `agent-doc admin recycle` only as the fallback after the ops log records `retained_persistence_visible_roll_forward_requested` for the file (see [Real-Time Workflow Authority](14-realtime-workflow.md)). **A live endpoint's rejected receipt is terminal (`#visibleguardterminal`, GH #344):** the controller spends the remaining roll-forward budget immediately instead of refunding/re-requesting, records `roll_forward_refusal=editor_endpoint_rejected` on the same durable row, and `session-check` directly says `Run agent-doc admin recycle now`; only changed content may re-arm the recovery. A timeout, missing route, or `projection_changed` receipt remains retryable and does not spend the attempt. The same read feeds the write-ownership verdict `EditorHoldsUnmergedVisibleText`, so the respond/finalize terminal report (the recovering terminal-convergence gate) and the write path's retained refusal name the same state and action; the write refusal withholds `retained=delivery_projection_pending`.
- Fails on open cycle states, uncommitted visible `### Re:` / `## Assistant` patchbacks, hidden `snapshot != HEAD` closeout drift, or committed-cycle exchange drift that appends a prompt+response pair or other new assistant response content.
- A durable binary-owned pending document write for a non-committed closeout suppresses the generic direct-patchback classifier. `session-check` must report that the existing intent is retained and will resume from editor registration and state projections; its only retry command is `session-check`, never another finalize/write payload or force-disk. A retained response capture continues to own closeout after the cycle reaches `write_applied`: captured-finalize owns the terminal commit, so the foreground agent must not invoke `commit` concurrently; only an uncaptured `write_applied` cycle may name manual `commit` recovery. When replacement registration bootstraps from the retained canonical target, exact canonical/target/disk equality and captured-response materialization settle a captured-response slot, refresh the response snapshot, advance the same capture through `write_applied`, and commit it. A pending preflight/editor-reconnect projection outside a captured-response phase settles monotonically when its stored target hash, canonical editor authority, and disk bytes are exact; it must not wait for inapplicable response-materialization proof or describe that projection as a captured response. A terminal committed cycle continues through ordinary terminal validation because a post-commit projection intent is not evidence that the response needs recapture. A non-terminal pending intent remains the authority until it converges or a typed competing-user-intent decision is required.
- A matching terminal proof releases retained response ownership even when later prompt/queue edits have advanced visible editor authority beyond the committed snapshot. The proof must identify the exact cycle, capture, and response hash; prove the response is materialized in `HEAD`; and prove snapshot equals `HEAD`. It may then classify the visible difference as `snapshot_head_visible_drift`, retire the obsolete post-commit reposition target, and let `agent-doc commit` adopt the reviewed prompt-only state. It never replays the older target over newer prompts.
- When another request owns the same closeout, the controller follower wakes on terminal-cycle or explicit owner-release facts. Because lease expiry has no fact until the next claim reconciles it, the follower must also schedule that lease boundary and return `owner_released` there rather than sleeping until its longer request deadline. The retrying claim remains responsible for the serialized stopgap release/acquire CAS.
- Preflight/sync closeout-drift guards reuse the same exchange-drift detection for promptless response-body drift, so a prior OpenCode/Codex/direct-exec response body that is visible only in the working tree cannot be hidden behind a generic clean snapshot or postponed to the next manual commit. Prompt-bearing user edits still flow into the next normal preflight diff.
- Fails when a committed submodule document snapshot still leaves the parent repository submodule pointer uncommitted, naming the submodule path and prescribing `agent-doc commit <FILE>` recovery.
- **Post-commit operator steering is pending work, not a failure (`#steerinterruptexit`).** When the cycle is `committed` and the document carries prompt-bearing operator edits added concurrently with (or after) the write — the shared `turn_admission` verdict is `continue_with_steering` — `session-check` returns the typed `SessionCheckStatus::SteeringPending` outcome: it prints `[session-check] steering pending: …` (the committed-prompt-diff detail with the verbatim steering marker), then one block per settled item with its `dispatch` / `source` / `change` and the operator text verbatim (`midturn_steering::pending_steering_items`, a stateless boundary observation against the committed baseline that reads and advances no consumer watermark), then guidance that frames the steering as the next cycle's input — never as something to address in the current turn, never as a closeout to redo. The CLI exits `0` and prints `queue_continuation_required=false steering_pending=true` (queue continuation is deferred behind the steering, like `#prompt-preempts-auto-queue`); under `--codex-final-gate` it exits `2`, the gate's "work is still owed" code, not the failure code `1`. The embedded closeout (`respond` / `finalize` / `write --commit`, `enforce_clean_closeout`) succeeds and prints the line to stderr, so the terminal report no longer exits nonzero and the dogfood `ACTIONABLE_AGENT_DOC_FIX_PROMPT` never fires for it (`preflight_policy::is_dogfood_terminal_issue`). Genuine failures still win: a blocking retained document write turns it into `INTERRUPTED`, and the full guard sweep runs over it — only the prompt-only-exchange-tail guard (which is the same steering) is skipped, and a finding whose own recovery is `Recovery [pending_operator_steering]` (drift the steering turn's commit carries) is kept as a warning. A non-`committed` terminal phase (`abandoned`) with the same diff stays `INTERRUPTED`. Consumers: the Codex Stop hook routes `SteeringPending` through the same committed-prompt-diff steering path an `INTERRUPTED` from an older binary took (`is_committed_prompt_diff_interruption` matches both). When the final commit boundary returns the typed `UnansweredEditPending` refusal after the response is already committed, Stop treats that refusal as terminal success and allows the turn to end (`#stopnextedit`): the newer queue/backlog/status edit remains uncommitted for the next cycle exactly as the shared remedy requires, rather than being wrapped in a contradictory "could not finish closeout" hook block. The Claude Stop hook holds the final answer once per run for exchange-sourced steering (shared continuation-request ledger, bounded by `stop_hook_active` and an armed `/loop` re-entry) unless a ready supervisor's `#steeringwake` will submit the trigger; preflight's resume-commit gate, route closeout drain, `fix`'s finish-turn loop, the MCP `session_check`/`finalize` tools (`ok: true`, `status: "steering_pending"`), and `doctor` treat it as success. The active-harness-session post-commit drift guard (Codex `CODEX_THREAD_ID` sessions) runs first and classifies the drift by provenance (`#codexsteerinterrupt`, `ActiveSessionPostCommitDrift`): when the drift is prompt-bearing steering AND replaying the newest captured editor-op epoch (`agent_doc_op_capture_io::last_editor_text_for_base`) onto the committed baseline (or HEAD) reproduces the current document exactly (modulo transient agent-doc markers), the operator typed it, and a `committed` cycle takes this same `steering pending` outcome (exit `0`, `2` under `--codex-final-gate`). Any byte the editor ops do not explain — the harness writing the file directly, console output replayed into the document as a fake prompt, harness output written beside a real operator prompt — leaves the drift unproven and it stays `INTERRUPTED` (exit `1`); unobservable op-capture state is not evidence. Promptless drift (no steering marker) is checked the same way (`#sdkretained`): when the captured editor ops reproduce it exactly — e.g. the operator deleting a struck queue line or typing a new queue head right after a commit — it is operator work, not harness drift, and the guard does not fire; otherwise it stays `INTERRUPTED`. Each decision logs `session_check_active_session_drift_provenance operator_proven=<bool>` (`promptless=true` for the promptless branch). Response patchbacks are refused earlier by the bypassed-response-write guard, so editor-op provenance never launders one.
- **Captured assistant text cannot become operator steering (`#assistantsteeringlineage`).** A turn-boundary scan deliberately compares the committed document to the cycle's preflight watermark so it can retain genuine operator edits absorbed by closeout. Before reporting or persisting exchange changes, it subtracts only text contained in the response body attested by the exact `(cycle_id, capture_id, response_sha256)` lineage. If the cycle claims a captured response but that lineage or body is unavailable or mismatched, the scan fails without dispatching or acknowledging the ambiguous exchange items; missing provenance must never reinterpret assistant output as operator intent. The subtracted lineage is every response captured since the watermark's cycle opened, not only the latest cycle's: a `write`/`respond` auto-reopen (`baseline_replay_auto_reopened`) opens a fresh cycle without re-seeding the steering watermark, so a boundary scan whose baseline predates two committed responses must attribute both to the agent. The earlier captures are proven from the state ledger (the watermark cycle's `preflight_started` fact and every later content-bearing `response_captured` fact, bounded window); when the watermark cycle's opening is not provable (for example a `committed:<hash>` fallback watermark, whose baseline already holds earlier responses), only the latest lineage is subtracted. Attribution is by capture provenance, never by blockquote prefix: an agent's `> **Queue prompt:** <line>` strike echo above its `### Re:` heading is response text like any other.
- **Response examples cannot terminate closeout attribution (`#closeoutqueuesnapshotprojection`).** The boundary steering scan strips a newly added assistant response through the next real `agent:boundary:*` marker, later response heading, or `<!-- /agent:exchange -->`. A component close marker shown inside that response (for example fenced documentation containing `<!-- /agent:status -->`) is response prose, not a structural terminator. It must not expose the remaining response or the following `agent:run` body to exchange steering classification. Queue lifecycle projections over a legacy non-list multiline head therefore remain queue state across repeated warning/claimed/progress marker changes; the rendered queue snapshot is never synthesized as a fresh exchange prompt or treated as authorization.
- Editor projection envelopes containing only `❯ >`, `❯ > **User prompt:**`, or `❯ > **Queue prompt:**` are not operator intent. Likewise, a restored contiguous quoted prompt block immediately followed by its existing response is already answered and must not open another cycle. This suppression is adjacency-bounded: a quoted prompt at the exchange tail or separated from a later response by assistant prose remains actionable.
- Fails after a closed cycle when the live `agent:exchange` tail ends with a prompt-looking block and no later assistant response, even if the prompt already matches the committed snapshot. This prevents direct/manual implementation commits from counting as closeout when the response patchback was skipped.
- Plain `content_edit` drift without a new prompt target or response patchback is not an unstarted closeout by itself; session-check must leave that to the next normal preflight diff instead of forcing another finalize cycle after a committed turn.
- The active Codex post-commit drift guard is scoped the same way: exchange-only content edits with no unresolved prompt target are allowed to wait for the next preflight diff, as are answered-prompt marker / `(HEAD)` / boundary churn paired with backlog metadata wording drift. Typed-component drift outside that promptless closeout metadata envelope, fresh prompt targets, or response patchback markers still fail closed.
- May self-heal only narrow exchange-only already-committed historical drift proven by `HEAD`.
- Must fail closed when the repaired tail would still include a bare prompt target or typed-component drift.
- Direct-patchback diagnostics may report a bare prompt target only when that
  target appears before the newly inserted response heading. Prompt-like prose
  inside the response body after `### Re:` / `## Assistant` remains assistant
  content and must not be surfaced as a missing `❯ ` user prompt.
- Closeout transaction state is exclusively in `state.db`; cycle, capture, pending, startup-miss, and ACK files are not optional inputs. Cold snapshots and ops logs are audit/recovery outputs and cannot advance a lifecycle phase.
- Runs the pending-capture, pending-done, backlog-shadow, backlog-replay, completed-item reap, snapshot-vs-HEAD, and parent-submodule-pointer closeout guards after a committed cycle. The backlog-replay guard accepts a missing open row only with operator authority: exact editor-op replay, or a terminal/no-cycle command-entry cut whose committed projection still contains the row. An open-cycle or already-committed unexplained loss remains fail-closed.
- The pending-capture guard treats a response that explicitly closes a named tracked item in the same turn (for example, ``#item, now done``) as completed rather than demanding a new backlog mutation solely because preflight required follow-up accounting. This narrow completion proof does not suppress detection of other recommendation/future-work signals.
- Fails closed when a live backlog/icebox line looks like a tracked checklist item with an id but is not parseable as a canonical tracked-work item. This prevents malformed prefixes from hiding an open item from the pending-done guard.
- The pending-done guard reads completion signals from the response body, including `### Re: do [#id]` headings paired with later commit/verification/push evidence. It must not treat same-cycle backlog mutation text as completion proof, and ids explicitly kept open by `--backlog-edit`, `--backlog-gate`, `--backlog-ungate`, `--backlog-reorder`, or gate-type edits are excluded from missing-`--done` warnings.
- **Structured outcomes outrank prose, and the post-write gate never disagrees with the commit (GH #123).** `--done`, `--backlog-gate`, `--review-resolve` and a reap each satisfy a `do #id` closeout; the pending-done gate consults the response-text completion heuristic only for ids with none of them. The pre-commit gate in `respond`/`finalize` reads the invoking command's own `--done`/`--review-resolve` and kept-open ids (including `--backlog-gate`) alongside the cycle state's recorded done, reaped, gated and kept-open ids, so it judges on the same evidence the pre-write gate already passed — including when the tracked-work envelope was retained for editor delivery, whose landed outcomes are recorded into cycle state once the deferral is proven landed. The heuristic's completion markers (`fixed`, `verified`, `pushed`, …) count only when not negated within their clause: "`#id` cannot be verified" is not completion. Because the pre-commit gate runs after the response is materialized (`write_applied`) and captured-finalize recovery commits such a cycle regardless, a remaining miss there is advisory (`[finalize] warn:` plus a `pending_done_gate_post_write_advisory` op) rather than an error: `respond` must never report a terminal failure for a cycle that `session-check` then reports committed. The pre-write gate stays the blocking gate.
- **Synced-queue exclusion from `expect_done_or_gate_ids` (`#queue-sync-auto-pending-done-guard-misfire`).** When a backlog/icebox `queue=sync|append|prepend` attribute (`#backlog-queue-sync-attr`) auto-populates an active queue in the same cycle, the freshly-synced `do [#id]` lines surface as diff additions and would otherwise be recorded as cycle `do`-directives — making `pending_done_guard` demand every synced backlog item be resolved in the populating cycle. Preflight excludes only the backlog→queue ids newly inserted by that maintenance pass from `expect_done_or_gate_ids`; any id already present in the pre-sync queue, including the consumed queue head, remains an expect-done target. Without a `queue` sync mutation, directive accounting is unchanged.
- **Partial `do [#id]` closeout narrowing (`#do-id-partial-closeout-state`, WARN-only).** When a `do [#id]` turn ships a repo phase — the response carries a shipped signal (committed + pushed) — but the same response says live deploy / sync / verification / approval work remains, and a directed id is still `[ ]` open in `agent:backlog` (not done/reaped this cycle), `check_partial_closeout_state_guard` emits a WARN advising the agent to narrow the backlog item + queue head to the next phase via `--backlog-edit` (or `--backlog-gate` when only review/external validation remains), so the visible item describes the next action instead of the original full task. This guard is WARN-only by design — it must never block the closeout, because the auto-queue drain depends on this path — and is suppressed by a `<!-- no-partial-closeout-guard -->` response marker once the item is already narrowed. Remaining work (per `tasks/agent-doc/plan-do-id-partial-closeout-state.md`): per-id complete/gated/partial outcome tracking so the guard can distinguish a narrowing `--backlog-edit` from a bare keep-open, an opt-in strict mode, and queue convergence that carries the revised next-phase prompt forward.
- **Blocked `do [#id]` follow-up capture (`#blocked-closeout-followup-capture`).** `--backlog-gate <id>` is reserved for implementation-complete work awaiting review/external validation. When a `do [#id]` cycle instead gates a directed id out of `agent:backlog` (`pending_gated_ids`, still present in `agent:review`) while the response signals the work is blocked / still needs future action — a tight phrase list (`remains blocked`, `next steps to complete`, `must remove/expire …`, `awaiting approval before …`, `deliberately delete`, …) co-occurring with `#id` in the same response paragraph — `check_blocked_closeout_followup_guard` fails closed under `pending_done_guard` strict mode (WARN under `warn`). It is satisfied by any of: keeping the id open with `--backlog-edit "<id>=…"` (id stays in `agent:backlog`, recorded as kept-open), adding a new follow-up via any `--backlog-add*` primitive (`pending_added_this_cycle`), an explicit "no additional backlog follow-up is needed because …" justification phrase, a `<!-- no-blocked-followup-guard -->` / `<!-- no-pending-done-guard -->` response marker, or marking the id `--done`. The paragraph-scoped id tie keeps an incidental blocked phrase about unrelated work — or the `### Re:` heading that always names the id — from firing the guard. This is distinct from `#do-id-closeout-open-backlog` (target left `[ ]` open in backlog) and `#do-id-partial-closeout-state` (shipped+pushed phase still carrying full-task text, WARN-only).
- **Two-phase `--done` is not a resurrection.** A retained closeout may first render the target as `[x]` before the next maintenance seam archives/removes it. The reintroduced-reaped guard blocks only if the same id is active again as `[ ]` or `[/…]`; the intended `[x]` intermediate must be allowed to commit/settle and must never instruct the agent to recapture the response.
- **Queue-audit partial-completion advisory (`#queue-audit-partial-completion`, WARN-only).** A queue-completion audit ("which queue items are complete?") should classify each row as complete / partially complete / not-started, naming the completed substeps and the exact remaining condition for partial rows, instead of collapsing meaningful partial progress into a blanket "none complete." Per the binary-vs-skill rule that per-row classification is natural-language judgment, the binary only flags the unambiguous collapse: `check_queue_audit_partial_completion_guard` emits a WARN when the committed response is about the queue, makes a blanket none-complete claim (`\b(none|no)\b … complet(e|ed)`), cites ≥2 distinct substep completions (`is complete`, `was clean`, `passed`, …), and never frames anything as "partial." WARN-only — never blocks closeout — and suppressed by a `<!-- no-queue-audit-guard -->` marker. The richer per-row state table and split/narrowing recommendation are response-contract guidance (skill/spec), not deterministic row classification.
- **Queue-contamination slash-command carve-out (`#queue-contamination-guard-false-positive`).** `check_queue_response_contamination_guard` fails closed when a free-text `agent:run` prompt is assistant answer prose copied from a `### Re:` body (the `#jb-run-agent-doc-response-queue-contamination` repro). It must not false-positive on a genuine user prompt that merely *mentions a slash command* (`/agent-doc`, `/clear`, `/compact`, …) and therefore shares a verbatim ~40-char run with a response that discussed the same command. A queue prompt that references a slash command at a token boundary (`mentions_slash_command`) is a user instruction, not copied answer prose — declarative answer prose never leads with slash-command instructions — so it is skipped alongside the existing directive (`do`/`preset`/`dispatch`/`#id`) and short-prompt carve-outs. Response prose copied into the queue that contains no slash command is still flagged.
- **Gated-phase split advisory (`#gated-followup-split-enforcement`, WARN-only).** When a directed `do [#id]` cycle keeps a tracked item open (`--backlog-edit` / `--review-edit` / `--backlog-gate`, recorded in `pending_kept_open_ids`) whose body enumerates multiple gated/remaining phases — the word "phase" plus ≥2 short parenthesized phase markers (`(2b)`, `(3)`, …) framed by a gating signal (`gated`, `remaining`, `live-verify`, `awaiting`, `still needs`) — but does not break those phases out into discrete child backlog IDs (≥2 distinct `#child` references other than its own id and the `#agent-doc-bug` preset tag), `check_gated_phase_split_guard` emits a WARN advising one child backlog ID per actionable phase (sibling of `#blocked-closeout-followup-capture` and the SKILL "one backlog ID per actionable phase" rule). It is WARN-only by design — it never blocks closeout — and is suppressed by a `<!-- no-gated-phase-split-guard -->` response marker when the phases are intentionally one unit.
- The Codex/OpenCode/direct-exec harness path is expected to run this immediately after `finalize` or strict `write --commit`, and must fail closed if the check reports an open or bypassed cycle.
