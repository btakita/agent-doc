A `/agent-doc` `finalize --stream` that fails with `IPC proof insufficient ... invariant=live_prompt_drift_after_preflight` (and the follow-on "snapshot is N bytes but visible file is M bytes, looks like manual cleanup with stale snapshot/CRDT state") can CRDT-merge fragments of the new response into the middle of the *prior* committed response, relabel the old header `(HEAD)`, drain the queue, and reap the `do #id` pending item — yet leave NO clean new response section in the file.

The hidden blocker: the failed finalize writes a capture at `.agent-doc/captures/<pathhash>/cycle-<runid>.json` with `write_applied_at` set but `committed_at: null`. Its `response_body` is the exact finalize patch text. Until that capture's body appears verbatim in the snapshot, `agent-doc commit`, `agent-doc write --commit`, and `reset --from-current[ --preserve-session]` all refuse with `captured response baseline no longer matches` / `captured response body is not present in the staged snapshot ... refusing already-committed closeout`.

**Recovery that worked (2026-06-08, jq1r corky publish cycle):**
1. Manually reconstruct the exchange with Edit — restore the prior response clean (strip `(HEAD)` + the wedged fragment lines), then add the new response section with its own `### Re: … (HEAD)` header + queue-prompt blockquote + a fresh `<!-- agent:boundary:xxxx -->`.
2. `mv .agent-doc/captures/<pathhash>/cycle-<runid>.json /tmp/...` to take the stale capture out of the way (match by the `run_id` printed in preflight's `pipeline.run_id`, e.g. `cycle-1780943977655`).
3. `agent-doc commit <FILE>` — succeeds now (snapshot==HEAD, no orphan capture). Then `agent-doc session-check <FILE>` returns `committed`.

`agent-doc commit` normalizes to a single HEAD boundary, so a hand-inserted intermediate boundary marker gets dropped — that's fine, the prior response text is preserved.

**Why:** the capture sidecar is a fail-closed replay guard; a manually-cleaned file can never match the captured patch byte-for-byte, so the guard deadlocks until the capture is removed. Distinct from [[feedback_hung_agent_doc_write_stale_live_buffer]] (live-buffer sidecar, exit 75) and [[feedback_agent_doc_supervisor_self_race_finalize_block]] (supervisor race). **How to apply:** when finalize fails with `live_prompt_drift_after_preflight` and the queue already drained, don't re-run finalize — fix the file by hand, clear the orphan `captures/<pathhash>/cycle-*.json`, then `agent-doc commit`.

**Variant — the binary's own suggested recovery is circular (2026-07-02, signals-patchboard cycle):** `write --commit` errors with "Rebuild sidecars … `agent-doc reset --from-current --preserve-session`", but running that command does NOT clear the stale capture — the next `write --commit` fails with the identical message. `--preserve-session` preserves the captures dir, so the loop never exits. Break it the same way: `mv captures/<pathhash>/cycle-<runid>.json` aside. In this occurrence the wedged finalize also (a) merged only a FRAGMENT of the response (numbered list, no header) into the exchange, (b) resurrected a superseded queue item the operator had already rewritten, and (c) a stuck `response_captured` cycle in `state/cycles/<pathhash>.json` kept session-check INTERRUPTED with `editor_convergence_required` even after the clean commit — mv that aside too, then `write --commit` reports "empty response" (correct) and session-check goes ok. A granular `--backlog-add` no_ack a minute earlier had ALSO landed asynchronously (~20s later) — always grep the doc for the new ids before re-adding.

**Variant — preflight recovery re-poisons HEAD via a bloated CRDT overlay (2026-06-09, EFS #b0wq cycle):** after the same `live_prompt_drift_after_preflight` failure, `git checkout HEAD` + a clean hand-edit + `git commit` produced a correct HEAD — but the NEXT `agent-doc preflight` "recovered" by replaying the stale `content_ours` snapshot and re-committed the CONTAMINATED version back to HEAD (here: freeform `agent:queue` lines that tripped `session-check` queue-contamination guard `#jb-run-agent-doc-response-queue-contamination`). Root cause was `.agent-doc/crdt/<pathhash>.overlay.yrs` having grown to ~2.5× the doc size (82K overlay vs 33K doc) — it held accumulated drift ops the merge kept resurfacing. Each `preflight`/`session-check` also spawned a fresh `preflight_started` cycle that never reached write, so session-check stayed INTERRUPTED. **Fix that worked:** (1) make the working tree the clean correct content; (2) `mv` aside `.agent-doc/crdt/<pathhash>.{yrs,overlay.yrs,yrs.lock}`, `.agent-doc/captures/<pathhash>`, and `.agent-doc/state/cycles/<pathhash>.json`; (3) `git commit` the clean tree; (4) `agent-doc reset <FILE> --from-current --preserve-session` (rebuilds sidecars/CRDT from clean disk); (5) `agent-doc session-check` → ok. The actual feature work (built/tested/pushed to the EFS submodule) was never at risk — only the session-doc bookkeeping was wedged.
