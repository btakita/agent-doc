In the agent-loop `src/agent-doc` workspace, `cargo install --path .` resolves dependencies **fresh**, ignoring the workspace cargo-patch (`../.cargo/config.toml`) that repoints sibling crates (e.g. `agent-doc-orchestration`, `tmux-router`, `lazily`) at local paths. So `cargo install` can **fail to compile** (e.g. E0061 arg-count mismatch in `agent-doc-orchestration/src/write.rs`) on code that `cargo build --release` and `make check` compile cleanly, because those use the patched local versions.

Implications when "rebuild BOTH binaries" ([[feedback_cargo_build_release_after_route_edit]]):
- A failing `cargo install --path .` is often **pre-existing sibling-crate drift / in-flight work**, not your change — especially for markdown-only edits (SKILL.md/VERSIONS.md). Confirm with `git diff --stat` that your edit is innocent before chasing it.
- `.bin/agent-doc` → `target/release/` IS refreshed by `cargo build --release` (used by the skill). `~/.cargo/bin/agent-doc` (tmux-spawned sessions) only refreshes via `cargo install` — so it can lag when `cargo install` is blocked by unrelated broken sibling code.
- Installed skill **surfaces** (`.claude/skills/.../SKILL.md`, `.codex/AGENTS.md`, etc.) are static files regenerated by `agent-doc skill install --all` using whichever binary you invoke; the nudge/content is live in surfaces regardless of which `~/.cargo/bin` binary version runs.
